# 文档怎么写

这条线有**三层**，各装各的。往错的层里塞东西，是这套结构最常见的死法。

| 层 | 只装 | 判据 | 代价 |
| --- | --- | --- | --- |
| `CLAUDE.md` | 每次会话都得知道的硬约束 | **不知道就会做错事** | 每次会话都进上下文，塞多了每次都在付 |
| 文档站（钉代码） | 为什么这么定、撞过什么、判据怎么来的 | 需要时查 | 钉住的代码一改就报黄，要人复核 |
| 代码注释 | 只写现状：这文件装什么、这行在做什么 | 离了它读不懂**这一行** | 没人钉，写多了必然腐烂 |

## 判断一句话该去哪

问自己：**这句话是「必须知道」，还是「想知道」？**

- 「服务名一律 `gwb` 开头」→ 必须知道（不知道就写错）→ `CLAUDE.md`
- 「为什么全加而不是通用名才加」→ 想知道 → 文档站
- 「这个函数是保底 error 出口」→ 读这行代码需要 → 注释

**默认答案是文档站。** 往 `CLAUDE.md` 加之前先问：不知道这条会做错什么事？答不上来就别加。

## 代码注释：只写现状

文件头两三句说它装什么，个别离了注释读不懂的留一行，其余不写。

**注释里不写文档站的页名或锚点。** livedoc 只钉「文档 → 代码」，反向没有任何守卫——
写死位置必然腐烂，而且没有任何机制发现。要指路就写「见文档站」四个字。

清理注释时的手法：把「为什么 / 症状 / 母仓怎样 / 当时怎么查的」整段搬进 walls，
原地留一句说它是什么。

## 加一条「撞过的墙」

`walls.mdx` 按代码位置分区，每条固定四段：

> **现状**一句 → **为什么** → **症状**（撞出来的才有）→ **钉住的那段代码**

「症状」那段最值钱：写清楚**当时看到的是什么**（报错原文、日志里有什么、有没有报错），
下一个人照着症状就能认出同一个坑。静默失败尤其要写明「一个字都没有」。

## livedoc：五类引用

写草稿记号，跑 `confirm` 转正：

```
@@livedoc ref src/x.ts:12-20 @@        行段
@@livedoc ref src/x.ts @@              整文件（末尾追加也算变）
@@livedoc tree src @@                  目录树，可带 depth=2
@@livedoc exists src/x.ts @@           在；absent 是「断言不在」
@@livedoc has src/x.ts "export foo" @@ 文件里有这个字面量
```

**引用路径相对文档站目录**（`../apps/...`）。**跨单元钉不了**——件仓的代码只能在件仓
自己的站上钉。

### 顺序：先改代码，再写文档，最后 confirm

反过来的话行号全变，白 confirm 一遍。

**被引的代码必须先提交**——livedoc 的记忆认 git，未提交的会拒绝 confirm。

### 两条命令

```powershell
pnpm doc          # check：钉住的代码变了报黄，指向空气报红
pnpm doc:confirm  # 看过之后确认；草稿记号也在这一步转正
```

**不在 `pnpm check` 里**——它要起文档站的解析链，太慢。改了被钉住的代码就跑一次，
多次改动攒着一起跑也行，提交前跑一次是个好习惯。

### 行号不用人维护

代码挪了位置，下次 `confirm` 会把记号改写成今天的位置。**但内容变了要人看一眼**——
那正是报黄的意义，别闭着眼 confirm 过去。

## 组件随便加

文档站不是内核，准入判据管不着它。要 `<Callout>`、要图表、要什么加什么——
只记得在 `livedoc.config.mjs` 的**名册**里给它一条压平规则，不然 `check` 当场报红。

## README 是生成物

仓根 `README.md` 由 `content/docs/readme.mdx` 摆出去，**别手改**。改完：

```powershell
pnpm --filter <站名> exec livedoc render --target ai
```

摆出去的页**不写站内链接**——render 原样保留 `/docs/...` 路径，落到别的目录里就是死链。

## 两个仓的分工

- **内核仓的站**：规则本身（准入判据、服务命名、依赖三档）、内核的四件事与它的坑
- **件仓的站**：件的实现取舍、每个件的说明、件这边撞的墙

**规则住内核仓，具体现场住撞上的那个仓。** 比如「依赖三档」这条规则在内核仓，
而 `GwbCli.run` 回 `GwbResult` 那次现场在件仓。
