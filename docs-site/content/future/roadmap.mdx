# 路线

**「等什么」那一栏是这页的重点。** 它记着「为什么现在不做」，正好接住准入判据第二关
（真遇到需求才加）。一条东西等的前提到了，它才该动。

## 做完了

这条线的前五刀（载体、取址、桥、装机、loader 与服务）和日志四路汇总都在两进程线上
落地、又随单进程重构整体换了形状——那段做完史连墙带读数都冻结在
[轨迹区](/trajectory)，这儿不再复述。只列单进程线上的账：

| | 断言 | 怎么证明的 |
| --- | --- | --- |
| **第六刀** 单进程重构 | cordis 住进 Electron 主进程，应用只剩主进程＋渲染层 | 四个探针在实验目录逐个验：`loader.internal` 可塞、页面直吃 `file://` 五项全通、件三种出错主进程都活着、v0 内核端到端；再拿外壳＋日志两个真件与四件组合实机跑通，整套搬回本仓（读数全文见[单进程重构](/trajectory/2026-09-09-single-process)） |
| 词汇表 0.1 | 契约面只有七个名字加一个形状 | `@godcreator02/gwb-plugin-api@0.1.0` 已发本机 registry，正文逐条钉在 `index.ts`（见[词汇表](/docs/plugins/vocab)） |
| 十二件迁 0.1 | 件仓十二件并发版全部对上新契约 | 件仓那边验：五格窗格全自报 `client`/`style`、十二条条目 active、两条 CLI 退出码 0、日志实时回环（件仓的决策页记着账） |
| 文档站对齐 | 站不再说旧线的话 | 机制页全部重钉 `main.ts` / `index.html` / `preload.cjs`；轨迹区纯历史化、零钉码；`pnpm doc` 全绿、站能 build |
| 同一 home 单开 | userData 拆成每 home 一份，平台锁自动按 home 生效；不同 home 随便并跑 | 名字式与乱大小写路径式的二开都被拒（退出码 1，报归一后的路径）；双 home、三 home 并跑各自 CDP 应答（见[单开锁](/trajectory/2026-09-12-one-home-one-instance)） |
| 内核 0.1.0 上架 | 日常用与调件不再进仓走 build；跑的哪一版说得出 | `@godcreator02/gwb-kernel-desktop@0.1.0` 在本机源上，tarball 五个文件；安装位（`26091201qzv\gwb-app`）起 default，`runtime.json` 的 `appDir` 指安装位、`version` 0.1.0；MCP 握手调通 `devkit.home.new`（见[上架与安装位](/trajectory/2026-09-12-kernel-on-registry)） |

内核现在 **512 行**（`main.ts` 338、`imports.ts` 63、`index.html` 92、`preload.cjs` 19）加
词汇表 62 行，对照母仓 5100。`imports.ts` 是 2026-09-12 从 `main.ts` 抽出去的纯逻辑
（importmap 扫描），为的是单测——判据见[怎么跑、怎么验](/docs/dev-loop)。

口径是**连空行与注释一起数**。这个仓注释密度高，正文远少于这个数。数字漂了就订正，
但别为它专门去数：它只用来提醒「离母仓那 5100 还有多远」。

## 日志：从四路到三路

两进程线上日志是四路（件、宿主、主进程、渲染层）汇主进程、环形缓冲、preload 两口、
按字节轮转——那一整套是「两个进程要说话」逼出来的，随单进程重构**连管道带轮转一起
退役**了（了断见轨迹区那五张日志卡）。

现在：三路——件、内核、渲染层 console——都走 `ctx.logger`，内核在起 cordis 时挂一个
exporter 全量写 stderr 加 `<home>/gwb.log`。**任何件再挂一个 exporter 就把三路全收齐**，
页面上要看的日志归 `gwb-logger` 件：自己挂第二个 exporter、从 `ctx.logger.buffer` 补
历史段、经 `gwbKernel.emit` 推给页面。内核为窗格不铺任何管道。

## 在等前提

| 要做的 | 等什么 | 说明 |
| --- | --- | --- |
| **日志历史段跨启动** | **真要看上次那趟运行** | 眼下 `gwb.log` 一份流水在，页面上看的历史段是 `gwb-logger` 件内存里那两千条，重启就没。要跨启动得写一份结构化落盘，第二份文件与第一份不一致时没人说得清信哪份——到期时重新过第一关 |
| **安装包（electron-builder / Forge）** | 真要分发给别人 | **上架已完成**：0.1.0 在本机源上，日常从安装位起（见[上架与安装位](/trajectory/2026-09-12-kernel-on-registry)）。剩下的是「分发」那一半——到时拿两个工具各试一次，手上会有一个确定的问题：pnpm 怎么进产物 |
| **命令行（`gwb` CLI）** | 界面点不动时真需要一条出路 | 眼下从安装位 `run.cmd` 起，`GWB_HOME` 与 CDP 开关都透传，够用 |
| **多 home 的控制面** | 真要同时跑两套 | 并跑本身已经**结构上安全**（userData 每 home 一份，2026-09-12 验过三实例）。缺的只是 GUI 里切换那半（**那可能是控制面，可能根本不该在内核里**） |

## 件那边

件的路线、每个件的状态与版本号，全在**件仓的文档站**（`26090709qzp/gwb-base-plugins`）。

**这儿不再抄一份**——两处各记一份必然漂移。形势一句话：十二件已迁 0.1 并发版、实机
验通，日常 default home 就是这套安的家；废弃那批无前缀包（`@godcreator02/shell` 那些）
从 registry 删掉，`gwb-` 前缀跟它们错开。

## 不在路线上

这些是**决定不做**，不是排期没排到。要做得先推翻准入判据——理由见
[刻意不做什么](/future/not-doing)：

自动升级、盘上对账与失败还原、GUI 失败兜底页、件之间的 peer 准入、
配置文件的模板与自愈、宿主子进程、日志管道、`gwb://`。

**数据落盘**也在其中：内核只出 `dataDir`，落盘做成
[`gwb-data` 件](/trajectory/2026-09-07-gwb-data-plugin)。
