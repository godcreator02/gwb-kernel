## 文件格式（内核 0.10.0 起）

`<home>/gwb.log`：UTF-8，一行一个 JSON 对象，以 `\n` 结尾。键固定五个、顺序固定：

| 键 | 值 |
| --- | --- |
| `ts` | ISO 8601 的 UTC 时间字符串，毫秒精度 |
| `level` | `error` / `warn` / `info` / `debug`（cordis 的其余类型记成 `info`） |
| `source` | `kernel`（内核自己、cordis 的 loader 与 include）/ `renderer`（页面 console）/ `plugin`（其余） |
| `name` | logger 名 |
| `msg` | 正文，可含换行（在 JSON 字符串里转义） |

写满 128 MB 改名为 `gwb.log.1`（只留这一份旧的）。按时间顺序读：先 `gwb.log.1` 再 `gwb.log`。stderr 仍是文本 `<ts> <level> <name> <msg>`，给终端看，不是给程序读的。

挂载日志的 logger 名是 `loader`：每个条目挂上（带 apply 耗时）、挂载失败、卸载、退回等待各一行；条目树有变化时，等 `ctx.loader.await()` 之后再写一行汇总（有失败或没导入成功是 error，只有在等的是 warn，否则 info）。

## `logger.query`

参数 `{ limit?, minLevel?, name?, text?, after? }`，都可省；认不出的键、类型不对直接报错。

- 不给 `after`：从文件末尾往前取，筛完之后最近的 `limit` 条（默认 2000）
- 给 `after`（上一次回执里的 `cursor`）：只取那之后新写的；`gwb.log` 比 `after` 小说明轮转过，先读 `gwb.log.1` 从 `after` 到末尾，再读新 `gwb.log` 全部
- `minLevel` 只要这一级及以上；`name` 精确匹配；`text` 在 `name` 与 `msg` 里找子串，不分大小写

回执 `{ file, cursor, entries }`：`file` 是 `gwb.log` 的绝对路径，`cursor` 是读完时 `gwb.log` 的字节长度，`entries` 是文件里的原样对象，从旧到新。不是 JSON 的行直接报错，写明文件与行首几十个字符。
