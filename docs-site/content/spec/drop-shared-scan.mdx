# 删掉 gwb.shared 扫描

**本页回答**：「任何包都能在清单里写 `gwb.shared`、内核扫描 home 合成 importmap」这套机制为什么还在、删掉它要改哪几个仓、按什么顺序、哪几件事要人先定。

**状态（2026-09-25 核对）：内核一侧全部完成——内核 0.5.0 删了扫描，0.6.0 连 `gwb.shared` 字段也删了，importmap 写死在页面入口 `index.html`；default 已经在跑内核 0.6.1。块笔记（第一步）、devkit（第五步）、界面插件（第六步，外壳 0.13.10）都已完成，default 里的旧库 `@godcreator/block-note` 已卸掉。还剩两件：块笔记窗格在 default 上照常显示没有亲眼确认（见验收最后一条）；块笔记仓与论文插件仓的 `tools/build-plugin.ts` 还从内核包清单读 `gwb.shared`，装着内核 0.6 时读不到、构建会报错，要改成写死 react 的四个名字——通知「内核直接跟 0.6」已经在两个仓的收件页，还没处理，归各自的仓做。**

## 由来

devkit 仓全生态精简计划第五期原定「react 改由内核提供，删掉 `gwb.shared` 机制」。第五期提前做时（内核仓轨迹卡「react 收进内核」）只做了一半：

- react 的四个包名由内核包提供，声明**仍写在内核包自己清单的 `gwb.shared` 里**。devkit 的发版检查、`devkit.capabilities`、各插件的 `build.ts` 本来就读这个字段，所以不用改
- 扫描 home 的机制留着，因为块笔记的库 `@godcreator/block-note` 还声明着自己的包名。计划是等第三期块笔记撤掉声明再删

当时还在声明的只有三处：内核包、块笔记 `main` 线的库 `lib/`、块笔记 v2 线的界面包 `packages/ui`。

**跟块笔记 v2 线的冲突**：v2 线的轨迹卡「拆掉旧 lib」（2026-09-24）决定让方言入口进页面 importmap、接替旧库那一份，并且明确否掉了「各插件自己打包一份」，理由是每个插件都要多带一份 mdast / micromark，页面上会有好几份解析器。v2 计划页还列着「核心插件的 `./shared` 入口也进页面 importmap」。这和 devkit 第三期「block-note 撤掉自己的 `gwb.shared`、块笔记系列插件把解析库各自打包进构建产物」正好相反，要先定下来走哪边（见待决定第 1 条）。

## 为什么删

- **机制本身的成本**：内核要读 home 清单、逐个包读清单、处理同名冲突、记警告，还要保证解析不走 Node 缓存；接缝页的一半篇幅在讲这些规则
- **它要求库装成 home 的直接依赖**：内核只扫 home 清单的直接依赖，库要进 importmap 就得装在 home 根上。这和全生态精简计划第四期「home 里只有插件」对不上
- **多份拷贝不影响正确性**：方言是纯函数（清单写 `sideEffects: false`，模块顶层只有常量与函数），规矩里也禁止对别的插件的对象用 `instanceof`。页面上有几份解析器只多占体积，不会出错；页面从本地 `file://` 加载，体积不是瓶颈

## 删掉之后的样子

这一节是内核 0.5.0 的做法；0.6.0 又往前一步，见页头第二段。

- 内核启动时从自己的包目录读 `gwb.shared`、解析成 `file://` 地址，这就是整张 importmap；解析不到照旧启动失败。不再读 home 清单，也不再每次推送都重算
- `gwb:shell` 消息的 `imports` 字段形状不变，页面入口不用改
- 内核包清单里的 `gwb.shared` 字段**保留**：它是「内核给页面哪些包名」的唯一来源，插件构建时照它外置、devkit 照它检查
- 别的包写 `gwb.shared`，内核不看、不警告；拒绝放在 devkit 发版检查上，发不出去
