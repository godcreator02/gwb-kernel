## 两个插件怎么内置

**代码位置不变**：`plugins/commands`、`plugins/plugin-manager` 仍是两个包，仍按 cordis 插件的写法写，各自的测试照旧在仓根 `pnpm check` 里跑。两个包是 `private`，不再发布。

**内核怎么加载**（`main.ts`）：两个模块从 `dist/builtin/` import，内核交给 loader 的 import 按包名先查它们；它们和 include 一起放进 `root.update`，顺序是 `commands`、`plugin-manager`、`home`，条目名用包名。做成条目，是因为数据、说明书等插件按调用方的条目认身份；排在 `home` 之前，是为了残留在 `cordis.yml` 里的同名条目只会失败。插件管理的 config 是 `{ home, pnpm }` 两个字符串（loader 会深拷贝 config），条目树由它用到时从自己条目所在那一层取。

内置插件不在 `cordis.yml` 里，也不在 home 的 `package.json` 里，所以 `plugin-manager.list` 看不到它们，`update-all` 不会升级它们。

**怎么进安装包**：安装器把 `apps/desktop` 打成 tarball、再从包源安装它的依赖，所以内置插件不能写成运行时依赖（那样就得发布它们）。`apps/desktop` 构建时把两个插件的 `package.json`、`dist/` 与 `skills/` 复制到自己的 `dist/builtin/<目录名>/`。两个插件的构建产物里除 node 内置模块外没有包名 import（各自的 `artifact.test.ts` 守着），复制过去就能运行。

**pnpm**：`apps/desktop` 的开发依赖写 `@pnpm/exe.win32-x64`（精确版本）。安装器把其中的 `pnpm.exe` 与清单复制到 `build/pnpm/`，electron-builder 放进 `resources/pnpm/`。`main.ts` 打包运行时用这个路径，从源码运行时用开发依赖里那份。

## 已有 home 的迁移

内核不为这两个包名写特殊判断。同一个服务名第二次提供一律报错、不覆盖；内置的先加载，所以已有 home 里残留的两条条目加载失败（`FAILED`，日志里各一条 `service "…" has been registered at <…>` 的 error，外加一条 unhandledRejection），依赖这两个服务的插件照常拿到内置那份。迁移只是清掉这些报错，写在 `INSTALL.md` 第 0 步。
