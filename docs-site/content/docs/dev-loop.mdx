# 怎么跑、怎么验

读完这页你能回答：提交前要过哪道门禁；为什么这个仓的验收大半靠实机；从改代码到说「验过了」的路。

第一次跑、装插件、home 在哪，见[跑起来](/docs/getting-started/first-run)——那页管「跑起来」，这页管「怎么验」。

## 门禁

```powershell
pnpm check   # build:api（词汇表直出 dist）+ typecheck 全仓 + oxlint + vitest
```

提交前跑它。构建这次**在场**：`build:api` 先把词汇表包编出来，typecheck 才有得吃——
词汇表是全仓的类型契约，它坏了 typecheck 一定跟着坏。

`pnpm lint` 那段是 `oxlint . --type-aware --deny-warnings`。**规则集就是 oxlint 的默认**——
配置里一条 `rules` 都没写。默认是 870 条里的 111 条，几乎全在 correctness 这一类
（`no-const-assign`、`no-dupe-keys`、`no-unreachable`、`use-isnan`、`missing-throw`
这种「几乎肯定是错的」），其中 16 条要类型信息。style / pedantic / restriction 那些
噪音类别默认一条都不开。

lint 面很小，但**它是靠人记的**——仓里非 docs-site 的 `.ts` 眼下十个：内核四个
（`main.ts` / `imports.ts` / `bare-import.ts` / `entry-state.ts`）、旁边三个测试、
词汇表 `index.ts` 与它的测试、`vitest.config.ts`。将来加了新包、新目录，忘了它在不在
某份 tsconfig 里，它会静默留在 lint 面外，没有任何东西会说话。数不上就该去看一眼。

**文档站不在里面**：它钉 `typescript ^6.0.3`，而 type-aware 要 TS 7+，tsgolint 给它建不出
program。它本来也不进根 build/test，自己有 `docfirst check` 与 `next build` 两道，
见[账本与钉码](/docs/docfirst/how-it-works)。

两个 flag 都不是装饰：**不带 `--deny-warnings`，有诊断也照样 `exit 0`**（屏幕上有红字而
门禁放行）；`--type-aware` 配置里已经开着，CLI 上再写一次是为了让「它没生效」变成看得见
的错误，而不是静默降级成非类型模式——那是这条门禁最危险的失败形态，因为一切看起来都绿。

## 测试：判据还在，空档已补

这个仓写逻辑之前先写测试。TDD 在这里最大的用处不是保证正确，是**它自己会把代码逼成
可测的形状**：写不出测试的那一刻，就知道该把纯逻辑从副作用里抠出来了。

判据是**「跑它要不要起一个 Electron」**，不是「这段重不重要」。单进程内核里够得上这个判据的
是三个纯函数模块——`imports.ts`（扫 `gwb.shared` 拼 importmap）、`bare-import.ts`（裸名两步
解析）、`entry-state.ts`（条目状态分类），各自的副作用只剩磁盘读，单测就在旁边 `tests/`
（imports 那份九个用例：空仓、无依赖、正常收进、子路径不带前缀、地址断言、junction 换版后现算、撞名先到先得、
解析不到只 warn、坏形状静默忽略）。

其余——`BrowserWindow`、IPC、loader、真插件挂载——一律归实机验证。硬凑自动化只会得到
一堆脆弱的桩。

## 实机验证怎么做

实机的规矩正本是本仓 AGENTS「怎么跑」：每次验开自己的隔离 home（`GWB_HOME` 给一个
`<这次验什么>-<yyMMddHHmm>` 的名字）、别拿 default 试、起法是 `cd apps\desktop; pnpm start`。
验机纪律的正本在 `skill.read {"name":"gwb-devkit"}`：「验机」一节讲产物是不是新的（`dist/`
时间戳）、哪几种「看着成了」其实什么都没验，「测试 home」一节讲隔离与命名法。页面取证用
devkit 登记的 node CLI `devkit.cdp`——只收 home 名（口从那个 home 的 `runtime.json` 里查），
表达式放文件不放命令行；CDP 是这个 home 起的时候带的开关（源码跑：`electron.exe .
--remote-debugging-port=<口>`），端口别跟别的会话正在跑的实例撞上。

有个具体例子说明为什么实机不可省：第一次开测试 home 时撞出「全新 home 起不来」——
`cordis.yml` 不在，include 抛错落在挂载链上，整趟起不来（见
[那面墙](/trajectory/2026-09-07-wall-fresh-home-no-yml)）。**单测抓不着这个**：每个
函数单看都对，是「从没被走过的一条路径」上才显形的组合问题。实机起一次，一眼就看见。

单进程重构走的也是这条路：四个探针逐个验「墙拆了插件活不活得成」，读数进了
[轨迹](/trajectory/2026-09-09-single-process)，探针本身验完即删、不进仓。
