**本页回答**：装一个包要经过哪几步、每一步失败时回执是什么样；为什么安装不装 peer、也不判断是不是库；为什么建条目只等写入、不等加载；卸载为什么先删条目、失败不回滚。

## 安装的三步

<Diagram name="pm-install" title="安装一个包：三步依次做，每一步失败时回执是什么样，回执里逐步多出哪几行">
1. **校验参数**：包名与版本范围不合规就抛错——拦的是 `-r` 这类会被 pnpm 当成命令行选项的参数。参数全程以数组传给 pnpm、不经过 shell。只有调用方写错才抛，下面每一种失败都转成 `ok: false` 的回执
2. **一次 `pnpm add`**：先[找 pnpm](/docs/plugin-manager/pnpm)，再经 `applyToHome` 运行。失败时回执带 pnpm 输出的最后几行
3. **选 id，加一条条目**：选一个 id（规则见[条目、id 与归属](/docs/plugin-manager/entries#选-id)），经条目树 `create` 加进 `cordis.yml`，回执带 `entryId`。加载在后台继续，命令不等它；写不进 `cordis.yml` 时回执 `ok: false`，包留在 home 里
</Diagram>

同一个包 install 两次会得到两条条目（第二条的 id 带数字后缀）：一个包对应几条条目本来就合法，不替调用方猜「是不是装过了」。

装了一个没有 `apply` 的包（比如一个库），条目照样加上，加载失败（日志 `invalid plugin, expect function or object with apply`），在 `list` 里显示为未加载；要去掉就 `uninstall`。

<Callout type="warn" title="为什么安装不装 peer：peer 只写宿主提供的 cordis">
插件的 peer 只该是宿主提供、构建产物里按值 import 的 `cordis`，它由内核提供，不能在 home 里再装一份（那是第二张服务注册表）；别的依赖一律写 dev、打包进插件自己的构建产物。所以插件管理不读插件的 `peerDependencies`、不替它装任何东西，也不运行 `pnpm peers check`。插件的 peer 写了别的包，是那个插件没按规矩写，运行时找不到就会加载失败。
</Callout>

<Callout type="warn" title="为什么不判断是不是库：库不进 home">
库（包括词汇表包、接口定义包）由用它的插件打包进自己的构建产物，不装进 home。页面上必须只有一份的运行时代码（今天是 react 的四个包名）只由有条目的插件在清单的 `gwb.shared` 里声明，库不声明。所以 home 里只该有插件，插件管理不按 `keywords` 猜一个包是不是库。
</Callout>

### 建条目只等写入、不等加载

条目树的 `create` 返回的 promise 里包含加载过程，而加载可能永远不结束：`inject` 满足不了的插件会一直等待。等它的话，装一个依赖还没装的插件，命令就永远没有回执。写回 `cordis.yml` 在 `create` 的第一个 `await` 之前就同步安排好了，所以不等也不影响写入；加载成功没有看 `list` 里的 `active`，失败原因在日志里。

## 卸载

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="541-571" */}

- **先删全部条目，后卸包**：反过来的话，条目会指向一个不在 home 里的包。删条目时 fiber 当场卸载，依赖它的其他插件被 cordis 一起卸载，停在未加载
- **pnpm 失败不回滚**：条目已删是可以接受的结果，包会出现在「已装、没有条目」那一组里，要用再加条目
- **设置与数据留在磁盘上**：重新装回来时沿用原来的 id，还是那一份（见[选 id](/docs/plugin-manager/entries#选-id)）
- 只删一条条目、保留包，用 `remove-entry`

## 怎么单独测

- `tests/ids.test.ts`：包名、版本范围的校验与 `pnpm add` 参数
- `tests/home.test.ts`：读 home 的 `package.json`，清单不在、坏了都当空表
- `tests/uninstall.test.ts`：卸载删哪些条目
- `tests/pnpm.test.ts`：pnpm 失败时回执里的 `error` 与最后几行
- 整条安装、卸载只能实机验证：`devkit.dev` 把开发版装进隔离 home，再调 `plugin-manager.install` / `uninstall`
