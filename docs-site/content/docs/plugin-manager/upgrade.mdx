## 查新版本

`outdated` 运行一次 `pnpm outdated --json`，返回「包名 → `{ current, latest }`」，空对象表示全都最新。

- 退出码 1 表示「有过期包」，是结果不是失败
- 找不到 pnpm、输出解析不了都转成 `ok: false` 的回执：界面上它只显示一句提示
- 它只读不写，也排进 pnpm 的串行队列：排队等一下没关系，省得另外处理并发

## 一键热升级

<Diagram name="pm-upgrade" title="一键热升级的时间线：每条横道是一个参与方，竖虚线是回执发出的时刻">
- 调用方调用 `update-all`；plugin-manager 查过期包，定计划
- plugin-manager 一次 `pnpm add` 精确版本；磁盘上 A@1.0 的目录删掉、A@1.1 装上
- 条目 A 停用再启用，重新解析拿到 A@1.1，回到 `ACTIVE`
- 回执发出（`selfDeferred: true`），调用方收到
- 下一个宏任务：重新加载插件管理自己的条目
- 外壳 `shell.reload` 整页重新加载
</Diagram>

### 计划

升哪些、重新加载哪些、谁排最后，由一个纯函数算出，单独测：

- **精确版本**：用 `outdated` 查到的版本号，不用 `@latest` 标签——两次查询之间又发了一版，也不会装成回执上没写的那个
- **每条条目各自重新加载**：被别的插件 inject 的插件重新加载时，cordis 会把依赖它的插件停用再启动，但那是重跑内存里的旧代码，磁盘上的新版本没有加载
- 本来就停用的条目保持停用，记为 `skipped`
- 插件管理自己那条排在它的包里最后，它的包排在所有包最后
- 给了 `only` 就只升点名的几个；点了名却不在过期清单里的，回执里列出来

### 升级与重新加载在同一条命令里

pnpm 装新版本时会删掉旧版本目录。升级之后、重新加载之前只要隔着一条命令，旧版插件去读磁盘上自己的文件就读不到。所以 `update-all` 一条命令做完：一次 `pnpm add` → 逐条重新加载 → 整页重新加载。`pnpm add` 失败时一条条目都不动。只升某几个包也用它，给 `only`；没有「只升包、不重新加载」的命令——那样升完正在运行的还是旧代码，还会留下下面这段空档。

<Diagram name="pm-upgrade-gap" title="分两条命令时，旧版插件在目录删掉之后还要运行一段">
- 分两条命令：`pnpm add` 装上 A@1.1、删掉 A@1.0 的目录；到另一条命令停用再启用之前，旧版 A 还在运行，读自己的文件就读不到
- 同一条命令：`pnpm add` 一结束马上停用再启用，旧版 A 在目录删掉之后不再运行
</Diagram>

<Callout type="warn" title="一条命令只做一件事——例外：依赖同一份执行前状态的事务">
命令保持原子，多步流程写进说明书，由调用方一步步调。`update-all` 是允许的例外：升级与重新加载都依赖「这次升级之前磁盘上是哪个版本」，拆成两条命令，中间就有上图那段空档。`install`（装包 + 加条目）也是同样的理由：条目必须指向刚装上的那个包。
</Callout>

### 重新加载一条条目

{/* ref file="../plugins/plugin-manager/src/remount.ts" lines="52-60" */}

- 启用时 loader 重新 import 包名，内核按真实路径解析，版本换了路径就换了，拿到的就是新版本；条目在 `cordis.yml` 里的位置与 id 都不变
- **等旧的卸载完再启用**：loader 停用条目时调 `fiber.dispose()` 但不等它结束，而服务是在卸载过程中撤销的。不等就启用，新实例启动时旧服务可能还在，cordis 报「service has been registered」
- 每一步最多等 5 秒，超时就继续，读到什么状态报什么（`ACTIVE` 才算加载成功）
- `remount` 命令用的是同一套时序，目标是命令插件（`gwb-commands`）时也在这一条命令里做完

### 插件管理自己排最后

在命令处理函数里停用插件管理自己，这条 `await` 链会跟着一起卸载，回执永远到不了调用方。所以回执先发出（`selfDeferred: true`、`reload: 'deferred'`），下一个宏任务再重新加载自己，重新加载完再调 `shell.reload`。这时插件管理原来的实例已经卸载，ctx 上什么都不能用，那段代码只持有条目树、id、命令插件的引用与 logger。

<Callout type="warn" title="卸载时清理自己启动的一切——例外：插件对自己发起的重新加载">
插件自己启动的进程、定时器、监听，以及尚未完成的写盘和网络请求，卸载时都要清理掉，并把清理返回成 promise——内核退出时等的就是它。插件管理重新加载自己的那段代码天然在自己卸载之后才运行，这是允许的例外，条件是只持有条目树与 logger（这里另外持有命令插件的引用，用来调用 `shell.reload`），不碰 ctx 上的任何东西。
</Callout>

### 整页重新加载

经命令插件调用外壳的 `shell.reload`，按命令名查找，不 import 外壳。回执的 `reload`：`done` 已经重新加载；`deferred` 等插件管理自己重新加载完再做；`unavailable` 命令表里没有它或它失败了，界面要手动刷新，原因在 `note` 里。

## 怎么单独测

- `tests/outdated.test.ts`：`pnpm outdated` 输出的解析，空输出、格式变了、单条缺字段
- `tests/update-all.test.ts`：计划——精确版本、自己最后、停用的保持停用、分组条目不算、`only` 的过滤
- `tests/remount.test.ts`：停用再启用的时序（假的条目树）；自己那条推迟到下一个宏任务
- `tests/loader.test.ts`：用真实的 loader 停用再启用一条条目，回到 `ACTIVE`
- 整条热升级只能实机验证：在隔离 home 里先装某个包的旧版本，再调 `plugin-manager.update-all`
