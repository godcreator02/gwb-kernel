**本页回答**：条目有哪几种操作、各改了什么；`list` 怎么把包和条目对上；id 的规则是什么、为什么不能改；装包时 id 怎么选；数据与设置属于哪个包、怎么转给另一个包。

## 条目的操作

条目树的约定（取法、几个方法、为什么只能经它改 `cordis.yml`）在接缝页[home 与插件管理](/docs/seams/home#接口)。插件管理在它上面做这几件事：

| 命令 | 做什么 |
| --- | --- |
| `add-entry` | 给已装的包再加一条条目，id 按下面的规则选，或者手动给 |
| `remove-entry` | 删一条条目，包留在 home 里；显示名、设置与数据都保留 |
| `enable` / `disable` | 改条目的 `disabled`。启用时传 `{ disabled: null }`——loader 把 null 当作删掉这个字段 |
| `remount` | 停用再启用，一条命令做完，时序见[重新加载一条条目](/docs/plugin-manager/upgrade#重新加载一条条目) |
| `set-label` | 改显示名，空字符串是清除 |

entryId 写完整的（`home:commands`）或只写 id（`commands`）都可以：插件从 ctx 上读到的是完整的，条目树的方法只认不带前缀的 id，插件管理先把前缀去掉。

### 显示名

id 只能是 ASCII kebab-case，人需要一个看得懂的名字。显示名存在插件管理自己的数据里（一份「id → 显示名」的文档），不写进 `cordis.yml`，也不放进设置——这样插件管理不必为了显示名去依赖设置插件。没装数据插件时 `set-label` 返回 `ok: false`，界面只显示 id。

### list 怎么对上包与条目

`list` 把 home 的 `package.json` 与条目树对照，两边都不丢：

- `package.json` 里有、条目树上没有的包，报成 `entries: []`——这只表示「一条条目都没有」，不表示「装了没启用」，共享包与库本来就没有条目
- 条目指向一个不在 `package.json` 里的包（手工改过 `cordis.yml`，或包被 `pnpm remove` 删了），报成 `installed: false`
- `active` 看的是 fiber 的状态是不是 `ACTIVE`，不是 fiber 在不在：`inject` 没满足的插件照样有 fiber，只是永远到不了 `ACTIVE`

## id 的规则

- kebab-case：小写字母、数字、单个连字符分段。数据插件与设置插件用同一套字符集校验，三处必须一起改——生成的 id 通不过它们的校验，这条条目就存不下任何设置和数据
- **一经确定不改**：数据插件、设置插件都按 id 分区，改了 id，原来的设置与数据就留在旧分区里读不到。所以没有改 id 的命令，要改的是显示名
- 默认 id 是包名去掉 scope 与 `gwb-` 前缀：`@godcreator/gwb-py-cli` → `py-cli`；重名时加数字后缀 `py-cli-2`
- 一定显式给 loader 传 id：不给的话 loader 每次启动生成一个新的随机 id，设置与数据每启动一次就新建一份

## 选 id

默认 id 去掉了 scope，`@a/gwb-foo` 和 `@b/foo` 都叫 `foo`；而删掉条目后，它的数据与设置还留在磁盘上。只按条目树判断重名，空出来的 `foo` 会被下一个同名的包拿走、读到前一个包的东西。所以数据插件、设置插件都记录了每个 id 属于哪个包，选 id 时一起看：

- 否则从默认 id 起加后缀，条目树上已有的和属于别的包的都跳过
- 手动给的 id 在条目树上已被占用、或属于别的包，直接拒绝，错误里写明属于谁

## 把数据与设置转给另一个包

同一个插件改了包名、要继续用旧数据时，用 `transfer-owner`（`{ id, pkg }`）把这个 id 的数据目录与设置分区一起转给新包名，再 `remount` 那条条目。插件管理只调数据插件、设置插件自己的服务来改归属，不碰它们的目录；哪个插件没装，回执里对应的一半是 `false`。

**不是同一个插件**就换一个 id，别转归属——那等于把前一个包的东西交给它。

## 怎么单独测

- `tests/ids.test.ts`：id 字符集、默认 id、后缀、沿用旧 id、避开别的包、手动给的 id 被拒
- `tests/inventory.test.ts`：`list` 两边都不丢、`active` 按状态判断、分组条目标出来
- `tests/tree.test.ts`：条目树少了哪个方法都立即报错
- `tests/loader.test.ts`：用真实的 loader 取条目树与自己的 entryId，`create` / `update` / `remove` 写回 `cordis.yml`
