**本页回答**：安装包产出什么、装好之后是什么样；它产出的东西谁在用、定义在哪；它依赖什么、缺了会怎样；哪些事不归它做。包名 `gwb-installer`，源码目录 `installer/`（不在 pnpm 工作区里），入口文件 `installer/scripts/build.ps1`。

安装包把本仓的内核打成 Windows 安装程序，内核发版就是发这个 exe，内核不发 npm 包（[撤掉 npm 发布](/trajectory/2026-09-18-withdraw-npm-channel)）。怎么运行打包脚本、它一步步做什么见[开发](/docs/develop#打安装包)。

## 功能

- **产出两种安装包**：在 `installer\build\dist\` 下生成 NSIS 安装包 `gwb-setup-<版>.exe`（一键安装、按当前用户安装、不需要管理员权限）和便携 zip `gwb-portable-<版>.zip`，`<版>` 是内核版本。同目录的 `win-unpacked\` 是两种产物共用的未打包目录，只用来验证；每次打包整个重新生成，别日常直接运行它
- **只带内核**：本仓 `apps/desktop` 的构建产物和它的运行时依赖。插件一个也不带，pnpm 也不带：`cordis.yml` 里的插件一律从包源装、经插件管理热升级，插件放进安装包的话，每发一个插件版本就得重打 exe，热升级也就没有用了；不带插件，同一个版本号的安装包内容就唯一，home 从一开始就由 pnpm 管理（[不带插件，装机交给 agent](/trajectory/2026-09-18-no-seed-agent-installs)）
- **装好之后**：安装到 `%LOCALAPPDATA%\Programs\gwb-kernel\`，开始菜单出现「gwb-kernel」。外层应用（清单、引导脚本、装好的 `node_modules`）在 `resources\app.asar` 里。home 在 `%APPDATA%\gwb-kernel\homes\` 下，和安装目录分开：内核启动时只补 home 缺的文件、不覆盖（[home 的准备与单实例锁](/docs/desktop/home)）
- **升级内核**：重新运行新版安装包，home 不动
- **装机**：由 agent 照仓根 `INSTALL.md` 做：配用户级 pnpm 配置 → 装 exe → 往 default home 写 `package.json` 与 `cordis.yml`、用机器上的 pnpm 装命令插件、插件管理、MCP 入口等插件 → 启动 → 连 MCP 入口
- **发布**：release 只上传 `gwb-setup-<版>.exe` 到 gitea 发布仓 `godcreator/gwb-kernel`，便携 zip 只在本地构建；顺序与注意事项见[开发](/docs/develop#发版)

## 接口

安装包本身不导出模块或类型，别的模块用的是它产出的东西，都不属于八条接缝。

| 接口 | 谁在用、做什么 |
| --- | --- |
| 安装程序 `gwb-setup-<版>.exe` 与便携 zip | 人和装机的 agent 用它安装内核；按当前用户安装，产品名 `gwb-kernel` 决定安装目录与开始菜单项 |
| 装好后的目录 | 内核应用从 `resources\app.asar` 启动 |
| 外层引导脚本 `bootstrap.mjs` | 外层应用的入口，只 import 内核包，内核自己在 Electron ready 之后运行；import 失败时弹错误框、退出码 1 |
| 给人和装机 agent 的发布物 | gitea release 上的 `gwb-setup-<版>.exe`、开始菜单里的「gwb-kernel」；装机步骤在仓根 `INSTALL.md` |

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 内核包 `@godcreator/gwb-kernel-desktop` | 打进安装包的内核本身：`apps/desktop` 的 `pnpm build` 与 `pnpm pack` 打出的 tarball | 构建或打包失败时脚本停下；内核仓有已跟踪文件的未提交改动时脚本在第一步就停下 |
| 内核 tarball 的依赖（cordis、loader、include、词汇表包） | 在组装目录里装齐 `node_modules`，npm 从包源装 | `npm install` 失败时脚本停下；词汇表包的新版本要先发布，否则装不上（[版本号与发版](/docs/vocab#版本号与发版)） |
| electron | 安装包里的运行时：版本只写在 `apps/desktop` 的 `devDependencies.electron`，二进制从 `electron-builder.yml` 的 `electronDownload` 镜像下载 | 下载不下来时 electron-builder 失败，脚本停下 |
| electron-builder | 打出 NSIS 安装包与便携 zip：`installer/package.json` 的开发依赖，工具二进制从 `ELECTRON_BUILDER_BINARIES_MIRROR` 下载，环境里没设就用脚本里的国内镜像 | `installer/node_modules` 里没有时脚本先 `npm install`；装不上或打包失败时脚本停下 |
| git | `git status --porcelain` 检查内核仓没有未提交的改动 | 找不到 git 时脚本在第一步就报错停下 |
| gitea | 发布 release：git 凭据管理器里的凭据、gwb-gitea 插件的 `gitea.http` | 发布不了；安装包照样能在本地打出来 |

## 不做的事

- **不改内核运行时**：外层应用只有一份 `package.json` 和一个只负责启动内核的引导脚本，内核怎么选 home、怎么加载插件全由内核自己决定
- **不带插件、不写 home**：安装包不知道 `cordis.yml` 里装哪些插件；home 缺的文件由内核启动时补上，插件由装机的 agent 照 `INSTALL.md` 用机器上的 pnpm 装
- **不带 pnpm**：装机与插件管理都用机器上自己装的 pnpm
- **不从包源下载内核**：内核来自本仓当场构建、`pnpm pack` 打出的 tarball；只有这个 tarball 自己的依赖由 npm 从包源装
- **不自己定 electron 版本**：版本只写在 `apps/desktop/package.json` 的 `devDependencies.electron` 一处，打包时经命令行传给 electron-builder
- **不发 npm 包**：内核只以安装包的形式发布
