**本页回答**：第一次安装是什么过程、装好之后是什么样；安装包产出什么；启动器每次启动做什么、怎么从 home 里找到内核；产出的东西谁在用；它依赖什么、缺了会怎样；哪些事不归它做。两部分：启动器 `gwb-kernel-launcher`（源码目录 `apps/launcher/src`，入口文件 `main.ts`，不发布），打包脚本 `installer/`（不在 pnpm 工作区里，入口文件 `installer/scripts/build.ps1`）。怎么运行打包脚本、它一步步做什么、打完怎么验证，见[开发](/docs/develop#打安装包)。

安装包只带启动器与 Electron。内核是 npm 包 `@godcreator/gwb-kernel-desktop`，和插件一样装在每个 home 的 `node_modules` 里：这样插件的 peer `cordis` 与内核用的是 home 里同一份，各个 home 的内核版本也可以不同（[内核装进 home](/trajectory/2026-09-24-kernel-in-home)）。开始菜单里的「gwb-kernel」运行的就是启动器；安装程序只在装的时候用一次。

- 安装前在用户级配置里写好两项：`@godcreator` 的包从团队源下载；pnpm 放行 `@godcreator/*` 里发布不满一天的包
- 从 gitea 发布页下载 `gwb-setup-<版>.exe` 静默安装：装到 `%LOCALAPPDATA%\Programs\gwb-kernel`，只有启动器与 Electron
- 建 `homes\default`，用 pnpm 依次装内核包（精确版本）、`cordis`（内核包 peer 里的版本）、`cordis.yml` 里列的 11 个基础插件
- 启动：启动器选定 default，读内核包清单、比对 Electron 版本、加载内核；内核加载插件，把 MCP 入口地址写进 `runtime.json`，token 在 `mcp\secret.json`
- 另开一个 home：换一个目录照同样几步装一遍，设 `GWB_HOME` 用同一个 exe 启动，得到第二个窗口；它的 MCP 端口与 token 都是它自己的
- home 里没有内核包、或 Electron 版本不在内核包声明的范围里：启动器弹框说明，退出码 1，不写 home
- 每一步的完整命令与核对方法在仓根 `INSTALL.md`

## 功能

- **产出安装包**：在 `installer\build\dist\` 下生成 NSIS 安装程序 `gwb-setup-<版>.exe`（一键安装、按当前用户安装、不需要管理员权限），`<版>` 是启动器的版本号。同目录的 `win-unpacked\` 是打包前的目录，只用来验证；每次打包整个重新生成，别日常直接运行它
- **只带启动器**：内核、插件、pnpm 都不带。内核与插件由创建 home 的一方装进 home，经插件管理升级；只有 Electron 版本或启动器本身变了才重新打包
- **装好之后**：安装到 `%LOCALAPPDATA%\Programs\gwb-kernel\`，开始菜单出现「gwb-kernel」；启动器（清单、两个脚本、`semver`）在 `resources\app.asar` 里。home 在 `%APPDATA%\gwb-kernel\homes\` 下，和安装目录分开
- **启动器每次启动做四件事**：
  1. **选定 home**：按和内核同一条规则读 `GWB_HOME`——不设是 `default`；只写名字是 `%APPDATA%\gwb-kernel\homes\<名字>`；带路径分隔符就是那个目录本身。算出的绝对路径写回 `GWB_HOME`，内核启动时再选一次，一定落在同一个目录
  2. **检查内核包**：读 `<home>/node_modules/@godcreator/gwb-kernel-desktop` 的清单，`engines.electron` 要包含启动器自带的 Electron，清单里要有 `main`
  3. **加载内核**：import `main` 指向的入口，之后怎么准备 home、怎么加载插件全由内核决定
  4. **不满足就拒绝**：home 里没有内核包、清单读不了、没声明 `engines.electron`、版本不满足、没有 `main`、内核入口 import 失败，一律弹框说明是哪个 home、缺什么、怎么补，退出码 1

启动器与内核包之间只靠两个清单字段与环境变量 `GWB_HOME` 对接，约定写在[接缝 9 启动器加载内核](/docs/seams/launcher)。

## 接口

安装包本身不导出模块或类型。启动器与 home 里内核包之间的约定是[接缝 9 启动器加载内核](/docs/seams/launcher)；下表其余几项是它产出给人和 agent 用的东西，不属于接缝。

| 接口 | 谁在用、做什么 |
| --- | --- |
| 安装程序 `gwb-setup-<版>.exe` | 人和安装工作台的 agent 用它安装启动器；按当前用户安装，产品名 `gwb-kernel` 决定安装目录与开始菜单项。gitea 发布仓 `godcreator/gwb-kernel`（本仓的 git 远端 `gitea`）的 release 上传这个文件，顺序见[开发](/docs/develop#发版) |
| 开始菜单「gwb-kernel」与 `%LOCALAPPDATA%\Programs\gwb-kernel\gwb-kernel.exe` | 日常启动；设 `GWB_HOME` 再运行同一个 exe 就是另开一个 home，步骤在仓根 `INSTALL.md` 的「装一个别的 home」；开发插件用的测试 home 由 devkit 的 `devkit.home.new` 建 |
| home 里的内核包 `@godcreator/gwb-kernel-desktop` | 启动器从 `<home>/node_modules/@godcreator/gwb-kernel-desktop` 读清单、import `main` 指向的入口 |
| 内核包清单的 `engines.electron` | 内核声明它要的 Electron 版本范围；启动器拿自带的 Electron 比对 |
| 环境变量 `GWB_HOME` | 启动器读它选定 home，再写回绝对路径交给内核 |
| 拒绝时的弹框与退出码 1 | 告诉人或 agent 是哪个 home、缺什么、怎么补 |

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 启动器 `apps/launcher` | 打进安装包的全部代码：`pnpm build` 的产物与它的运行时依赖 `semver` | 构建失败时打包脚本停下；内核仓有已跟踪文件的未提交改动时脚本在第一步就停下 |
| electron | 安装包里的运行时：版本只写在 `apps/launcher` 的 `devDependencies.electron`，二进制从 `electron-builder.yml` 的 `electronDownload` 镜像下载 | 下载不下来时 electron-builder 失败，脚本停下 |
| electron-builder | 打出 NSIS 安装程序：`installer/package.json` 的开发依赖，工具二进制经脚本设的环境变量 `ELECTRON_BUILDER_BINARIES_MIRROR` 从国内镜像下载 | `installer/node_modules` 里没有时脚本先 `npm install`；装不上或打包失败时脚本停下 |
| git | `git status --porcelain` 检查内核仓没有未提交的改动 | 找不到 git 时脚本在第一步就报错停下 |
| gitea | 发布 release：git 凭据管理器里的凭据、gwb-gitea 插件的 `gitea.http` | 发布不了；安装包照样能在本地打出来 |

## 不做的事

- **不带内核、插件与 pnpm，不写 home**：启动器只读 home 里内核包的清单；home 里缺什么由创建 home 的一方照 `INSTALL.md` 装，启动器不替人安装
- **不决定内核怎么运行**：内核怎么准备 home、怎么加载插件全由内核自己决定；启动器只保证交给内核的 `GWB_HOME` 是它选定的那个绝对路径
- **不检查插件和内核兼不兼容**：插件 peer 里的内核包范围由插件管理比对
- **不把安装包的版本交给内核**：内核与插件都拿不到安装包的版本号
- **不自己定 electron 版本**：版本只写在 `apps/launcher/package.json` 的 `devDependencies.electron` 一处，打包时经命令行传给 electron-builder
