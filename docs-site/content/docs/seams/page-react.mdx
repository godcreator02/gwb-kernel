**本页回答**：页面上运行的代码写 `import 'react'` 时，页面凭什么找到文件；importmap 写在哪、有哪几个名字；页面代码构建时哪些名字不打进自己的产物。

<Diagram name="page-react" title="页面入口里写死的 importmap：react 的四个包名指向内核包 dist/react/ 里的文件">
- 页面入口 `dist/index.html` 的 `<head>` 里有一段 `<script type="importmap">`，只有 react 的四个包名，地址是相对 `index.html` 的 `./react/…`
- 这四个文件由内核包构建时打包进 `dist/react/`，和 `index.html` 在同一个目录下
- 外壳和插件的页面代码写 `import 'react'`，浏览器按这张表找到内核包里的文件，全页只有一份 react
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)：页面入口 `index.html` 里写着 importmap；构建时把 react 打进 `dist/react/`（怎么打见[内核应用](/docs/desktop#页面上的-react-怎么打包)）
- 页面上运行的代码：外壳和插件的浏览器端产物（窗格等）

地址相对 `index.html` 本身。内核用 `loadFile` 加载的就是内核包里的 `dist/index.html`，所以这四个地址指到的是同一个内核包 `dist/react/` 下的文件。

importmap 是静态的：内核启动时不计算、不推送，也不读任何包清单；`gwb:shell` 里只有外壳地址与只读状态页的数据。

## 约定

**内核应用**保证：

- **只有 react 的四个包名**：`react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`。页面上没有别的共享包名
- **写在页面脚本之前**：页面上第一次包名 import 发生时，importmap 已经生效
- **四个名字共用一个 react 实例**：`react-dom` 与 `react-dom/client` 两个文件把 `react` 外置，经同一张 importmap 指到 `react.js`
- **换 react 就是换内核包**：react 与 react-dom 是内核包的开发依赖，升级 react 就是发一版内核，重启后生效
- **这四个名字是接缝的一部分**：删掉或改掉一个名字、改掉它指向的东西，已经外置了它的页面代码会找不到文件，内核升 x（[开发](/docs/develop#发版)）

**页面代码**保证：

- **构建时把这四个名字外置**，不打进自己的产物、留给 importmap
- **别的依赖都打进自己的产物**：两个插件用同一个库就各带一份。同一个模块在页面上出现两份就会出错的（全局单例、hooks、跨组件树的 context），只有 react

## 不负责的事

- 内核应用不知道页面代码真的 import 了哪些名字，也不检查页面代码只 import 这四个——插件发版前由 devkit 的 `devkit.release` 从装好的内核包的 `dist/index.html` 读出这张表来检查
- 内核应用不替页面代码打包：除了 react 的四个文件，页面代码的产物由各自的构建决定

## 测试

`apps/desktop/tests/importmap.test.ts` 读 `index.html` 与构建产物：只有一段 importmap、只有 react 的四个包名、写在页面脚本之前，每个地址都是 `./react/<文件>` 并且构建后的 `dist/` 里有这个文件。四个文件的内容由 `apps/desktop/tests/react-bundles.test.ts` 保护（[内核应用](/docs/desktop#怎么单独测)）。页面上真的用上内核包里的 react，只能在隔离 home 里实机验证（[开发](/docs/develop#在隔离-home-里验证)）。
