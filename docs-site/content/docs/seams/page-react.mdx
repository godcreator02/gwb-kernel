内核负责页面的模块解析环境。React 的版本、打包和四个模块地址由 shell 负责；其他插件也可以提供自己的模块。

<Diagram name="page-react" title="提供方登记 → 页面准备 → 动态加载">
- shell 的 browserImports() 返回名字到本地文件 URL；主进程用 registerImports 登记
- 页面调用 prepareImports，从主进程取快照，在 preload 中追加 importmap
- 准备成功后才动态 import shell 或窗格；React 的文件来自 shell 包
</Diagram>

## 提供方和内核怎么连接

插件在代码中登记，并把撤销交给自己的生命周期：

```ts
ctx.effect(() => ctx.gwbKernel.registerImports(browserImports()))
```

`registerImports(imports): () => void` 接受精确裸名到本地 `.js` / `.mjs` 文件 URL 的映射；
不接受前缀、scopes 或远程模块。整个批次先校验，再原子登记。同名同 URL 可以重复登记、按引用计数释放；
同名不同 URL 直接拒绝，错误列出两个地址。撤销幂等，最后一个登记撤销时从主进程快照移除。

提供方发布无副作用的 `./browser-imports` 代码出口，导出同步 `browserImports()`，地址相对该模块的 `import.meta.url`。
运行时登记、下游构建外置名单和 devkit 发版检查复用它。内核不读取这个出口，也不扫描 home 或包清单；
它只接收插件交来的映射，因此没有 `gwb.shared` 或额外 JSON 声明。

## 页面什么时候能 import

```ts
await window.gwb.prepareImports(['react'])
const pane = await import(clientUrl)
```

`required` 可省略。给出时，任意名字尚未登记就拒绝，不等待未知提供方。调用方先用 cordis 依赖和服务就绪
保证提供方已登记。内核加载 shell、shell 加载窗格时都先准备，再动态 import；静态 import 无法等待这一步。

`prepareImports` 串行处理并发调用：经 `gwb:imports` 拉取当前快照，校验后只追加尚未注入的名字。
Promise 在 importmap 插入当前 Document 后完成；相同快照不重复插入，失败后允许再次请求。

## 撤销和升级

主进程登记与 Document 已解析的模块是两种状态。撤销登记不会卸载页面里的 ESM，也不会撤回 React 实例。
已注入名字被撤销或地址改变时，后续准备明确拒绝并要求整页重载。重新登记完全相同的地址仍使用原实例。
替换提供方版本后需要刷新页面；替换 kernel 则要重启 home。

React 的四个名字和构建产物归 shell，升级 React 不再要求发布 kernel。使用方 peer 写明提供方兼容范围，
只外置提供方承诺的名字，其他依赖打包进自己的产物。升级运行时版本是否需要下游适配由 shell 的契约决定。

## 验证

`browser-imports.test.ts` 测原子性、冲突、复用和撤销；`preload.test.ts` 测准备、并发、追加与重载边界；
`index-html.test.ts` 测准备前不加载、撤销时迟到的模块不挂载、失败报告不触发循环重试。
`importmap.test.ts` 核对内核不再携带静态 React 表与产物。
