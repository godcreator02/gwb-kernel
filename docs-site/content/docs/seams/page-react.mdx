**本页回答**：页面上运行的代码写 `import 'react'` 时，页面凭什么找到文件；importmap 写在哪、有哪些名字；页面代码构建时哪些名字不打进自己的产物。

<Diagram name="page-react" title="页面入口里写死的 importmap：react 的四个包名指向内核包 dist/react/ 里的文件">
- 页面入口 `dist/index.html` 的 `<head>` 里有一段 `<script type="importmap">`，只有 react 的四个包名，地址是相对 `index.html` 的 `./react/…`
- 这四个文件由内核包构建时打包进 `dist/react/`，和 `index.html` 在同一个目录下
- 外壳和插件的页面代码写 `import 'react'`，浏览器按这张表找到内核包里的文件，全页只有一份 react
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)：页面入口 `index.html` 里写着 importmap；构建时把 react 打进 `dist/react/`
- 页面上运行的代码：外壳和插件的浏览器端产物（窗格等）。构建时把这四个名字外置，运行时经 importmap 找到内核包里的文件

## 接口

页面入口 `index.html` 的 `<head>` 里，页面脚本之前：

{/* ref file="../apps/desktop/src/index.html" lines="14-24" */}

地址相对 `index.html` 本身。内核启动时 `loadFile` 加载的就是内核包里的 `dist/index.html`，所以指到的是同一个内核包 `dist/react/` 下的文件。这四个文件怎么生成见[开发](/docs/develop#内核包怎么打包-react)。

importmap 是静态的：内核启动时不计算、不推送，也不读任何包清单。`gwb:shell` 消息里只有外壳地址与只读状态页的数据（[外壳接管](/docs/seams/shell)）。

## 约定

内核应用保证：
- **importmap 只有 react 的四个包名**：`react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`。页面上没有别的共享包名
- **写在页面脚本之前**：页面上第一次包名 import 发生时，importmap 已经生效
- **换 react 就是换内核包**：react 与 react-dom 是内核包的开发依赖，升 react 发一版内核，重启内核后生效
- **这四个名字是接缝的一部分**：删掉或改掉一个名字、改掉它指向的东西，已经外置了它的页面代码会找不到文件，内核升 x

{/* has file="../apps/desktop/tests/importmap.test.ts" text="index.html 里只有 react 的四个包名，写在页面脚本之前" */}

页面代码保证：
- **构建时把这四个名字外置**，不打进自己的产物、留给 importmap
- **别的依赖都打进自己的产物**：两个插件用同一个库就各带一份。同一个模块在页面上出现两份就会出错（全局单例、hooks、跨组件树的 context）的，只有 react

## 不负责的事

- 内核应用不知道页面有没有真的 import 这几个名字，也不检查页面代码只 import 了这几个名字——那是 devkit 发版检查的事，见 devkit 仓文档站
- 内核应用不替页面代码打包：除了 react 的四个文件，页面代码的产物由各自的构建决定

## 测试

`apps/desktop/tests/importmap.test.ts` 读本仓源文件与构建产物：`index.html` 里只有一段 importmap、只有 react 的四个包名、写在页面脚本之前；每个地址都是 `./react/<文件>`，构建后 `dist/` 里有这个文件。打包产物的内容由 `apps/desktop/tests/react-bundles.test.ts` 保护（见[开发](/docs/develop#内核包怎么打包-react)）。页面上真的用上内核包里的 react，只能在隔离 home 里实机验证（见[开发](/docs/develop)）。
