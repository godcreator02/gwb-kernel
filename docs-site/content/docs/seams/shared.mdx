**本页回答**：页面上运行的代码写 `import 'react'` 或 `import '@godcreator/block-note'` 时，页面凭什么找到文件；谁来声明、内核应用怎么拼、名字冲突怎么办；提供方换了版本什么时候生效。

<Diagram name="shared-names" title="内核包与块笔记的库在包清单里声明，内核每次推送时拼成 importmap">
- 内核包自己的清单声明 react 的四个包名，指向内核包 `dist/react/` 里的文件；内核启动时解析一次，每次推送都先放进表里
- 块笔记的库在自己的清单里写 `gwb.shared` 声明它自己的包名；内核每次推送 `gwb:shell` 时扫描 home 清单里的每个包，按 home 解析成真实文件的 `file://` 地址
- 别的包声明了内核给了的名字：忽略这条声明，记一条 warn（同一句只记一次）
- 两个包声明同一个名字：两个都不收录，记一条 warn，页面 import 它直接报解析错误；别的名字不受影响
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)：扫描 home、拼 importmap、随 `gwb:shell` 推给页面入口；它自己的包清单也是一个提供方，声明 react 的四个包名
- 在包清单里声明 `gwb.shared` 的包（提供方）：内核应用不区分插件和库，home 清单 `dependencies` 里的任何包都可以声明。目前是块笔记的库 `@godcreator/block-note`：一个库，不在 `cordis.yml` 里，声明的是它自己的包名

页面上使用这些包名的代码（外壳、插件的窗格）不属于这条接缝，它的义务写在下面的「约定」里。

块笔记的库写的是 `"@godcreator/block-note": "./shared/index"`。react 的四个文件由内核包构建时生成，怎么生成见[开发](/docs/develop)。

子路径按包的 `exports` 解析，从 `<home>/node_modules/<包名>` 的真实路径开始，和加载插件用同一套解析（见[插件加载](/docs/seams/loading)）。内核应用把结果拼成一张 importmap（包名 → 真实文件的 `file://` 地址），作为 `gwb:shell` 消息的 `imports` 字段推给页面；页面入口经 `window.gwb.onShell` 收到后注入成 `<script type="importmap">`（通道见 [IPC 通道](/docs/seams/ipc)）：

声明写在包清单里，不由提供方在运行时调用接口登记：共享出去的代码只在页面上运行，库在主进程里没有代码可以去登记，包清单是它唯一能声明的地方。

## 约定

内核应用保证：
- **react 的四个包名由内核给**：内核启动时解析一次，解析不到就启动失败（说明内核包本身不完整）；别的包对这几个名字的声明一律忽略、记一条 warn，不算同名冲突。内核包升级 react 就是内核升版
- **其余名字一个名字只能有一个提供方**：两个包声明了同一个名字，全部不收、记一条 warn，不比版本、不挑谁更新
- **一个提供方出问题只影响它自己**：声明解析不到只记 warn，形状不对的声明直接跳过，别的名字照常收录
- **同一句警告只记一次**：importmap 每次推送都重新计算，不这样的话开机时每次推送都会把同一句警告再记一遍
- **提供方换了版本，下一次推送就是新地址**：每次推送都从真实路径重新解析，不会拿到 Node 解析缓存里上一版的文件（[importmap 也会遇到 Node 解析缓存](/trajectory/2026-09-17-wall-importmap-resolver-cache)）。但页面上的 importmap 只注入一次，**整页重新加载**之后才用上新版本；内核自己的那几条要重启内核才换

提供方保证：
- **声明的是整个页面只能有一份的运行时代码**：react、一个库的模型层这类要让页面上所有代码共用同一个实例的东西；不为了省体积把普通依赖声明出去
- 声明的子路径在自己的 `exports` 里写明
- 自己是 home 清单 `dependencies` 里的直接依赖：内核应用只扫这一层

使用这些包名的页面代码保证：构建时把这些名字外置，不打进自己的产物、留给 importmap；外置名单从声明它的包的清单取，不手抄。插件在 peer 里写了内核包，react 的四个名字就从内核包的清单取。

## 不负责的事

- 内核应用不知道页面有没有真的 import 某个名字，也不检查声明的文件能不能在浏览器里运行
- 内核应用不扫 home 清单的传递依赖，不区分提供方是插件还是库
- 内核应用不替提供方打包：除了 react 的四个文件，声明指向的文件是什么样由提供方自己的构建决定
- 提供方不管谁在用它声明的名字

## 测试

`apps/desktop/tests/imports.test.ts` 用手工构造的临时 home 保护上面的约定：同名全部拒绝、内核给的名字优先、解析不到只报 warn、链接换指向后拿到新地址、内核包的声明解析不到时抛出。`apps/desktop/tests/main.test.ts` 用真实的内核包启动，确认推给页面的 react 指向内核包、同一句警告只记一行；`apps/desktop/tests/index-html.test.ts` 确认页面只注入一次 importmap。页面整页重新加载后用上新版本，只能在隔离 home 里实机验证（见[开发](/docs/develop)）。
