**本页回答**：页面上的代码怎么调命令、收事件、知道外壳是谁；页面与内核应用的主进程之间有哪几个通道、各传什么；内核应用和页面各保证什么。

## 连接的模块

- 页面：内核包里的页面入口 `index.html`，以及外壳和页面上运行的任何代码；`window.gwb` 由内核包里的 `preload.cjs` 注入
- [内核应用](/docs/desktop)的主进程

命令到了主进程之后交给谁执行，是另一条接缝：[命令转交](/docs/seams/commands)。

| 通道 | 方向 | 传什么 |
| --- | --- | --- |
| `gwb:command` | 页面 → 主进程，回执原路返回 | 命令名与参数；内核应用交给命令转交（[接缝 10](/docs/seams/commands)），回执 `GwbResult` 原样交回 |
| `gwb:event` | 主进程 → 页面 | 插件经 `gwbKernel.emit` 发出的 payload，原样 |
| `gwb:shell` | 主进程 → 页面 | 整份外壳状态 `{ url, imports, report }`：外壳地址、importmap、只读状态页的数据 |
| `gwb:hello` | 页面 → 主进程 | 不带内容；主进程向发来的那个页面回一条 `gwb:shell` |

`gwb:shell` 在这几种时候发：页面发来 `gwb:hello`；插件调用 `setShell` 或撤销；插件加载完、条目状态变化、有新的 error 或 warn 日志（这三种在短时间内的多次合并成一次）。

`GwbWindowApi` 里 `onShell` 的参数只写了 `url` 与 `imports`：`report` 只给内核自己的页面入口画只读状态页用，不在契约里（只读状态页显示什么见[内核应用](/docs/desktop)）。`url` 怎么用见[外壳接管](/docs/seams/shell)，`imports` 从哪来见[页面上的包名](/docs/seams/shared)。

## 约定

**内核应用**保证：

- `gwb:command` 收到的命令名和参数交给命令转交，回执原样交回页面；内核应用自己不登记任何命令
- `gwb:event` 原样推给页面；窗口不在时事件就丢了，不补发
- 每条 `gwb:shell` 都是整份当前状态，不是增量；页面发来 `gwb:hello` 就回一条，所以外壳插件比页面先调用 `setShell` 也不会错过
- 页面上除了 `window.gwb` 什么都不注入：没有 Node、没有 `ipcRenderer`，新的通道只能由内核加

**页面**保证：

- 参数能经 Electron 的 IPC 传过去（结构化克隆：函数、DOM 节点传不过去）
- 不再需要时调用 `on`、`onShell` 返回的取消订阅函数
- `onShell` 只由内核的页面入口订阅；外壳和别的页面代码用 `command` 与 `on`

## 不负责的事

- 内核应用不认识命令名，不校验参数，不给命令分权限：命令交给谁、回执长什么样见[命令转交](/docs/seams/commands)
- 内核应用不保留事件，不知道谁在听，也不给事件标发送方：页面要区分，由发事件的插件自己写进 payload
