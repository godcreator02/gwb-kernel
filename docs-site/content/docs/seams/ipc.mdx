**本页回答**：页面上的代码怎么调命令、收事件、知道外壳是谁；主进程和页面之间有哪几个通道、各传什么；内核应用在中间做什么、不做什么。

<Diagram name="command-relay" title="内核只转交，不认识任何命令名">
- 命令：页面调用 `window.gwb.command(名字, 参数)`，经 IPC 通道 `gwb:command` 到内核，内核原样交给 `ctx.gwbCommands.run`；回执 `{ ok, data, error }` 原路返回
- `ctx.gwbCommands` 由 home 里的命令插件提供；home 里没有命令插件、或它没加载成功时，内核直接回 `{ ok: false, error }`
- 事件：插件调用 `ctx.gwbKernel.emit(payload)`，经 `gwb:event` 推到页面，页面用 `window.gwb.on(cb)` 接收；只推送、不保留
- 页面这边只有 `window.gwb` 的三个函数
</Diagram>

## 连接的模块

- 页面：内核的页面入口 `index.html`，以及外壳和页面上运行的任何代码；`window.gwb` 由 `preload.cjs` 注入
- [内核应用](/docs/desktop)的主进程：通道的处理在 `main.ts` 里

命令由 `ctx.gwbCommands` 执行：它是 home 里的命令插件 `@godcreator/gwb-commands`（在基础插件仓）提供的服务，内核应用只把命令交给它。

| 通道 | 方向 | 传什么 |
| --- | --- | --- |
| `gwb:command` | 页面 → 主进程，回执原路返回 | 命令名与参数；回执 `GwbResult` |
| `gwb:event` | 主进程 → 页面 | 插件经 `gwbKernel.emit` 发出的 payload，原样 |
| `gwb:shell` | 主进程 → 页面 | 整份外壳状态 `{ url, imports, report }`：外壳地址、importmap、只读状态页的数据 |
| `gwb:hello` | 页面 → 主进程 | 不带内容；主进程向发来的那个页面回一条 `gwb:shell` |

## 约定

内核应用保证：
- 命令名和参数原样交给 `ctx.gwbCommands.run`，回执原样返回；内核应用自己不注册任何命令
- 命令名不是字符串时回 `{ ok: false, error: '命令名要是字符串' }`；`ctx.gwbCommands` 不存在时回 `{ ok: false, error: '没有命令服务（ctx.gwbCommands），无法执行 <命令名>' }`
- 事件原样推给页面；窗口不在时事件就丢了，不补发
- 每条 `gwb:shell` 都是整份当前状态，不是增量；页面一订阅 `onShell` 就会先请求一次，所以外壳插件比页面先就位也不会错过

命令插件保证：任何命令都返回 `{ ok, data, error }`，命令抛错也收成 `ok: false`，页面不会收到异常（命令插件的文档在基础插件仓）。

页面保证：
- 参数能经 Electron 的 IPC 传过去（结构化克隆：函数、DOM 节点传不过去）
- 不再需要时调用 `on`、`onShell` 返回的取消订阅函数
- `onShell` 只由内核的页面入口订阅；外壳和别的页面代码用 `command` 与 `on`

## 不负责的事

- 内核应用不认识任何命令名，不校验参数，不给命令分权限，不提供命令服务
- 内核应用不保留事件，也不知道谁在听
- 内核应用在页面上除了 `window.gwb` 什么都不注入：没有 Node、没有 `ipcRenderer`，新的通道只能由内核加
