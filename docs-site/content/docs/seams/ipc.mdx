**本页回答**：页面上的代码怎样调命令、收事件、知道外壳是谁；页面与主进程之间有哪几个通道、各传什么；内核在页面这一侧保证的边界是什么；内核应用和页面各保证什么。

## 连接的模块

- 页面：内核包里的页面入口 `index.html`，以及外壳和插件在页面上运行的代码。`window.gwb` 由内核包里的 `preload.cjs` 注入
- [内核应用](/docs/desktop)的主进程

命令到了主进程之后交给谁执行，是另一条接缝：[命令转交](/docs/seams/commands)。

| 通道 | 方向 | 传什么 |
| --- | --- | --- |
| `gwb:request` | 页面 → 主进程 | 通道名与载荷；返回值由登记方解释，未登记或传输错误拒绝（[请求通道](/docs/seams/requests)） |

| `gwb:event` | 主进程 → 页面 | 插件经 `gwbKernel.emit` 发出的 payload，原样 |
| `gwb:shell` | 主进程 → 页面 | 整份外壳状态 `{ url, report }`：外壳地址、只读状态页的数据 |
| `gwb:imports` | 页面 → 主进程 | 返回当前登记快照；只接受顶层框架；prepareImports 准备后再动态 import |
| `gwb:hello` | 页面 → 主进程 | 不带内容；主进程向发来的那个页面回一条 `gwb:shell` |

### 页面边界

页面能调用整条命令总线，命令不分权限，所以内核在页面这一侧只保证一条边界：主框架只能是内核包里的 `index.html`，命令只收顶层框架发来的（[页面边界](/trajectory/2026-09-25-page-navigation-lock)、[网页链接交给系统浏览器](/trajectory/2026-09-25-open-external-links)）。三条判定是三个纯函数：

## 约定

**内核应用**保证：

- `gwb:command` 收到的命令名和参数交给命令转交，回执原样交回页面；内核自己不登记任何命令
- `gwb:command` 只接收顶层框架的调用：发送方是 iframe，或发送方框架已经跳走、销毁，都回 `{ ok: false, error }`，不转交
- 主框架只可能是内核包里的 `index.html`，新窗口一律不开（做法见上一节）
- `gwb:event` 原样推给页面；窗口不在时事件就丢了，不补发
- 每条 `gwb:shell` 都是整份当前状态，不是增量；页面发来 `gwb:hello` 就回一条，所以外壳插件比页面先调用 `setShell` 也不会错过
- 页面上除了 `window.gwb` 什么都不注入：没有 Node、没有 `ipcRenderer`，新的业务请求通道由插件用 `handleRequest` 登记，Electron IPC 接线仍归内核

**页面**保证：

- 参数能经 Electron 的 IPC 传过去（结构化克隆：函数、DOM 节点传不过去）
- 不再需要时调用 `on`、`onShell` 返回的取消订阅函数
- `onShell` 只由内核的页面入口订阅；外壳和别的页面代码用 `request`、`on` 与 `prepareImports`；旧代码仍可用 `command`
- 要在系统浏览器里打开网页，链接写 `target="_blank"` 或调用 `window.open`；不带 `target` 的链接点击是主框架跳转，会被拒绝

## 不负责的事

- 内核应用不认识命令名，不校验参数，不给命令分权限（[命令转交](/docs/seams/commands)）
- 内核应用不管 iframe 里加载什么：iframe 可以嵌网页、在自己里面跳转，`window.gwb` 只注入顶层框架。同源的 iframe 能经 `parent.gwb` 调到顶层框架的 `window.gwb`，那时发送方就是顶层框架，内核分不出来；页面上放哪些同源 iframe 由外壳和插件决定
- 内核应用不保留事件，也不给事件标发送方

## 测试

- `apps/desktop/tests/preload.test.ts`：给 `preload.cjs` 一个假的 `electron` 求值，证明页面上只有 `window.gwb` 的公开函数、`command` 走 `gwb:command`、订阅能取消、`onShell` 订阅后马上发 `gwb:hello`
- `apps/desktop/tests/page-boundary.test.ts`：三条判定——哪些跳转算整页重新加载、哪些发送方算顶层框架、`window.open` 的哪些地址交给系统浏览器
- `apps/desktop/tests/main.test.ts`：主进程回 `gwb:hello`、`gwb:command` 拒绝非顶层框架、主框架跳转与重定向被拒、`window.open` 按协议交给系统浏览器或拒绝、系统浏览器打开失败只写 warn

页面与主进程真的连起来只能在隔离 home 里实机验证（[开发](/docs/develop#在隔离-home-里验证)）：插件 `emit` 的事件页面收得到，整页重新加载后立刻收到当前外壳状态，拖进窗口的链接被拒，`target="_blank"` 的网页链接在系统浏览器里打开。
