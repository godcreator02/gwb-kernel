**本页回答**：页面怎么交给一个插件来渲染；外壳换了、卸载了、启动失败时页面显示什么；页面入口和外壳插件各保证什么。

<Diagram name="shell-handover" title="页面先问外壳是谁，外壳插件调用 setShell 后把 #root 交出去，外壳卸载后回到只读状态页">
- 页面入口订阅 `onShell`，订阅时发一次 `gwb:hello` 问当前外壳是谁；内核每次都回一条 `gwb:shell`：外壳地址（没有时是 `null`）、只读状态页的数据
- 还没有外壳时页面显示只读状态页
- 外壳插件调用 `setShell(url)`，内核记下地址、再推一次；页面入口 import 这个地址，把 `#root` 交给它的默认导出
- 外壳插件卸载时撤销函数执行，内核推 `url: null`；页面入口调用旧外壳的 `dispose`，回到只读状态页
- 后调用 `setShell` 的替换先调用的
</Diagram>

## 连接的模块

- 页面入口：内核包里的 `index.html`，在页面里运行
- 调用 `setShell` 的外壳插件：目前是 `@godcreator/gwb-shell`（界面插件仓 `gwb-ui-plugins`）

两者之间经过内核应用的主进程：`setShell` 是内核服务（[内核服务](/docs/seams/kernel)），外壳状态经通道 `gwb:shell` 推给页面（[IPC 通道](/docs/seams/ipc)）。

## 接口

外壳插件在主进程里调用 `setShell`，把自己在页面上运行的那个模块的地址交给内核：

```ts
const entry = new URL('./client.js', import.meta.url).href
ctx.effect(() => ctx.gwbKernel.setShell(entry))   // 撤销函数交给 ctx.effect，插件卸载时交还页面
```

{/* ref file="../apps/desktop/src/api.ts" lines="23-27" */}

页面入口 import 这个地址，只认它的默认导出：拿到 `#root`，返回可选的 `dispose`。

{/* ref file="../apps/desktop/src/api.ts" lines="48-49" */}

页面入口里写死了 importmap，外壳模块里 react 的四个包名可以直接 import（[页面上的 react](/docs/seams/page-react)）。

## 约定

**页面入口**保证：

- 订阅时先问一次当前外壳，外壳插件比页面先调用 `setShell` 也不会错过
- 同一时刻只有一个外壳：换外壳时先调用旧外壳的 `dispose`、清空 `#root`，再挂新的；旧外壳的 `dispose` 抛错只打一行 `console.error`，照样换
- 同一个地址连推两次，外壳只挂载一次，上一次还在 import 时也一样
- 地址是 `null`、import 失败、默认导出不是函数时，显示只读状态页，失败时第一行写明原因；不会白屏。失败后同一个地址再推来会重新 import。只读状态页显示什么见[内核应用](/docs/desktop)

**外壳插件**保证：

- 把 `setShell` 返回的撤销函数交给 `ctx.effect`，插件卸载时交还页面
- 在页面上运行的模块默认导出一个 `ShellBoot`；`dispose` 移除自己在页面上创建的一切
- 用到 react 时，构建时不打进自己的包，留给 importmap

## 不负责的事

- 页面入口不挑外壳：主进程推来哪个地址就挂哪个；谁能调用 `setShell` 也不限制（后调用的替换先调用的，见[内核服务](/docs/seams/kernel)）
- 页面入口除了只读状态页不渲染任何界面，不认识窗格
- 只读状态页不分析失败原因，没有按钮
- 外壳插件不管页面入口怎么拿到它的地址，也不直接接触 IPC 通道

## 测试

页面入口的接管逻辑由 `apps/desktop/tests/index-html.test.ts` 保护：把页面脚本放进一个极简的假 DOM 求值，证明外壳挂载、同一地址不重复挂载（在 import 时也一样）、换外壳先 `dispose` 旧的、外壳撤销时回到只读状态页、`dispose` 抛错与 import 失败的处理。外壳模块的形状由类型检查保护（外壳从内核包 `import type` 取 `ShellBoot`）。真实窗口里的显示在隔离 home 里实机验证（[开发](/docs/develop)）。
