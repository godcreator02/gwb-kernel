**本页回答**：页面怎么交给一个插件来渲染；外壳换了、卸载了、启动失败时页面显示什么；内核应用和外壳插件各保证什么。

<Diagram name="shell-handover" title="页面先问外壳是谁，外壳就位后把 #root 交出去，外壳卸载后回到只读状态页">
- 页面订阅 `onShell`，订阅时发一次 `gwb:hello` 问当前外壳是谁；内核每次都回一条 `gwb:shell`：外壳地址（没有时是 `null`）、importmap、只读状态页的数据
- 还没有外壳时页面显示只读状态页
- 外壳插件调用 `setShell(url)`，内核记下地址、再推一次；页面注入 importmap，import 这个地址，把 `#root` 交给它的默认导出
- 外壳插件卸载时撤销函数执行，内核推 `url: null`；页面调用旧外壳的 `dispose`，回到只读状态页
- 后调用 `setShell` 的替换先调用的

## 连接的模块

- [内核应用](/docs/desktop)：页面入口 `index.html`，加上主进程里记着当前外壳的 `setShell`
- 调用 `setShell` 的外壳插件：目前是 `gwb-shell`

外壳状态经 IPC 通道 `gwb:shell` 推给页面，通道本身见 [IPC 通道](/docs/seams/ipc)；`setShell` 在内核服务里的语义见[内核服务](/docs/seams/kernel)。

## 接口

外壳插件在主进程里只调用一次 `setShell`，页面入口只认外壳模块默认导出的形状：

```ts
// 外壳插件：把自己在页面上运行的模块的地址交给内核
const entry = new URL('./client.js', import.meta.url).href
ctx.effect(() => ctx.gwbKernel.setShell(entry))   // 撤销函数交给 ctx.effect，插件卸载时交还页面

// 外壳模块的默认导出：拿到 #root，返回可选的 dispose
type ShellBoot = (root: HTMLElement) => { dispose?(): void } | undefined | void
```

### 页面入口怎么接管

页面入口 `index.html` 收到 `gwb:shell` 后：

1. 注入 importmap——只注入一次、而且必须在第一句包名 import 之前，注入之后已经解析过的名字无法再改（importmap 从哪来见[页面上的包名](/docs/seams/shared)）
2. 地址和当前外壳相同、或同一个地址正在加载，就什么都不做
3. 调用旧外壳的 `dispose`（出错只打印），清空 `#root`
4. 地址是 `null`，显示只读状态页；否则 import 这个地址，把 `#root` 交给默认导出

### 没有外壳时

地址是 `null`、或外壳启动失败（import 失败、默认导出不是函数）时，页面显示只读状态页：纯文本、没有按钮，启动失败时第一行写明原因。页面上画什么、数据从哪来、什么时候重新推送，见[只读状态页的数据](/docs/desktop/status-page)。

## 约定

内核应用（主进程与页面入口）保证：
- 页面一订阅就能拿到当前外壳，不会因为外壳插件比页面先就位而错过
- 同一时刻只有一个外壳；换外壳时旧外壳先 `dispose` 再清空 `#root`
- 同一个地址连续推来两次，外壳只加载一次
- 外壳出任何问题，页面都回到只读状态页，不会白屏

外壳插件保证：
- 把 `setShell` 返回的撤销函数交给 `ctx.effect`，插件卸载时交还页面
- 在页面上运行的模块默认导出一个 `ShellBoot`；`dispose` 里移除自己在页面上创建的一切
- 在页面上运行的代码用到 react 这类共享包名时，构建时外置、留给 importmap

## 不负责的事

- 内核应用不挑外壳：谁调用 `setShell` 谁就是
- 内核应用（主进程与页面入口）不渲染任何界面（只读状态页除外），不认识窗格
- 内核应用的只读状态页不分析失败原因、不重试
- 外壳插件不管页面入口怎么拿到它的地址，也不直接接触 IPC 通道

## 测试

页面接管的逻辑写在 `index.html` 里、依赖窗口，没有单元测试；外壳模块的形状由类型检查保护（外壳从词汇表包取 `ShellBoot`）。其余在隔离 home 里实机验证（见[开发](/docs/develop)）：没有外壳插件时看到只读状态页，装上外壳后页面被接管，停用外壳后回到只读状态页，再启用又被接管。
