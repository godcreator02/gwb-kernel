**本页回答**：`cordis.yml` 里的一个插件怎么被找到、加载、卸载；内核应用和插件在这一步各保证什么；换插件改哪里。

<Diagram name="plugin-seam" title="内核不认识任何插件，插件只从 ctx 拿内核的东西">
- 内核在 cordis 的根上下文提供 `gwbKernel`：`dataDir`、`version`、`emit`、`setShell`；命令服务 `gwbCommands` 由 `cordis.yml` 里的命令插件提供
- 分界线上面是内核，不认识 `cordis.yml` 里任何插件、服务、命令的名字；下面是插件，每个都是 home 里的一个 npm 包，命令插件与插件管理也在下面
- 换插件的地方：`cordis.yml` 里的条目（一条写一个包名），包从 home 的 `node_modules` 按真实路径找到
- 插件之间通过 cordis 的服务和命令交互，不经过内核
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)（`@godcreator/gwb-kernel-desktop`）：用 cordis 官方的 loader 与 include 读 `cordis.yml`，加载其中的插件
- `cordis.yml` 的条目里写到的任何插件：每个都是 home 里的一个 npm 包

命令插件 `@godcreator/gwb-commands`（基础插件仓）与插件管理 `@godcreator/gwb-plugin-manager`（devkit 仓）也是 `cordis.yml` 里的普通插件，加载方式和别的插件没有区别。loader 与 include 是内核包自己的依赖，版本写死在内核包清单里；运行中怎么改条目见[home 布局与条目树](/docs/seams/home)。

## 接口

**插件包的入口**导出 cordis 认识的形状：

```ts
// 插件的入口（函数式写法；也可以默认导出一个继承 Service 的类）
export const name = '@godcreator/gwb-demo'
export const inject = ['gwbData']           // 依赖的服务都在了，cordis 才调用 apply
export function apply(ctx: GwbContext): void { /* … */ }
```

`ctx` 的类型 `GwbContext` 在[词汇表包](/docs/vocab)里，上面有哪些内核服务见[内核服务](/docs/seams/kernel)。

**`cordis.yml` 的条目**：一条写一个包名 `name`、一个手写的 `id`、可选的 `config`。整份 `cordis.yml` 在 loader 的根上是唯一的一条 include 条目，id 是 `home`，所以只读状态页和插件管理看到的条目都在 `home` 之下。

**包名怎么找到文件**：loader 要 import 一个包名时，内核应用替它按 home 解析——先把 `<home>/node_modules/<包名>` 解析成磁盘上的真实路径，再按包清单的 `exports` 找到入口文件，然后 import。从真实路径开始，运行中换了版本就能拿到新版本（为什么见[关键设计](/docs/design#包名一律按-home-解析)）；页面上的包名用的是同一个解析函数（[页面上的包名](/docs/seams/shared)）。

加载之后，cordis 调用插件的 `apply(ctx)`，或实例化它的 `Service` 类；`inject` 里的服务缺一个，插件就停在等待状态，补齐后自动加载。

## 约定

**内核应用**保证：

- `gwbKernel` 在 `cordis.yml` 里的任何插件加载之前就已提供（[内核服务](/docs/seams/kernel)）
- 包名一律从 home 的 `node_modules` 按真实路径解析，不从内核包自己的目录找
- 一个插件出错不让内核退出：没被处理的 rejection 和未捕获的异常只记一条 `kernel` 的 error 日志
- 退出时卸载整棵插件树，等各插件的清理结束，最多等 5 秒，没清理完也照样退出（[启动与退出](/docs/desktop/boot)）

**插件**保证：

- 包清单的 `exports` 写明入口，import 这个包名能拿到上面那种形状
- 依赖的服务写进 `inject`（包括命令插件提供的 `gwbCommands`）；`gwbKernel` 总在，不用写；要 home 路径只从 `gwbKernel.dataDir` 取
- 卸载时清理自己启动、创建的东西，异步的清理返回 promise——内核退出时等的就是这个 promise
- 和别的插件只通过服务和命令交互

## 不负责的事

- 内核应用不给插件提供安装接口，也不带 pnpm：装插件、升级插件由插件管理的 `plugin-manager.*` 命令做；插件之间的依赖齐不齐，内核应用不核对
- 内核应用不监听 `cordis.yml` 的改动：include 只在有 `hmr` 服务时才监听文件，内核不提供这个服务。运行中加载、卸载插件要调用 loader 的条目接口（插件管理就是这么做的，见[home 布局与条目树](/docs/seams/home)）
- 内核应用不判断插件是否加载成功：看 cordis 给这个条目的状态，`ACTIVE` 才算；没有外壳时只读状态页列出每个条目加载到哪一步（[内核应用](/docs/desktop)）
- 插件不管自己的包放在哪、怎么被找到：那是内核应用和 home 布局的事
