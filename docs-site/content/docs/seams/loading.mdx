**本页回答**：`cordis.yml` 里的一个插件怎么被找到、加载、卸载；内核应用和插件在这一步各保证什么；在哪里换插件。

<Diagram name="plugin-seam" title="内核不认识任何插件，插件只从 ctx 拿内核的东西">
- 内核在 cordis 的根上下文提供 `gwbKernel`：`dataDir`、`version`、`emit`、`setShell`；命令服务 `gwbCommands` 由 `cordis.yml` 里的命令插件提供
- 分界线上面是内核，不认识 `cordis.yml` 里任何插件、服务、命令的名字；下面是插件，每个都是 home 里的一个 npm 包，命令插件与插件管理也在下面
- 换插件的地方：`cordis.yml` 里的条目（一条写一个包名），包从 home 的 `node_modules` 按真实路径找到
- 插件之间通过 cordis 的服务和命令交互，不经过内核
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)（`apps/desktop`）：注册 cordis 的 loader，替它把包名解析成文件
- `cordis.yml` 的条目里写到的任何插件：每个都是 home 里的一个 npm 包

插件加载之后能用的内核服务见[内核服务](/docs/seams/kernel)。命令插件 `@godcreator/gwb-commands`（在基础插件仓）与插件管理 `@godcreator/gwb-plugin-manager`（在 devkit 仓）也是 `cordis.yml` 里的普通插件，内核应用加载它们和加载别的插件没有区别。

## 接口

**插件交出的**是一个 npm 包，入口导出 cordis 认识的形状：

```ts
// 插件的入口（函数式写法；也可以默认导出一个继承 Service 的类）
export const name = '@godcreator/gwb-demo'
export const inject = ['gwbData']           // 依赖的服务都在了，cordis 才调用 apply
export function apply(ctx: GwbContext): void { /* … */ }
```

入口拿到的上下文类型 `GwbContext` 在[词汇表包](/docs/vocab)里。

**`cordis.yml` 里的一条条目**写这个包名（`name`）、一个手写的 `id`、可选的 `config`。内核应用注册 cordis 官方的 loader，把承载 `cordis.yml` 的 include 条目（id 是 `home`）作为 loader 根层唯一的条目交给它；include 读这个文件，loader 按条目加载。loader 要 import 一个包名时，内核应用替它解析，一律交给 `bareImportFromHome`：

`bareImportFromHome` 先把 `<home>/node_modules/<包名>` 解析成磁盘上的真实路径，再从那里按包的 `exports` 找到入口文件：

{/* ref file="../apps/desktop/src/bare-import.ts" lines="12-24" */}

从真实路径开始，是为了运行中换了版本能拿到新版本：pnpm 布局里真实路径带版本号，不会命中 Node 为上一版记下的解析缓存。页面上的包名用的是同一个 `resolveFromHome`（见[页面上的包名](/docs/seams/shared)）。

加载之后，cordis 调用插件的 `apply(ctx)`（或实例化它的 `Service` 类）；`inject` 里的服务缺一个，插件就停在等待状态，补齐后自动加载。

### home 里和加载有关的文件

和加载有关的是 home 里的三样：`package.json`、`cordis.yml`、`node_modules/`。home 里每样东西归谁写列在[home 布局与条目树](/docs/seams/home)；home 怎么选定见 [home 的准备与单实例锁](/docs/desktop/home)。

## 约定

内核应用保证：
- `gwbKernel` 在 `cordis.yml` 里的任何插件加载之前就已提供
- 包名一律从 home 的 `node_modules` 按真实路径解析，不从内核自己的目录找
- 一个插件抛错只让它自己进入失败状态；没被处理的异常只记一条 error 日志，内核不退出
- 退出时卸载整棵插件树，等各插件的清理结束，最多等 5 秒，超时就强制退出（见[启动与退出](/docs/desktop/boot)）

插件保证：
- 入口在包的 `exports` 里写明，`import` 这个包名能拿到上面那种形状
- 依赖的服务写进 `inject`（包括命令插件提供的 `gwbCommands`）；要 home 路径只从 `gwbKernel.dataDir` 取
- 自己启动、创建的东西在卸载时清理掉，并把清理返回成 promise——内核退出时等的就是这个 promise
- 和别的插件只通过服务和命令交互

## 不负责的事

- 内核应用不给插件提供安装接口，也不带 pnpm：装插件、升级插件由插件管理（`@godcreator/gwb-plugin-manager`）的 `plugin-manager.*` 命令做；插件之间的依赖齐不齐，内核应用不核对
- 内核应用不监听 `cordis.yml`：运行中加载、卸载插件要调用 loader 的条目接口（插件管理就是这么做的，见[home 布局与条目树](/docs/seams/home)）
- 内核应用不判断插件是否加载成功：看 cordis 给这个插件的状态，`ACTIVE` 才算；没有外壳时只读状态页会列出每个条目加载到哪一步（见[只读状态页的数据](/docs/desktop/status-page)）

## 测试
