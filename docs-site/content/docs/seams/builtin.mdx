**本页回答**：内核应用怎么把两个内置插件复制进构建产物、按什么顺序加载、交给它们什么；两个内置插件要满足什么才能这样被加载；怎么单独测。为什么这两个插件内置在内核里，见[关键设计](/docs/design#命令插件与插件管理内置在内核里)。

## 两侧

- 一侧是[内核应用](/docs/desktop)：构建脚本 `apps/desktop/scripts/copy-assets.mjs` 与主进程入口 `main.ts`
- 另一侧是两个内置插件：[命令插件](/docs/commands)（`plugins/commands`）与[插件管理](/docs/plugin-manager)（`plugins/plugin-manager`）

## 交换什么

**构建产物的位置与形状**：构建的最后一步把两个插件的 `package.json`、`dist/`、`skills/` 复制进内核的 `dist/builtin/<目录名>/`，每次整个重建；插件还没构建就报错：

**模块与条目名**：内核按目录名找到复制过来的插件，读它的 `package.json` 取包名，import 它的 `dist/index.js`：

内核交给 loader 的 import 先按包名查这两个内置模块，查不到再按 home 解析。所以条目的 `name` 可以直接写包名，已有 home 的 `cordis.yml` 里残留的同名条目也解析到内置的这份代码：

{/* ref file="../apps/desktop/src/main.ts" lines="303-313" */}

**根层条目与顺序**：loader 根层依次是 `commands`、`plugin-manager`、承载 `cordis.yml` 的 include 条目 `home`：

{/* ref file="../apps/desktop/src/main.ts" lines="315-323" */}

做成条目、而不是用 `ctx.plugin` 直接加载，是因为数据、说明书等插件按调用方的条目认身份：没有条目，内置插件就存不了显示名、登记不了说明书（[内置插件做成根层条目](/trajectory/2026-09-23-builtin-as-root-entries)）。条目名写包名，说明书表、日志里报的就是包名，和命令表对得上（见[说明书](/docs/seams/skills)）。

**插件管理的 config**：两个字符串——承载 `cordis.yml` 的 include 条目的 id，和 pnpm 可执行文件的路径。类型由插件管理定义，内核按它构造：

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="170-189" */}

config 只能是字符串这类纯数据：loader 会深拷贝条目的 config，带方法的对象（比如条目树本身）传过去就丢了方法（实验 `probes/2609232050_builtin-as-root-entry/`）。插件管理拿到 id 之后怎么取条目树，见[条目树与 home 布局](/docs/seams/home)；pnpm 路径怎么选、怎么用，见 [pnpm](/docs/seams/pnpm)。命令插件没有 config。

## 两边各保证什么

内核应用保证：
- 两个内置插件先于 `cordis.yml` 加载：cordis 对同一个服务名第二次提供一律报错、不覆盖。内置的先提供，残留的同名条目只会加载失败，不影响使用；顺序反过来的话内置的那份会失败，而且之后不会自己恢复（实验 `probes/2609231919_duplicate-service-provider/`）
- 条目 id 固定是 `commands`、`plugin-manager`，`name` 是包名（`@godcreator/gwb-commands`、`@godcreator/gwb-plugin-manager`）；根层条目不写进 `cordis.yml`
- 插件管理的 config 是 `{ home, pnpm }`，`home` 就是根层那条 include 条目的 id
- 退出时卸载 loader，两个内置插件和 `cordis.yml` 里的插件一起卸载

两个内置插件保证：
- 构建产物除 node 内置模块外没有包名 import：复制到 `dist/builtin/` 就能运行，不需要旁边有 `node_modules`（各自的 `artifact.test.ts` 守着）
- 说明书按 `new URL('../skills/', import.meta.url)` 找，`skills/` 与 `dist/` 同级，复制时保持这个关系
- 插件管理在 `apply` 开头核对 config：没有内核给的 config（`cordis.yml` 里残留的旧条目）就报「……是旧版留下的，删掉它」
- 插件管理不在构造时取条目树：它加载时 include 条目排在后面、还没建好，用到时再取（见[条目树与 home 布局](/docs/seams/home)）

## 一侧不管什么

- 内核应用不知道两个插件提供什么服务、登记什么命令；它只在转交页面发来的命令时取 `ctx.gwbCommands`（见 [IPC 通道](/docs/seams/ipc)）
- 内核应用不清理 `cordis.yml` 里残留的同名条目，它们照旧加载失败：命令插件那条报同名服务，插件管理那条报「删掉它」
- 两个内置插件不知道自己是从哪个目录被复制、怎么被 import 的；它们不在 home 的 `package.json` 与 `cordis.yml` 里，不能停用、卸载、热升级，随内核一起发版
