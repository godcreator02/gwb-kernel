**本页回答**：页面发来的命令怎么交到命令插件手里；内核应用对命令插件要求什么；home 里没有命令插件时会怎样；换一个命令插件要满足什么。

<Diagram name="command-relay" title="内核应用只调用 gwbCommands.run，不认识任何命令名">
- 页面调用 `window.gwb.command(命令名, 参数)`，经 IPC 通道 `gwb:command`（接缝 3）到内核应用
- 内核应用每次转交时读取 `ctx.gwbCommands`，把命令名和参数原样交给它的 `run`，再带上第三个参数 `{ via: 'ui' }` 标明来自界面；命令插件找到登记了这条命令的插件执行
- 回执 `{ ok, data, error }` 原路返回页面；命令不存在、处理函数抛错，命令插件也收成 `ok: false`
- 命令名不是字符串，或 `ctx.gwbCommands` 不存在（home 里没装命令插件、它没加载成功或已停用）时，内核应用直接回 `{ ok: false, error }`
- 命令插件是 `cordis.yml` 里的普通插件；内核应用认识的只有 `gwbCommands` 这个服务名
</Diagram>

## 连接的模块

- [内核应用](/docs/desktop)：主进程里处理通道 `gwb:command` 的那一段
- 命令插件 `@godcreator/gwb-commands`（基础插件仓 `gwb-base-plugins`）：`cordis.yml` 里的普通插件，提供服务 `gwbCommands`

页面怎么把命令送到主进程是[IPC 通道](/docs/seams/ipc)的事，本页从命令到了主进程讲起。

## 接口

`run(命令名, 参数, { via: 'ui' })` 返回 promise，得到的值原样交回页面，页面按内核包导出的 `GwbResult` 读它。第三个参数是请求来源：命令插件把它原样交给处理函数，处理函数据此认出请求来自界面（比如块笔记的撤销只撤来自界面的提交）。内核转交的命令一律带 `'ui'`；MCP 入口调用时带 `'mcp'`、插件直接调用时不带，这两种与内核无关。`gwbCommands` 的完整类型（登记命令、来源的取值等）不在内核包导出的类型里，由命令插件自己导出。

## 约定

**内核应用**保证：

- 每条命令都在转交时读取 `ctx.gwbCommands`：命令插件运行中装上、换掉、停用，下一条命令就跟着变
- 命令名和参数原样交给 `run`，第三个参数固定是 `{ via: 'ui' }`；`run` 得到的值原样交回页面
- 不是页面顶层框架发来的命令不转交，回 `{ ok: false, error }`（见 [IPC 通道](/docs/seams/ipc)）；命令名不是字符串时回 `{ ok: false, error: '命令名要是字符串' }`；`ctx.gwbCommands` 不存在时回 `{ ok: false, error: '没有命令服务（ctx.gwbCommands），无法执行 <命令名>' }`
- 只找 `gwbCommands` 这一个服务名，不认识任何命令名，自己不登记命令

{/* ref file="../apps/desktop/src/main.ts" lines="234-239" */}

**命令插件**保证：

- 提供名为 `gwbCommands` 的服务，`run(命令名, 参数, 来源)` 返回 promise；不认识第三个参数的旧版命令插件忽略它，行为不变
- 任何命令都回 `{ ok, data, error }`：命令不存在、处理函数抛错也收成 `ok: false`，`run` 不 reject
- 来源只转交，不按来源限制谁能调哪条命令

## 不负责的事

- 内核应用不校验参数，不给命令分权限，不检查回执的形状，也不捕获 `run` 的异常：`run` 一旦 reject，页面上的 `command` 就收到一个异常
- 内核应用不管命令怎么登记：登记规则由命令插件定（当前的命令插件要求每条命令带非空的 `name`、`description`、`usage`），内核应用不检查
- 命令插件不管页面怎么把命令送到主进程（[IPC 通道](/docs/seams/ipc)）

## 测试

`apps/desktop/tests/main.test.ts` 保护内核应用这一边：命令名不是字符串、没有命令服务时回失败回执；home 里有一个提供 `gwbCommands` 的测试插件时，命令原样交给它、回执原样交回。命令插件自己的行为由它在基础插件仓里的测试保护。页面调到真实插件登记的命令、调不存在的命令收到 `ok: false`，只能在隔离 home 里实机验证（[开发](/docs/develop)）。
