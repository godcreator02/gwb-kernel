**本页回答**：页面上的代码怎么调用插件的命令、怎么收到插件的事件；内核在中间做什么、不做什么；在哪里换命令总线。

<Diagram name="command-relay" title="内核只转交，不认识任何命令名">
- 命令：页面调用 `window.gwb.command(名字, 参数)`，经 IPC 通道 `gwb:command` 到内核，内核原样交给 `ctx.gwbCommands.run`；回执 `{ ok, data, error }` 原路返回
- 没有插件提供 `gwbCommands` 时，内核直接回 `ok: false`
- 事件：插件调用 `ctx.gwbKernel.emit(payload)`，经 `gwb:event` 推到页面，页面用 `window.gwb.on(cb)` 接收；只推送、不保留
- 页面这边只有 `window.gwb` 的三个函数；换命令总线只要换一个提供 `gwbCommands` 服务的插件
</Diagram>

## 接口

页面这边只有 `window.gwb`，由 preload 注入，页面上运行的任何代码都能直接调用：

```ts
interface GwbWindowApi {
  command<T = unknown>(command: string, args?: unknown): Promise<T>   // 调一条命令
  on(cb: (payload: unknown) => void): () => void                     // 收事件，返回取消订阅
  onShell(cb: (shell: { url: string | null; imports: Record<string, string> }) => void): () => void
}

// 命令的回执
interface GwbResult<T = unknown> { ok: boolean; data?: T; error?: string }
```

`onShell` 是给页面入口用的，见[外壳接管页面](/docs/seams/shell)。

内核在主进程这边只做转交：

```ts
ipcMain.handle('gwb:command', (_event, command, args) => {
  if (typeof command !== 'string') return { ok: false, error: '命令名要是字符串' }
  const bus = ctx.gwbCommands
  if (bus === undefined) return { ok: false, error: `没有命令服务（ctx.gwbCommands），认不出 ${command}` }
  return bus.run(command, args)
})
```

## 两边各保证什么

内核保证：
- 命令名和参数原样交给命令总线，回执原样返回；内核自己不注册任何命令
- 事件原样推给页面；页面没打开时事件就丢了，不补发

命令总线保证（今天是 commands 插件，见[标准例子 E1](/docs/criteria/examples/e1-commands)）：
- 任何命令都返回 `{ ok, data, error }`，命令抛错也收成 `ok: false`，不会让页面收到异常
- 页面、agent、插件用的是同一张命令表

## 内核不管什么

- 不认识任何命令名，不校验参数
- 不给命令分权限
- 不保留事件，也不知道谁在听

## 怎么单独测

这条接缝的内核部分只有转交，没有可以单独抽出来测的逻辑。在隔离 home 里实机验证：没有命令总线插件时，页面调命令收到 `ok: false`；装上之后能调到别的插件注册的命令；插件 `emit` 的事件页面收得到。命令总线自己的行为在 commands 插件的仓里测。

## 代码从哪读

- 页面一侧：`preload.cjs` 的 `command` 与 `on`
- 主进程一侧：`main.ts` 的 `ipcMain.handle('gwb:command', …)` 与 `kernel.emit`
- 类型：`packages/gwb-plugin-api/src/index.ts` 的 `GwbWindowApi`、`GwbResult`
