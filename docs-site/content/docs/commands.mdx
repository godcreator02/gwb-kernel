**本页回答**：命令插件管什么、不知道什么；它的表长什么样；它对外提供什么、依赖什么；怎么单独测；代码从哪读。登记、注销、执行的规则是它和别的插件之间的约定，在接缝页[命令总线](/docs/seams/command-bus)。

## 管什么

一张「命令名 → 处理函数」的表。插件把自己的能力登记成命令；页面经 `window.gwb.command`（内核原样转交，见 [IPC 通道](/docs/seams/ipc)）、agent 经 MCP 入口的 `run`、别的插件直接调 `run`，用的都是这一张表。

它是内核内置的插件，源码在 `plugins/commands/`，包 `@godcreator/gwb-commands` 不单独发布。内核把它作为 loader 根层的条目 `commands`、排在 `cordis.yml` 之前加载，所以 `cordis.yml` 里的任何插件加载时命令总线都已经在了；它不能停用、卸载，随内核一起升级（见[内置插件的加载](/docs/seams/builtin)）。

## 不知道什么

- 不知道有哪些命令、命令做什么：表里的每一条都是别的插件登记的，它自己一条命令也不登记
- 不知道调用方是谁：页面、agent、插件调的是同一个 `run`，不带调用方身份
- 不知道命令怎么展示给 agent：`index` / `search` 的格式由 MCP 入口决定
- 不运行命令行程序：处理函数就是普通的 JS 函数，在主进程里执行。启动子进程运行命令行程序的是基础插件仓的 `gwb-node-cli` 与 `gwb-py-cli`，它们把自己的命令也登记到这张表上
- 不知道说明书插件的类型：只按形状取它用到的 `register(dir)`（见下面「依赖的接口」）

## 数据结构

一张按命令名索引的 `Map`，每条记录是命令的说明（`name`、`description`、`usage`、`plugin`，缺的补成空串）加处理函数。注销时按记录本身比对，所以同名替换后先登记的一方删不掉接手的那条：

## 提供的接口

服务 `ctx.gwbCommands`，三个方法 `register` / `run` / `list`，类型在[词汇表包](/docs/vocab)里。形状、回执、同名与注销的规则、登记方要做到什么，都在接缝页[命令总线](/docs/seams/command-bus)。

服务用 `ctx.effect` 包住 `provide`：本插件卸载时服务自动撤销，不会留下一张没人维护的命令表。

{/* ref file="../plugins/commands/src/index.ts" lines="23-30" */}

它还带一份说明书 `gwb-commands`，给 agent 讲回执怎么拆、失败有哪几种；它怎么到 agent 手里见接缝页[说明书](/docs/seams/skills)。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `RegistryLog`（`info` / `warn`） | 每次登记、执行写一行日志 | cordis 的 `ctx.logger('gwb-commands')` | `registry.test.ts` 里不写日志的空函数；要检查告警的用例传 `vi.fn()` |
| 词汇表包的 `GwbCommands`、`GwbCommandDef`、`GwbResult` | 表的形状与回执 | `@godcreator/gwb-plugin-api`，只 `import type` | 同一份类型 |
| cordis 的 `ctx.provide` / `ctx.effect` | 提供服务、卸载时撤销 | 内核里的 cordis | 没有单元测试，从源码启动内核验证 |
| 说明书插件的 `register(dir)`（可选） | 登记自带的说明书 | `cordis.yml` 里的说明书插件 `gwbSkills` | 没有单元测试，实机验证（见[说明书](/docs/seams/skills)） |

说明书插件是可选的：用 `ctx.inject(['gwbSkills'], …)` 局部注入，**不写进 `export const inject`**——没装说明书插件的 home 里，命令总线也必须能加载，写进 `inject` 的话，少了说明书插件整个命令总线就一直等待。它不 import 说明书插件的类型，只按形状声明用到的那一个方法：说明书插件反过来依赖命令总线，这样包之间的依赖是单向的。pnpm 12 的 `pnpm -r` 遇到工作区里的依赖环会直接报错退出。

## 怎么单独测

测试在 `plugins/commands/tests/`，在仓根运行 `pnpm check` 时和内核、插件管理的测试一起跑：

{/* tree dir="../plugins/commands/tests" depth="1" */}

- `registry.test.ts`：直接调 `createRegistry`，传入假的日志函数，不需要 cordis；证明命令表的全部规则——同名替换、注销只删自己、回执两种形状、抛错转回执、写日志。逐条对应的测试钉在[命令总线](/docs/seams/command-bus#怎么单独测)
- `artifact.test.ts`：构建产物里相对 import 带扩展名、除 node 内置模块外没有包名 import（没构建时跳过），复制进内核的 `dist/builtin/` 就能运行
- `self-report.test.ts`：`package.json` 里的自我描述（提供的服务、说明书份数、命令条数）与文档一致

服务真正提供出去、说明书登记上，要从源码启动内核验证（见[开发](/docs/develop)）。
