# 系统地图

读完这页你能回答：一次点击、一句日志、一个件的浏览器那半，各自经过哪些进程与文件。

## 三个进程

| 进程 | 是什么 | 起法 | 说什么 |
| --- | --- | --- | --- |
| **主进程** | Electron 本体：开窗、算 home、汇日志、转发命令 | `pnpm start` 直接起 | `mainLog` |
| **宿主** | 纯 node，cordis 与所有件住这儿 | 主进程 spawn，`ELECTRON_RUN_AS_NODE=1` + `--expose-internals` | cordis 日志走 exporter，自己的话走 `host` |
| **渲染层** | 页面。内核不画任何东西，画的是外壳件 | 宿主 `ready` 之后才开窗 | `console` → `console-message` 事件 |

先起宿主、后开窗——渲染层第一句话就是问内核要 `kernel.info`。

## 盘上有什么

| 路径 | 是什么 |
| --- | --- |
| `apps/desktop/src` | 内核本体（约 1300 行） |
| `packages/gwb-plugin-api` | 词汇表包（46 行，五个名字） |
| `docs-site/` | 文档站（fumadocs + livedoc），dev 起在 4314 |
| `<home>/package.json` | 件的 dependencies。pnpm 维护 |
| `<home>/cordis.yml` | 条目表。**内核唯一认的配置文件**，但解析归 include |
| `<home>/node_modules/` | 包本身：件、共享包都在 |
| `<home>/logs/gwb.log` | 全量字节流（主进程劫持 stdout/stderr 落盘），2 MB 切段留 20 份 |

home 的完整位置：`%APPDATA%\gwb-kernel\homes\<GWB_HOME ?? default>`。它是个普通的 npm 项目根——装件、卸件、配件都在这儿做。

## 四条流

| 流 | 方向 | 路 | 详见 |
| --- | --- | --- | --- |
| **命令** | 页面 → 件 | preload → IPC → 主进程（UUID + 120s）→ stdin → 宿主 dispatch → `gwbCommands.run` | [桥](/docs/kernel/bridge) |
| **回执与事件** | 件 → 页面 | fd3 → 主进程按 id 配对 / `gwb:event` 转发 → preload | [桥](/docs/kernel/bridge) |
| **日志** | 四源 → 页面与文件 | 源头结构化 → 主进程发号进环形缓冲 → preload 两口；平行漏斗落盘 | [日志](/docs/kernel/logs) |
| **资产** | 盘 → 页面 | `gwb://asset/plugins/<包>/<exports 子路径>`，主进程直读 home 的 node_modules | [桥](/docs/kernel/bridge) |

## 速查

| 什么 | 值 |
| --- | --- |
| 文档站 dev | `pnpm --filter gwb-kernel-docs-site dev`，端口 4314 |
| 本机 Verdaccio | `http://127.0.0.1:4873/`，`@godcreator02` scope 指向它 |
| home 选择 | 环境变量 `GWB_HOME`（严格 kebab-case），不给是 `default` |
| 宿主环境变量 | `GWB_DATA_DIR` / `GWB_LOG_DIR` / `GWB_VERSION` |
| 资产 URL | `gwb://asset/plugins/<包名>/<exports 子路径>`，浏览器入口约定 `./client` |
| 内核原生命令 | 只有 `kernel.info`，其余全转发命令总线 |
| 门禁 | `pnpm check`（typecheck + oxlint + vitest）；`pnpm doc`（livedoc，单独跑） |
