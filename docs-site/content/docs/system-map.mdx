# 系统地图

**本页回答**：内核由哪几块组成、各住哪个文件、先读什么、一次命令 / 一条事件 / 一行日志 / 一个外壳各走哪条路。

## 两个进程

整个应用只有两个进程。**主进程**是 Electron 本体，cordis 与所有件都住在这里，件 `import('electron')` 就够得着开窗、菜单、子进程（[单进程](/trajectory/2026-09-09-single-process)）。**渲染进程**是那一扇窗里的页面，内核只给它一个空 `#root`、一张 importmap 与一个 `window.gwb`，画什么归外壳件。

## 模块

内核本体是 `apps/desktop/src` 下这几个文件；`main.ts` 是组装者，其余不带 electron 的纯逻辑各自成文件、测试在 `apps/desktop/tests/`：

{/* tree dir="../apps/desktop/src" depth="1" */}

| 模块 | 管什么 | 住哪 |
| --- | --- | --- |
| [home](/docs/kernel/home) | 选 home、铺两个文件、单开锁、`runtime.json` | `main.ts` 顶层 |
| [挂载](/docs/kernel/loading) | 起 cordis、loader 与 include、node 半裸名解析、启动与退出 | `main.ts`、`bare-import.ts` |
| [importmap](/docs/kernel/importmap) | 浏览器半裸名：收 `gwb.shared` 拼 `file://` 表 | `imports.ts` |
| [页面与桥](/docs/kernel/bridge) | 开窗、三条 IPC、页面根、只读现状 | `main.ts`、`preload.cjs`、`index.html`、`entry-state.ts` |
| [日志](/docs/kernel/logs) | 唯一出口、上限与轮转、只记不退 | `main.ts`、`log-file.ts` |
| [契约面](/docs/kernel/contract) | 内核与件、页面之间的全部类型 | `packages/gwb-plugin-api` |

**读序**：home → 挂载 → importmap → 页面与桥 → 契约面；日志独立。依赖方向是 `main.ts` 吃其余一切；`imports.ts` 吃 `bare-import.ts`；`entry-state.ts`、`log-file.ts` 谁也不吃；契约面只被 import 类型。

**可跳过**：`dist/`（tsc 直出的产物，`index.html` 与 `preload.cjs` 原样复制）、`installer/`（出安装包，见 AGENTS）、`probes/`（实验材料）、`docs-site/`（本站）。

## 开机顺序

模块顶层同步做完 home 那一段（选 home、铺文件、开日志、单开锁、`runtime.json`）并注册日志 exporter、provide `gwbKernel`；`whenReady` 之后 `main()` 先开窗、再挂 loader 与 include、等整棵条目树收敛。开窗先于挂件，所以外壳没上来时页面已经在画只读现状。

## 四条流

| 流 | 方向 | 路 |
| --- | --- | --- |
| 命令 | 页面 → 件 | `window.gwb.command` → `gwb:command` → 命令总线 `ctx.gwbCommands.run` → 回执回页面。内核不认识任何命令名 |
| 事件 | 件 → 页面 | `gwbKernel.emit` → `gwb:event` → `window.gwb.on`，火过就灭 |
| 外壳 | 内核 → 页面 | `setShell` / 撤销 / `gwb:hello` / 去抖重推 → `gwb:shell` 带 `{ url, imports, report }` → 页面注 importmap、import 外壳 |
| 日志 | 三路 → 出口 | 件、内核、页面 console 都走 `ctx.logger` → 内核的 exporter → stderr 加 `gwb.log` |

没有自定义资源协议：页面直接吃 `file://`，件的浏览器半地址由件自己从 `import.meta.url` 算。
