# 从这里开始

**本页回答**：gwb-kernel 是什么；从双击到外壳画出来，内核依次做了哪些事、各归哪一页；带着不同来意该怎么往下读。

## 是什么

god 工作台的内核：一个 Electron 应用，只做**第一个件跑起来之前必须发生的事**，其余一切——界面、命令、数据、设置、装卸、给 agent 开的门——全是件。它存在的理由是一个验收标准：用最小的内核把件正常跑起来，件得真能干活。只做什么、刻意不做什么、往内核里加东西要过的两道关，见[边界](/docs/boundary)。

整个应用只有两个进程：

```text
主进程（Electron）                               渲染进程（一扇窗）
  内核：home · 挂载 · 日志 · importmap             页面根 index.html
  cordis ── 所有件都住这里                         window.gwb（preload 注入）
     ◀── gwb:command ─────────────────────────   外壳件与各窗格（件的浏览器半）
     ── gwb:event / gwb:shell ─────────────────▶
```

件跑在主进程里，`import('electron')` 就够得着开窗、菜单、子进程；页面里画什么全归外壳件，内核只给一个空 `#root`、一张 importmap 与一个 `window.gwb`。

## 跟着一次开机走一遍

1. **选定 home**：看 `GWB_HOME` 定目录，归一成磁盘真实路径，Chromium 的 userData 也按 home 拆开——[home](/docs/kernel/home)
2. **铺两个文件**：缺 `package.json` 或 `cordis.yml` 就补最小的一份，在的不动——[home](/docs/kernel/home)
3. **开日志文件**：`gwb.log` 带上限与轮转，从这一刻起出错人看得见——[日志](/docs/kernel/logs)
4. **拿单开锁**：同一 home 已有实例就报一句退出——[home](/docs/kernel/home)
5. **写 `runtime.json`**：这一轮进程的 pid、版本、调试口——[home](/docs/kernel/home)
6. **起 cordis**：根上下文指向 home，挂上日志出口，未捕获的错只记不退，provide `gwbKernel`——[挂载](/docs/kernel/loading)、[日志](/docs/kernel/logs)、[契约面](/docs/kernel/contract)
7. **开窗**（等 Electron ready 之后）：撤掉默认菜单，加载页面；页面订上 `onShell` 问一次，此刻还没有外壳，画只读现状——[页面与桥](/docs/kernel/bridge)
8. **挂件**：挂 loader 与 include，按 home 解析每个件的包名，把 `cordis.yml` 里的条目挂成一棵树，等它收敛——[挂载](/docs/kernel/loading)
9. **外壳上台**：外壳件挂上时调 `setShell`，内核把外壳地址连同现算的 importmap 推给页面——[页面与桥](/docs/kernel/bridge)、[importmap](/docs/kernel/importmap)
10. **页面交接**：页面注上 importmap、import 外壳模块、把 `#root` 交给它——[页面与桥](/docs/kernel/bridge)

开机之后，运行期只有四条路：

| 流 | 方向 | 路 |
| --- | --- | --- |
| 命令 | 页面 → 件 | `window.gwb.command` → `gwb:command` → 命令总线，回执原路回页面；内核不认识任何命令名 |
| 事件 | 件 → 页面 | `gwbKernel.emit` → `gwb:event` → `window.gwb.on`，火过就灭 |
| 外壳 | 内核 → 页面 | `setShell` 与撤销、页面打招呼、条目换态与错误行到来时，推 `gwb:shell` |
| 日志 | 三路 → 出口 | 件、内核、页面 console 都走 `ctx.logger`，汇进 stderr 与 `gwb.log` |

**关机**：窗全关即退出；退出前内核拆掉整棵件树、等收尾交回来，挂死的收尾超时硬退——[挂载](/docs/kernel/loading)。

## 按来意读

- **改内核**：先读[边界](/docs/boundary)，再按侧栏顺序读完模块页；仓根 AGENTS 是动手前的硬约束
- **写件**：读[契约面](/docs/kernel/contract)与[页面与桥](/docs/kernel/bridge)；写件的整条路在 devkit 的说明书 `gwb-devkit`
- **排障**：先看[日志](/docs/kernel/logs)（`gwb.log` 在 home 里），外壳起不来时页面上的只读现状见[页面与桥](/docs/kernel/bridge)，进程找不着看 [home](/docs/kernel/home) 的 `runtime.json`

## 模块索引

内核本体是 `apps/desktop/src` 下这几个文件，`main.ts` 是组装者，其余不带 electron 的纯逻辑各自成文件、测试在 `apps/desktop/tests/`：

{/* tree dir="../apps/desktop/src" depth="1" */}

| 模块 | 管什么 | 住哪 |
| --- | --- | --- |
| [home](/docs/kernel/home) | 选 home、铺两个文件、单开锁、`runtime.json` | `main.ts` 顶层 |
| [挂载](/docs/kernel/loading) | 起 cordis、loader 与 include、node 半裸名解析、启动与退出 | `main.ts`、`bare-import.ts` |
| [importmap](/docs/kernel/importmap) | 浏览器半裸名：收 `gwb.shared` 拼 `file://` 表 | `imports.ts` |
| [页面与桥](/docs/kernel/bridge) | 开窗、三条 IPC、页面根、只读现状 | `main.ts`、`preload.cjs`、`index.html`、`entry-state.ts` |
| [日志](/docs/kernel/logs) | 唯一出口、上限与轮转、只记不退 | `main.ts`、`log-file.ts` |
| [契约面](/docs/kernel/contract) | 内核与件、页面之间的全部类型 | `packages/gwb-plugin-api` |

依赖方向：`main.ts` 吃其余一切；`imports.ts` 吃 `bare-import.ts`；`entry-state.ts`、`log-file.ts` 谁也不吃；契约面只被 import 类型。**可跳过**：`dist/`（tsc 直出的产物）、`installer/`（出安装包）、`probes/`（实验材料）、`docs-site/`（本站）。
