# 从这里开始

**本页回答**：gwb-kernel 是什么；从双击启动到外壳显示出来，内核依次做了哪些事、每一步由哪一页讲；带着不同的目的来，该接着读哪几页。

## 是什么

god 工作台的内核：一个 Electron 应用，只做**第一个插件运行之前必须完成的事**，其余一切——界面、命令、数据、设置、插件的安装与卸载、给 agent 用的 MCP 入口——全部由插件实现。它存在的理由是一条验收标准：用尽可能小的内核让插件正常运行，而且插件要真能完成实际工作。内核只做什么、刻意不做什么见[边界](/docs/boundary)；往内核里加东西要满足的两个条件，以及 peer 与 importmap 这几类反复遇到的选择怎么决定，见[关键判据](/docs/criteria)。

整个应用只有两个进程：

```text
主进程（Electron）
  内核：初始化 home · 加载插件 · 日志 · 生成 importmap
  cordis 实例 ── 所有插件都运行在这里
        ▲ gwb:command（页面调命令）   ▼ gwb:event / gwb:shell（推给页面）
渲染进程（应用唯一的窗口）
  页面入口 index.html · window.gwb（由 preload 注入）
  外壳插件与各窗格（插件在页面里运行的代码）
```

插件运行在主进程里，`import('electron')` 就能直接创建窗口、菜单和子进程；页面上显示什么全部由外壳插件决定，内核只提供一个空的 `#root`、一张 importmap 和一个 `window.gwb`。

## 一次启动依次发生什么

1. **选定 home**：根据 `GWB_HOME` 确定目录，规范化为磁盘上的真实路径，Chromium 的 userData 也按 home 分开存放——[home](/docs/kernel/home)
2. **补齐两个文件**：缺 `package.json` 或 `cordis.yml` 就补一份最小的，已有的不动——[home](/docs/kernel/home)
3. **打开日志文件**：`gwb.log` 有大小上限并会轮转，从这一刻起出了错人能看到——[日志](/docs/kernel/logs)
4. **获取单实例锁**：同一个 home 已经有实例在运行，就报一句错然后退出——[home](/docs/kernel/home)
5. **写 `runtime.json`**：本次运行的进程 pid、版本、调试端口——[home](/docs/kernel/home)
6. **创建 cordis 实例**：根上下文指向 home，注册日志输出，未捕获的错误只记录、不退出，provide `gwbKernel`——[加载插件](/docs/kernel/loading)、[日志](/docs/kernel/logs)、[内核接口](/docs/kernel/contract)
7. **创建窗口**（等 Electron ready 之后）：移除默认菜单，加载页面；页面订阅 `onShell` 并请求一次当前外壳，这时还没有外壳，于是显示只读状态页——[页面与 IPC](/docs/kernel/bridge)
8. **加载插件**：注册 loader 与 include，按 home 解析每个插件的包名，把 `cordis.yml` 里的条目加载成一棵树，等整棵树的加载全部结束——[加载插件](/docs/kernel/loading)
9. **外壳就位**：外壳插件加载成功时调用 `setShell`，内核把外壳地址连同每次重新计算的 importmap 推送给页面——[页面与 IPC](/docs/kernel/bridge)、[importmap](/docs/kernel/importmap)
10. **页面交给外壳**：页面注入 importmap、import 外壳模块、把 `#root` 交给它——[页面与 IPC](/docs/kernel/bridge)

启动之后，运行期间只有四类数据流：

| 数据流 | 方向 | 路径 |
| --- | --- | --- |
| 命令 | 页面 → 插件 | `window.gwb.command` → `gwb:command` → 命令总线，回执沿原路返回页面；内核不认识任何命令名 |
| 事件 | 插件 → 页面 | `gwbKernel.emit` → `gwb:event` → `window.gwb.on`，只推送、不保留 |
| 外壳 | 内核 → 页面 | 调用 `setShell` 或撤销它、页面发来 `gwb:hello`、条目状态变化、有新的 warn / error 日志行时，推送 `gwb:shell` |
| 日志 | 三个来源 → 输出 | 插件、内核、页面 console 都走 `ctx.logger`，汇入 stderr 与 `gwb.log` |

**退出**：所有窗口关闭即退出；退出前内核卸载整棵插件树，等各插件做完退出前的清理，某个清理卡住不结束时超时后强制退出——[加载插件](/docs/kernel/loading)。

## 按要做的事选读

- **改内核**：先读[边界](/docs/boundary)与[关键判据](/docs/criteria)，再按侧栏顺序读完各模块页；仓根 AGENTS 列的是动手前必须遵守的硬约束
- **写插件**：读[关键判据](/docs/criteria)、[内核接口](/docs/kernel/contract)与[页面与 IPC](/docs/kernel/bridge)；写插件的完整流程在 devkit 的说明书 `gwb-devkit`
- **排查故障**：先看[日志](/docs/kernel/logs)（`gwb.log` 在 home 里）；外壳启动不了时页面上显示的只读状态页见[页面与 IPC](/docs/kernel/bridge)；找不到进程就看 [home](/docs/kernel/home) 里的 `runtime.json`

## 模块索引

内核本体是 `apps/desktop/src` 下这几个文件：`main.ts` 负责把各部分组装起来，其余不依赖 electron 的纯逻辑各自一个文件，测试在 `apps/desktop/tests/`：

{/* tree dir="../apps/desktop/src" depth="1" */}

| 模块 | 管什么 | 位置 |
| --- | --- | --- |
| [home](/docs/kernel/home) | 选定 home、补齐两个文件、单实例锁、`runtime.json` | `main.ts` 顶层 |
| [加载插件](/docs/kernel/loading) | 创建 cordis 实例、注册 loader 与 include、主进程一侧的包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）解析、启动与退出 | `main.ts`、`bare-import.ts` |
| [importmap](/docs/kernel/importmap) | 页面一侧的包名 import：收集各包的 `gwb.shared`，拼成 `file://` 地址表 | `imports.ts` |
| [页面与 IPC](/docs/kernel/bridge) | 创建窗口、三条 IPC 通道、页面入口（`index.html`）、只读状态页 | `main.ts`、`preload.cjs`、`index.html`、`entry-state.ts` |
| [日志](/docs/kernel/logs) | 唯一的日志输出、大小上限与轮转、出错只记录不退出 | `main.ts`、`log-file.ts` |
| [内核接口](/docs/kernel/contract) | 内核与插件、页面之间的全部类型 | `packages/gwb-plugin-api` |

依赖方向：`main.ts` 依赖其余所有文件；`imports.ts` 依赖 `bare-import.ts`；`entry-state.ts`、`log-file.ts` 不依赖任何其他文件；词汇表包只被 import 类型。**可跳过**：`dist/`（tsc 直接输出的构建产物）、`installer/`（生成安装包）、`probes/`（实验材料）、`docs-site/`（本站）。
