**本页回答**：gwb-kernel 是什么、为什么只做这么一点；一次启动和一条命令从头走到尾经过哪些模块；带着不同的目的来，接着读哪几页；内核仓有哪些包、每两个模块之间靠哪条接缝相连、细节在哪一页。

## 是什么，为什么这么小

god 工作台的内核：一个 Electron 应用，cordis 运行在主进程里，负责**主进程插件启动与页面模块解析环境**——选定 home、创建 cordis 实例并加载插件、打开窗口并把页面交给外壳、在页面与插件之间传递消息、自己出错时让人看得见。命令总线、插件管理、界面、数据、设置、给 agent 用的 MCP 入口，全部是 `cordis.yml` 里的插件，各在自己的仓里。内核越小，换掉任何一个插件都不用改内核；什么能进内核、刻意不做什么，见[关键设计](/docs/design)。

内核自己也和插件一样装在 home 里：安装包只带启动器与 Electron，内核应用是 npm 包 `@godcreator/gwb-kernel-desktop`，和 `cordis`、各插件一起装在每个 home 的 `node_modules` 里，home 根上只有一份 `cordis`。所以各个 home 可以装不同版本的内核，新内核先装进隔离 home 验证。

## 一次启动与一条命令

**一次启动**：人从开始菜单打开「gwb-kernel」→ 启动器按 `GWB_HOME` 选定 home，确认 home 里的内核包能在这个 Electron 上运行，import 内核（接缝 9）→ 内核准备 home、打开日志、写 `runtime.json`（接缝 7），创建 cordis 实例并提供 `gwbKernel`（接缝 2）→ 打开窗口，页面入口先显示只读状态页 → loader 按 `cordis.yml` 从 home 加载插件（接缝 1、6）→ 外壳插件调用 `setShell`，页面入口 import 外壳、把 `#root` 交给它（接缝 4），外壳先登记 React 模块，页面 prepareImports 后加载（接缝 5）。每一步的顺序与为什么见[启动与退出](/docs/desktop/boot)。

**一条命令**：页面调用 commands 客户端 → `window.gwb.request` 经 `gwb:request` 到主进程（接缝 3）→ 内核按通道找到插件登记的处理器（接缝 10）→ commands 校验载荷、固定 ui 来源并执行命令，回执原路返回。插件要主动告诉页面什么，调 `gwbKernel.emit`，经 `gwb:event` 推到页面。一路上的日志——插件、内核、页面 console——汇成一条流写进 home 里的 `gwb.log`（接缝 8）。

## 按要做的事读

- **想知道内核为什么长这样**：[关键设计](/docs/design)
- **在本仓动手**（怎么跑、怎么检查、怎么在隔离 home 里验证、怎么发版）：[开发](/docs/develop)；硬约束在仓根 AGENTS
- **改内核应用**：[内核应用](/docs/desktop)看它有哪些功能、提供哪些接口，再看[启动与退出](/docs/desktop/boot)
- **写插件**：内核给插件的全部接入面先看总表[插件之间怎么连](/docs/wiring)，再按需读[插件加载](/docs/seams/loading)、[内核服务](/docs/seams/kernel)、[日志](/docs/seams/log)，接口类型从[包根导出的接口类型](/docs/desktop/api)取
- **做界面**：[IPC 通道](/docs/seams/ipc)、[外壳接管](/docs/seams/shell)、[浏览器模块解析](/docs/seams/page-react)
- **换命令插件**：[请求通道](/docs/seams/requests)
- **改了内核之后**：版本号升哪一位见[开发](/docs/develop#发版)；插件怎样发现自己不兼容新内核见[关键设计](/docs/design#插件在-peer-里写兼容哪个内核)
- **第一次安装、另开一个 home，或改安装包与启动器**：[安装包与启动器](/docs/installer)；给 agent 照着装的完整步骤在仓根 `INSTALL.md`
- **排查故障**：日志在 home 里的 `gwb.log`（[日志](/docs/seams/log)）；外壳没加载出来时页面显示[只读状态页](/docs/desktop#只读状态页)；找进程看 home 里的 `runtime.json`（[runtime.json](/docs/seams/runtime)）
- **词不认识**：[术语表](/docs/glossary)

## 接缝图

模块不一定是代码：页面入口与 `window.gwb` 是内核包里的两个文件，在页面里运行；`runtime.json` 是写在 home 里、给外部工具读的一份记录。

<Diagram name="seam-map" title="虚线框按模块所在的位置分组，连线是接缝，编号对应下面的表">
- 页面（渲染进程）：页面入口 `index.html` 与 `#root`、`window.gwb`（`preload.cjs` 注入），这两个文件随内核包发布；还有外壳与插件在页面上运行的代码（窗格等）
- 内核应用（`apps/desktop`，装进 home）：包名解析、loader 与 include（内核包自己的依赖，版本写死）、组装（`main.ts`：`gwbKernel`、IPC、窗口、`runtime.json`）、日志、只读状态页的数据、浏览器模块解析、包根导出的接口类型（`api.ts`，只有类型，接缝 2、3、4 用这些类型）
- `cordis.yml` 里的插件（各自的仓，装进 home）：外壳、MCP 入口、插件管理 `gwb-plugin-manager`（生命周期插件仓 `gwb-lifecycle-plugins`）、命令插件 `gwb-commands`（基础插件仓），以及数据、设置、说明书、日志插件等任何插件
- 安装包（`apps/launcher` 与 `installer/`）：只有启动器与 Electron；启动器经接缝 9 从 home 加载内核包
- cordis（外部依赖，home 根上只有一份）：内核、loader、include 与插件共用
- home（磁盘上的目录）：`package.json`、`cordis.yml`、`node_modules/`（内核包、cordis、插件）、`gwb.log`、`runtime.json`
- 外部工具：devkit、安装工作台的 agent，经接缝 7 读 `runtime.json`
- 人经页面使用工作台，AI 经 MCP 入口使用；这两条是入口，不算接缝
- 实线接缝有代码接口；点线接缝（7、9）只靠约定
</Diagram>

一条接缝连接的两个模块可以各自替换：只要交换的东西不变，换掉其中一个，另一个不用改。连线停在框边上的（接缝 1），接的是那一组里的每一个模块。每条接缝由什么测试保护，写在它自己那一页；左栏接缝页标题前的数字就是图上的编号。

| # | 接缝 | 连接的模块 | 接口 | 细节在 |
| --- | --- | --- | --- | --- |
| 1 | 插件加载 | 内核应用 ↔ `cordis.yml` 里的插件 | `cordis.yml` 的条目；按 home 把包名解析成真实路径再 import；插件的 `apply` 或 `Service` 类 | [插件加载](/docs/seams/loading) |
| 2 | 内核服务 | 内核应用 ↔ 任何插件 | `ctx.gwbKernel` 的 `dataDir`、`version`、`emit`、`setShell` | [内核服务](/docs/seams/kernel) |
| 3 | IPC 通道 | 页面 ↔ 内核应用 | `window.gwb` 的四个函数；`gwb:request`、`gwb:event`、`gwb:shell`、`gwb:hello`、`gwb:imports` 五个通道；页面边界 | [IPC 通道](/docs/seams/ipc) |
| 4 | 外壳接管 | 页面入口 ↔ 调用 `setShell` 的插件 | 外壳模块的默认导出 `ShellBoot`、`#root`、`dispose`；没有外壳时显示只读状态页 | [外壳接管](/docs/seams/shell) |
| 5 | 浏览器模块解析 | 内核应用 ↔ 页面上运行的代码 | 插件 registerImports → 页面 prepareImports → 动态加载 | [浏览器模块解析](/docs/seams/page-react) |
| 6 | home 布局与条目树 | 内核应用 ↔ 插件管理 | home 的文件布局；loader 与 include 的版本与条目树；按真实路径解析包名 | [home 布局与条目树](/docs/seams/home) |
| 7 | runtime.json（约定） | 内核应用 ↔ 外部工具 | pid、启动时刻、版本、调试端口；读的一方自己确认进程还在 | [runtime.json](/docs/seams/runtime) |
| 8 | 日志 | 内核应用 ↔ 任何插件 | 三个来源汇成一条 cordis 日志流；插件注册 exporter；`gwb.log` 一行的格式 | [日志](/docs/seams/log) |
| 9 | 启动器加载内核（约定） | 安装包里的启动器 ↔ home 里的内核包 | 选 home 的同一条规则与写回的 `GWB_HOME`；内核包清单的 `engines.electron` 与 `main` | [启动器加载内核](/docs/seams/launcher) |
| 10 | 请求通道 | 内核应用 ↔ 提供方插件 | `handleRequest` 登记处理器；未登记时请求拒绝 | [请求通道](/docs/seams/requests) |

cordis 与 `cordis.yml` 里的插件都不在本仓：cordis 是外部依赖；命令插件在基础插件仓 `gwb-base-plugins`，插件管理在生命周期插件仓 `gwb-lifecycle-plugins`，其余插件各在自己的仓里。内核包发到团队包源，插件从它的包根 `import type` 内核的接口类型；启动器只随安装包发布。
