一次启动跨三个地方：主进程里的内核与 cordis、窗口里的页面、磁盘上的 home 目录。下面从启动器找到内核开始，一步一步走到外壳接管页面。

<KernelBootSteps />

## 两段：模块求值时与 ready 之后

**入口模块求值时**做完不需要窗口的部分：选定 home、设置 userData、拿单实例锁、打开 `gwb.log`、检查 home 里的两个文件、检查调试端口并写 `runtime.json`、建 cordis 实例并注册日志出口、提供 `gwbKernel`、注册 IPC 处理器。**Electron ready 之后**才去掉默认菜单、开窗口并加载页面、注册 loader、加载全部条目。

入口不能顶层 `await app.whenReady()`：Electron 要等入口模块求值完才触发 ready，顶层等它会互相等待，进程静默卡住（[ESM 主进程顶层等 ready 会卡死](/trajectory/2026-09-09-wall-esm-await-whenready)）。ready 之后的部分放在 `whenReady()` 返回的 promise 的 `then` 里执行，出错也在这条链上处理：

## 顺序是约束

- **`gwbKernel` 在注册 loader 之前提供**：它在模块求值时就提供了，而 loader 在 ready 之后才注册，任何插件加载时它都已经在（[`gwbKernel` 要在注册 loader 之前提供](/trajectory/2026-09-07-wall-gwbkernel-provide-early)）
- **`gwb.log` 在其余检查之前打开**：缺文件、端口给错、`runtime.json` 写不进时的那一行 error 才进得了日志文件
- **窗口先于 loader**：插件加载的过程中页面就显示只读状态页，页面的 console 也从一开始就进日志
- **`loader.internal` 在加载条目之前设好**：主进程没有 `--expose-internals`，不设的话 loader 按自己所在的位置解析包名，插件静默加载失败
- **等 loader 加载完才写「up」**并推一次页面状态：那时各条目都已走到各自的终态

窗口创建时不显示，`ready-to-show` 之后才显示；窗口底色 `#151518` 与 `index.html` 的背景、安装包图标的底色是同一个值，改就三处一起改，窗口出现与整页重新加载的第一帧都不闪白。

## 启动失败与插件出错

出错时人从哪里看到原因，取决于错在哪一步：选一种情况，看 stderr、`gwb.log`、错误框、`runtime.json` 与进程各自的结果。

大多数启动失败走同一个函数：先写一行 error（stderr 与 `gwb.log` 各一份），再弹错误框、框里带 `gwb.log` 的路径，退出码 1。Electron 保证错误框在 ready 之前也弹得出来，这时窗口可能还没有。

插件和内核在同一个进程里。内核对未捕获的异常和没人处理的 rejection 只写一行名字为 `kernel` 的 error，不退出（[两个进程合并为一个](/trajectory/2026-09-09-single-process)）；插件自己加载失败由 cordis 记在它的条目上，挂载日志与只读状态页上看得到。

## 退出

所有窗口关闭就退出。退出前内核卸载 loader，整棵插件树的清理逐层执行；插件启动的长期子进程靠这一步结束，否则主进程一退它们就成了孤儿进程。谁创建了 cordis 实例，谁负责卸载它。

<QuitCleanupCases />

{/* ref file="../apps/desktop/src/main.ts" lines="391-414" hash="a8eb09335cb7" blob="db3e92ccd653" */}

- **等到清理结束要内核和插件都做到**：内核 `dispose()` 之后还要 `await()`，才等得到嵌套的异步清理；插件要把清理的 promise 从 effect 的清理函数里**返回**出来。少做一方，退出日志一切正常，子进程却还在运行（[退出收尾：内核等、插件返回](/trajectory/2026-09-12-quit-dispose-two-halves)）
- **最多等 5 秒**：某个插件的清理卡住时，到 5 秒就不再等它、照常退出；清理中抛出的错误只写一行 warn
- **退出时不写挂载日志**：开始清理之前先停掉按条目写的挂载日志，卸载整棵插件树时不逐条写「已卸载」和汇总
- **只拦一次**：第一次进入 `will-quit` 时拦下退出、开始清理；清理完调用的 `app.quit()` 会再次进入，那一次放行。loader 还没加载就退出时没有要卸载的，同样放行

Electron 被强制结束或崩溃时，任何清理都来不及执行，插件的子进程仍可能留下。

## 守住它的测试

`apps/desktop/tests/main.test.ts` 把 electron 换成假的、cordis 与 loader 用真的，覆盖 ready 之后的顺序与「up」那一行、启动失败的各种情况、未捕获异常不退出、退出时先卸载插件树再放行。真实窗口的显示、插件清理超过 5 秒时照常退出、插件的子进程是否都已结束，只能在隔离 home 里实机验证（[开发](/docs/develop)）。
