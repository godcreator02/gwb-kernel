**本页回答**：内核的日志写到哪；`gwb.log` 的上限为什么是 128 MB、怎么调；到上限时怎么轮转；打不开、写不进、轮转失败时怎么办；怎么测。日志流本身（插件、内核、页面三个来源怎么汇成一条、插件怎么收到）见接缝页[日志](/docs/seams/log)。

## 写到哪

内核只有一个日志输出：每一行同时写 stderr 和 home 里的 `gwb.log`，一个插件都没有时人也看得见。一行的格式是 `<时间> <级别> <名字> <正文>`。

{/* ref file="../apps/desktop/src/main.ts" lines="61-87" */}

没有终端时（stderr 的另一端断开）每写一次 stderr 都抛 EPIPE，内核忽略它，日志文件照常写。

## 上限与轮转

- **默认上限 128 MB，只留一份旧的**：`gwb.log` 写到上限就改名为 `gwb.log.1`（原来的 `.1` 删掉），再打开一份新的 `gwb.log`。磁盘占用最多是两个上限，256 MB
- **为什么是 128 MB**：这份日志用来事后查错，不是存档，要看的是最近一次启动到现在那一段。按实测的写入速度，平时能留两天半，遇到大量输出日志的插件时十几分钟轮转一次。依据写在上面钉住的注释里
- **上限由环境变量 `GWB_LOG_LIMIT_MB` 调**，单位 MB；`0` 表示不轮转，排查问题要留全部日志时用。没给、空的、不是整数、负数都按默认值：一个打错的环境变量不该让上限失效。放在环境变量上、不做成设置项，是因为改它是排查问题时的一次性操作，做成设置项要改设置插件的契约

{/* ref file="../apps/desktop/src/log-file.ts" lines="29-36" */}

当前文件写了多少字节，只在打开时量一次，之后按写入的字节累加，不每行查一次文件大小。上一次运行留下的文件打开时已经超过上限的，下一行日志就把它轮转掉。

轮转的顺序有两处是 Windows 的要求：**先关句柄再改名**（开着句柄改名不保证成功，成功了句柄也还指向改名后的旧文件，之后的日志会写进旧的那份）；**改名之前先删掉目标文件**（改名遇到已存在的目标不一定覆盖）。

{/* ref file="../apps/desktop/src/log-file.ts" lines="121-147" */}

## 出错时不抛

日志文件的用处是「内核出错时人看得见」，它自己出问题绝不能反过来让内核崩溃，所以每一处文件操作都自己处理错误、只告警一句：

- **轮转失败**：原来那份还在原地，重新打开它照常往后写，再多写一个上限的量才重试，不在每一行上重试
- **打不开文件**：这段时间只写 stderr，一分钟后的下一行日志再试一次
- **写不进去**：只告警一次，直到某一次写成功才恢复告警，磁盘满时不会每行告警两遍

{/* ref file="../apps/desktop/src/log-file.ts" lines="149-164" */}

告警直接写 stderr，**不走写日志的那个函数**：那个函数也往这份文件写，出问题时会再次进入自己。
