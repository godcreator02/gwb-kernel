**本页回答**：home 是什么、怎么选定；内核启动时对 home 做了什么；home 里的每样东西归谁写；同一个 home 怎么保证只运行一个实例。

## 一个 home 是一个独立的目录

home 是磁盘上的一个目录，也是一个普通的 npm 项目根：装了哪些插件、加载哪些条目、各插件的数据、日志、本次运行的记录，全在里面。不同的 home 可以同时运行，插件、端口、数据互不影响；开发和验证用单独创建的隔离 home，不碰日常用的 `default`。插件要 home 路径只从 `ctx.gwbKernel.dataDir` 取（[内核服务](/docs/seams/kernel)）。

## 选定 home

环境变量 `GWB_HOME` 选定用哪个 home，不设时是 `default`。给的是名字，home 在 `<appData>/gwb-kernel/homes/<名字>`；带路径分隔符，就当成目录本身。目录不存在就创建。

{/* ref file="../apps/desktop/src/main.ts" lines="35-41" */}

路径最后经 `realpathSync.native` 统一成磁盘上的真实路径：大小写、junction、斜杠写法不同的同一个 home 必须得到同一个字符串，下面的单实例锁才认得出「同一个 home」。

Chromium 的 userData 每个 home 一份，放在 `<home>/electron`：单实例锁按它区分，多个 home 同时运行时 Local Storage 也互不影响。homes 的根从 appData 算、不从 userData 算，因为 userData 已经按 home 分开了。

## 补齐最小形态

home 能启动的最小形态是一份包清单和一个空的条目表。缺哪样补哪样，已有的一律不覆盖；之后这两个文件归 pnpm、include 和插件管理。内核不做 `cordis.yml` 的模板与自动修复。

{/* ref file="../apps/desktop/src/main.ts" lines="49-56" */}

## home 里有什么

home 里每样东西归谁写，列在 [home 布局与条目树](/docs/seams/home)的「home 的文件布局」。内核自己写的是：缺了时补的 `package.json` 与 `cordis.yml`，以及 `gwb.log`、`runtime.json`；`electron/` 是按上面那段放进 home 的 Chromium userData。

## 同一个 home 只运行一个实例

用 Electron 的单实例锁，按上面每个 home 一份的 userData 区分。第二个实例拿不到锁就写一行 error 日志、退出码 1，不动 `runtime.json`（锁在写它之前检查）；正在运行的那个收到通知，把已打开的窗口调到前面——第二次双击看到的是原来的窗口。

不在 home 里自己写锁文件：那要靠 pid 判断写锁的进程还在不在，而且判断发生在启动路径上；Electron 的锁在进程结束时由操作系统释放，崩溃、被强制结束都不会留下过期的锁。锁按 home 区分、不锁整个应用，因为不同 home 同时运行是日常用法（[同一 home 只允许一个实例](/trajectory/2026-09-12-one-home-one-instance)）。

## 怎么验证

这几段都在 `main.ts` 模块求值时执行，没有单元测试，只能实机验证：用同一个 `GWB_HOME` 启动两次，第二次退出码是 1、`gwb.log` 里有「已有实例在跑，本实例退出」一行、`runtime.json` 里仍是第一个实例的 pid；用一个新名字启动，home 目录里出现最小的 `package.json` 与 `cordis.yml`。
