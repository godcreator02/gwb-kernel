**本页回答**：内核应用有哪些功能；插件、页面、启动器和外部工具经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归别的模块。包名 `@godcreator/gwb-kernel-desktop`，源码目录 `apps/desktop/src`，入口文件 `main.ts`。

内核应用是内核本身：Electron 主进程里的一个 cordis 实例加一个窗口。它发布成 npm 包，和插件一样装在每个 home 的 `node_modules` 里，由安装包里的启动器加载（[启动器加载内核](/docs/seams/launcher)）；在本仓 `pnpm start` 时由 Electron 直接运行。页面入口 `index.html` 与注入 `window.gwb` 的 `preload.cjs` 也在这个包里，在页面里运行，接缝图上画在「页面」框里。一次启动依次做什么、哪几处顺序不能换，见[启动与退出](/docs/desktop/boot)。

## 功能

- **选定 home**：环境变量 `GWB_HOME` 只写名字时，home 是 `%APPDATA%\gwb-kernel\homes\<名字>`；带路径分隔符时就是那个目录；不设时是 `default`。目录不存在就创建，路径统一成磁盘上的真实路径（大小写、junction、斜杠写法不同的同一个目录得到同一个字符串）。home 里缺 `package.json` 或 `cordis.yml` 时启动失败，报错写明缺哪个、home 在哪：这两个文件由安装步骤（`INSTALL.md`）或 `devkit.home.new` 准备，内核不补（[home 布局与条目树](/docs/seams/home)）
- **同一个 home 只运行一个实例**：Chromium 的 userData 放在 `<home>/electron`，Electron 的单实例锁按它区分。同一个 home 再启动一次，新实例写一行 error、退出码 1，`runtime.json` 不动，已在运行的实例把窗口调到前面；不同的 home 可以同时运行。锁由操作系统在进程结束时释放，崩溃不留下过期的锁（[同一 home 只允许一个实例](/trajectory/2026-09-12-one-home-one-instance)）
- **加载插件**：创建 cordis 实例，提供 `gwbKernel`，用 loader 与 include 按 `cordis.yml` 加载插件；插件按包名 import 时，按 home 里的真实路径找到文件，换了版本的包重新加载时拿到新版本（[插件加载](/docs/seams/loading)、[内核服务](/docs/seams/kernel)）
- **窗口与外壳**：打开唯一的窗口，加载页面入口，把页面交给调用 `setShell` 的外壳插件（[外壳接管](/docs/seams/shell)）
- **页面边界**：主框架只可能是内核包里的 `index.html`，跳到别的地址、重定向一律拒绝，只放行整页重新加载；`window.open` 与 `target="_blank"` 从不打开新窗口，`http:`、`https:` 地址交给系统默认浏览器；`gwb:command` 只接收顶层框架的调用。页面能调用整条命令总线，这是内核保证的唯一边界（[IPC 通道](/docs/seams/ipc#页面边界)）
- **转交命令、推送事件**：页面发来的命令交给命令插件提供的 `ctx.gwbCommands`（[命令转交](/docs/seams/commands)），插件发出的事件推给页面（[IPC 通道](/docs/seams/ipc)）
- **页面上的 react**：构建时把 react 打进 `dist/react/`，页面入口里写死的 importmap 把 react 的四个包名指向这几个文件（[页面上的 react](/docs/seams/page-react)；怎么打包见[开发](/docs/develop#内核包怎么打包-react)）
- **日志**：插件、内核、页面 console 的日志汇成一条 cordis 日志流，每一行同时写 stderr 和 home 里的 `gwb.log`；`gwb.log` 写到 128 MB 改名为 `gwb.log.1`（只留这一份旧的）再开一份新的；`gwb.log` 启动时打不开就启动失败，运行中写不进、轮转失败都只告警一句，内核照常运行（[日志](/docs/seams/log)）
- **记下这次运行**：每次启动把 pid、启动时刻、版本、调试端口写进 home 里的 `runtime.json`；写不进、调试端口给的不是 1–65535 的整数时启动失败（[runtime.json](/docs/seams/runtime)）
- **出错与退出**：启动失败时弹错误框、退出码 1；插件抛出的未捕获异常只记进日志，工作台不退出；所有窗口关闭时卸载整棵插件树，最多等 5 秒（[启动与退出](/docs/desktop/boot)）

### 只读状态页

没有插件调用 `setShell`，或外壳启动失败（import 失败、默认导出不是函数）时，页面入口画一页纯文本、没有按钮的只读状态页：第一行说明是哪种情况，然后是 home 的路径、每个条目一行（id、包名、加载到哪一步：等待中的写还缺哪个服务，失败的写错误的第一行）、最近 20 行 error 与 warn 日志。条目状态变化、每来一行 error、loader 加载完，内核都重新推送整份状态，200 毫秒内的多次合并成一次（warn 不触发推送）；页面订阅时也请求一次当前值，比插件晚加载完也不会错过。

## 接口

每条接缝交换什么、各模块保证什么，写在接缝页；本节只列内核应用提供了哪些接口、各属于哪条接缝。包根只导出类型、不给插件任何运行时的值：它实现的接口的类型都在 `src/api.ts`，插件与页面代码从包根 `import type`（[包根导出的接口类型](/docs/desktop/api)）。

| 接口 | 给谁、做什么 | 接缝 |
| --- | --- | --- |
| `cordis.yml` 的条目与按 home 解析包名 | 插件：条目点名的包按 home 里的真实路径 import，插件导出 `apply` 或 `Service` 类 | [1 插件加载](/docs/seams/loading) |
| 服务 `ctx.gwbKernel` | 插件：`dataDir`、`version`、`emit`、`setShell`，早于任何插件提供、永不撤销；类型 `GwbKernelApi` | [2 内核服务](/docs/seams/kernel) |
| `window.gwb` 与 `gwb:command`、`gwb:event`、`gwb:shell`、`gwb:hello` 四个通道 | 页面：调命令、收事件、知道外壳是谁；类型 `GwbWindowApi` | [3 IPC 通道](/docs/seams/ipc) |
| 外壳模块的默认导出 | 外壳插件：页面入口 import 外壳的地址，拿页面的 `#root` 调用它的默认导出；类型 `ShellBoot` | [4 外壳接管](/docs/seams/shell) |
| 页面入口里的 importmap | 页面上的代码：react 的四个包名 → 内核包 `dist/react/` 里的文件 | [5 页面上的 react](/docs/seams/page-react) |
| home 的文件布局与条目树 | 插件管理：启动时 home 里要已有 `package.json` 与 `cordis.yml`，缺了启动失败、内核不补；loader 根层只有一条承载 `cordis.yml` 的 include 条目 `home` | [6 home 布局与条目树](/docs/seams/home) |
| `runtime.json` | devkit、安装工作台的 agent：每次启动整份重写 pid、启动时刻、版本，开了调试端口时还有端口 | [7 runtime.json](/docs/seams/runtime) |
| cordis 日志流与 `gwb.log` | 插件用 `ctx.logger` 写日志、注册 exporter 收全部日志；人和 agent 读 `gwb.log`，一行是「时间 级别 名字 正文」 | [8 日志](/docs/seams/log) |
| 内核包清单的 `engines.electron` 与 `main` | 启动器：Electron 版本在范围里才 import `main` 指向的入口 `dist/main.js` | [9 启动器加载内核](/docs/seams/launcher) |
| 对 `ctx.gwbCommands.run(命令名, 参数, { via: 'ui' })` 的调用 | 命令插件：内核声明这个可选服务的形状、自己不提供；命令名不是字符串、没有这个服务时内核自己回失败回执 | [10 命令转交](/docs/seams/commands) |

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| electron 的 `app`、`BrowserWindow`、`ipcMain`、`dialog`、`Menu`、`shell` | 单实例锁与每个 home 一份的 userData、窗口、IPC、启动失败时的错误框、把页面 `window.open` 的网页地址交给系统默认浏览器 | 内核就是这个 Electron 应用，没有它无法启动；Electron 由安装包提供，版本要在 `engines.electron` 的范围里，启动器才加载内核 |
| cordis 的 `Context` 与 logger | cordis 实例、提供 `gwbKernel`、日志流、只读状态页的错误行 | 无法启动；`cordis` 写在 peer 里，由 home 根上唯一的那一份满足，插件用的也是它（[home 布局与条目树](/docs/seams/home)） |
| `@cordisjs/plugin-loader`、`@cordisjs/plugin-include` | 按条目加载插件、读写 `cordis.yml` | 无法启动；它们是内核包自己的依赖，版本写死在内核包清单的 `dependencies` 里，升级它们是改接缝，内核升 x（[开发](/docs/develop#发版)） |
| 服务 `ctx.gwbCommands`，由命令插件 `@godcreator/gwb-commands` 提供 | 页面发来的命令一律交给它 | 内核照常运行；页面发来的每条命令都回失败回执「没有命令服务」 |
| react 与 react-dom（开发依赖，只在构建时用） | 打进 `dist/react/` 给页面用 | 内核包里缺这几个文件时，页面上的 react 加载失败，外壳无法挂载，页面显示只读状态页 |
| home 目录与文件系统 | 检查 `package.json` 与 `cordis.yml` 在不在、解析包名、写 `gwb.log` 与 `runtime.json` | 目录建不出来、缺这两个文件、`gwb.log` 打不开、`runtime.json` 写不进时都启动失败；运行中 `gwb.log` 写不进只告警一次，恢复之前日志只写 stderr |

## 不做的事

- **不认识任何命令**：页面发来的命令原样交给命令插件，命令由登记它的插件实现
- **不认识 `cordis.yml` 里的插件**：加载哪些插件由 `cordis.yml` 决定；内核认识的服务名只有自己提供的 `gwbKernel` 和转交命令时要找的 `gwbCommands`
- **不写 home 的包与条目**：`package.json` 与 `cordis.yml` 缺了也不补，不做 `cordis.yml` 的模板与自动修复；装卸包、增删条目只由插件管理 `@godcreator/gwb-plugin-manager` 做，内核不带 pnpm
- **不带插件**：命令插件、插件管理和别的插件一样写在 `cordis.yml` 里、装在 home 里；新 home 的插件由创建它的一方装（[关键设计](/docs/design#内核仓只放内核)）
- **不渲染界面**：只读状态页之外，页面显示什么全由外壳插件决定；内核不认识窗格，不替插件做菜单（只在启动时去掉 Electron 默认的那套），需要菜单的插件在 Electron ready 之后自己调 `Menu.setApplicationMenu`
- **不诊断插件故障**：只读状态页只列内核已有的数据，不分析失败原因、不重试、不放按钮；这些要认识具体的插件，归外壳和插件管理的窗格（[外壳未就位时的阶段页](/trajectory/2026-09-08-stage-page)）
- **不经手插件之间的交互**：服务、命令、契约版本都在插件之间，由 cordis 与命令插件连接
- **不显示、不查询日志**：内核只把日志写到 stderr 与 `gwb.log`；在界面上看日志归日志插件，它注册自己的 exporter
- **不提供设置、数据、说明书、MCP 入口**：这些都是 `cordis.yml` 里的插件
- **不确认 `runtime.json` 里的进程还活着**：退出时不删这份文件，读它的 devkit 与安装工作台的 agent 自己确认 pid 还在
- **不比对插件兼容哪个内核**：插件 peer 里内核包的范围内核不读，由插件管理比对
- **不装自己**：内核包由创建 home 的一方装进 home，升级由插件管理的 `plugin-manager.update {"specs":{"@godcreator/gwb-kernel-desktop":"<版本>"}}` 装、重启后生效
