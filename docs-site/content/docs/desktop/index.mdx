**本页回答**：内核应用有哪些功能；插件、页面和外部工具经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归别的模块。包名 `@godcreator/gwb-kernel-desktop`，源码目录 `apps/desktop/src`，入口文件 `main.ts`。

内核应用是内核本身：Electron 主进程里的一个 cordis 实例加一个窗口。页面入口是同目录的 `index.html`，页面上的 `window.gwb` 由同目录的 `preload.cjs` 注入。内核应用在[接缝图](/docs#接缝图)上是「内核应用」那个框，框边上的编号连线是它参与的接缝；`preload.cjs` 与 `index.html` 画在左边「页面」框里。

## 功能

- 按环境变量 `GWB_HOME` 选定 home，缺 `package.json`、`cordis.yml` 时补上能启动的最小形态；同一个 home 只运行一个实例，再启动一次只把已打开的窗口调到前面——[home 的准备与单实例锁](/docs/desktop/home)
- 创建 cordis 实例，按 `cordis.yml` 加载插件；退出时卸载整棵插件树，最多等 5 秒——[启动与退出](/docs/desktop/boot)
- 插件按包名 import 时，按 home 里的真实路径找到文件；换了版本的包重新加载时拿到新版本——[插件加载](/docs/seams/loading)
- 打开唯一的窗口，把页面交给调用 `setShell` 的外壳插件；没有外壳或外壳启动失败时，页面显示各条目加载到哪一步和最近的错误行——[只读状态页](/docs/desktop/status-page)
- 把 home 里各包声明的 `gwb.shared` 拼成页面的 importmap，外壳在页面上写 `import 'react'` 就能找到文件——[页面上的包名](/docs/seams/shared)
- 把页面发来的命令转交命令总线，把插件发出的事件推给页面——[IPC 通道](/docs/seams/ipc)
- 插件、内核、页面 console 的日志汇成一条，写到 stderr 和 home 里的 `gwb.log`；文件上限 128 MB、只留一份旧的——[日志文件](/docs/desktop/log-file)
- 每次启动把这次运行的 pid、启动时刻、版本、应用目录、调试端口写进 home 里的 `runtime.json`——[runtime.json](/docs/seams/runtime)
- 启动失败时弹错误框、退出码 1；插件抛出的未捕获异常只记进日志，工作台不退出——[启动与退出](/docs/desktop/boot)

### 启动参数

启动内核的人或程序经这三项控制它，不属于哪条接缝：

| 参数 | 做什么 | 细节在 |
| --- | --- | --- |
| 环境变量 `GWB_HOME` | 用哪个 home：只写名字时是 appData 下 `gwb-kernel/homes/<名字>`，带路径分隔符时就是那个目录；不设时是 `default` | [home 的准备与单实例锁](/docs/desktop/home) |
| 环境变量 `GWB_LOG_LIMIT_MB` | `gwb.log` 的上限，单位 MB；0 表示不轮转 | [日志文件](/docs/desktop/log-file) |
| 命令行开关 `--remote-debugging-port` | Chromium 调试端口；开了就记进 `runtime.json` | [runtime.json](/docs/seams/runtime) |

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| electron 的 `app`、`BrowserWindow`、`ipcMain`、`dialog`、`Menu` | 单实例锁、每个 home 一份的 userData、窗口、IPC、启动失败时的错误框 | 内核就是这个 Electron 应用，没有它无法启动 |
| cordis 的 `Context` 与 logger | cordis 实例、提供 `gwbKernel`、日志流、只读状态页的错误行 | 无法启动 |
| `@cordisjs/plugin-loader`、`@cordisjs/plugin-include` | 按条目加载插件、读 `cordis.yml` | 无法启动；版本写在 `apps/desktop/package.json`，升级它们是改接缝，内核升 x（见[开发](/docs/develop#发版)） |
| 服务 `ctx.gwbCommands`，由 `cordis.yml` 里的命令插件 `@godcreator/gwb-commands` 提供 | 页面发来的命令一律交给它 | 内核照常运行；页面发来的每条命令都回失败回执「没有命令服务」 |
| home 目录与文件系统 | 读包清单、解析包名、写 `gwb.log` 与 `runtime.json` | 目录建不出来时进程直接退出；`runtime.json` 写不进只记一行警告；`gwb.log` 打不开时日志只写 stderr |
| 词汇表包 `@godcreator/gwb-plugin-api` | `GwbKernelApi` 的类型 | 只在编译时用；形状对不上时内核的类型检查失败，运行时没有影响 |

## 不做的事

- **不认识任何命令**：页面发来的命令原样交给命令总线，命令由登记它的插件实现、由命令插件 `@godcreator/gwb-commands` 执行
- **不写 home 的包与条目**：只在缺文件时补 `package.json` 与 `cordis.yml` 的最小形态；装卸包、增删条目只由插件管理 `@godcreator/gwb-plugin-manager` 做
- **不带插件**：命令插件、插件管理和别的插件一样写在 `cordis.yml` 里、装在 home 里；新 home 的插件由创建它的一方装（[关键设计](/docs/design)）
- **不认识 `cordis.yml` 里的插件**：加载哪些插件由 `cordis.yml` 决定；内核认识的服务名只有自己提供的 `gwbKernel` 和转交命令时要找的 `gwbCommands`
- **不渲染界面**：只读状态页之外，页面显示什么全由外壳插件 `gwb-shell` 决定；内核不认识窗格，不替插件做菜单（只在启动时去掉 Electron 默认的那套），需要菜单的插件在 Electron ready 之后自己调 `Menu.setApplicationMenu`
- **不经手插件之间的交互**：服务、命令、契约版本都在插件之间，由 cordis 与命令总线连接
- **不显示、不查询日志**：内核只把日志写到 stderr 与 `gwb.log`；在界面上看日志归日志插件 `gwb-logger`，它注册自己的 exporter
- **不提供设置、数据、说明书、MCP 入口**：这些都是 `cordis.yml` 里的插件
- **不确认 `runtime.json` 里的进程还活着**：退出时不删这份文件，读它的 devkit 与装机的 agent 自己确认 pid 还在
- **不比对插件测过的内核版本**：插件 `package.json` 里的 `gwb.testedKernel` 内核不读，由插件管理比对
