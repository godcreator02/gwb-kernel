**本页回答**：内核应用管哪几件事、刻意不知道什么；它在内存里、页面上、home 里各有什么数据；它对插件、页面、启动器、外部工具提供哪些接口（各属于哪条接缝）；它依赖什么、测试时换成什么；每个测试文件证明什么；源码从哪读起。包名 `@godcreator/gwb-kernel-desktop`，源码在 `apps/desktop/src`。

内核应用是内核本身：Electron 主进程里的一个 cordis 实例加一个窗口。它发布成 npm 包，和插件一样装在每个 home 的 `node_modules` 里，由安装包里的启动器加载（[启动器加载内核](/docs/seams/launcher)）；在本仓 `pnpm start` 时由 Electron 直接运行。页面入口 `index.html` 与注入 `window.gwb` 的 `preload.cjs` 也在这个包里，在页面里运行。一次启动依次做什么、哪几处顺序不能换，见[启动与退出](/docs/desktop/boot)；包根导出的接口类型见[包根导出的接口类型](/docs/desktop/api)。

## 管什么

- **选定 home**：按 `GWB_HOME` 算出 home 目录（规则见[启动器加载内核](/docs/seams/launcher)），不存在就创建，路径统一成磁盘上的真实路径；缺 `package.json` 或 `cordis.yml` 时补一份最小的（[home 布局与条目树](/docs/seams/home)）
- **同一个 home 只运行一个实例**：Chromium 的 userData 放在 `<home>/electron`，Electron 的单实例锁按它区分。同一个 home 再启动一次，新实例写一行 error、退出码 1，已在运行的实例把窗口调到前面；锁由操作系统在进程结束时释放，崩溃不留下过期的锁（[同一 home 只允许一个实例](/trajectory/2026-09-12-one-home-one-instance)）
- **加载插件**：创建 cordis 实例，提供 `gwbKernel`，用 loader 与 include 按 `cordis.yml` 加载插件，包名按 home 解析（[插件加载](/docs/seams/loading)、[内核服务](/docs/seams/kernel)）
- **窗口与页面**：打开唯一的窗口，加载页面入口；把页面交给调用 `setShell` 的外壳，没有外壳时显示只读状态页（[外壳接管](/docs/seams/shell)）；守住页面边界，页面发来的命令转交给命令插件，插件发出的事件推给页面（[IPC 通道](/docs/seams/ipc)、[命令转交](/docs/seams/commands)）
- **页面上的 react**：构建时把 react 打进 `dist/react/`，页面入口里写死的 importmap 指向它们（[页面上的 react](/docs/seams/page-react)）
- **日志**：插件、内核、页面 console 的日志汇成一条 cordis 日志流，写 stderr 与 `gwb.log`，到上限轮转（[日志](/docs/seams/log)）
- **记下这次运行**：每次启动把 pid、启动时刻、版本、调试端口写进 `runtime.json`（[runtime.json](/docs/seams/runtime)）
- **出错与退出**：启动失败弹错误框、退出码 1；插件的未捕获异常只记日志；所有窗口关闭时卸载整棵插件树，最多等 5 秒（[启动与退出](/docs/desktop/boot)）

## 不知道什么

- **不认识 `cordis.yml` 里的插件与命令**：认识的服务名只有自己提供的 `gwbKernel` 和转交命令时要找的 `gwbCommands`；命令名原样转交，一条命令都不登记。换掉任何一个插件（包括外壳、命令插件）都不用改内核，只要新插件提供同名的服务、接口不变
- **不读插件包清单里的任何字段**：插件 peer 里的内核包范围由插件管理比对，页面的 importmap 写死在页面入口里
- **不知道插件管理存在**：不装包、不带 pnpm，除了缺文件时补最小的 `package.json` 与 `cordis.yml`，不写 home 的包与条目
- **不认识窗格、不渲染界面**：只读状态页之外，页面显示什么全由外壳决定；只在启动时去掉 Electron 默认的菜单，需要菜单的插件在 ready 之后自己调 `Menu.setApplicationMenu`
- **不诊断插件故障**：只读状态页只列内核已有的数据，不分析原因、不重试、没有按钮（[外壳未就位时的阶段页](/trajectory/2026-09-08-stage-page)）
- **不显示、不查询日志**：在界面上看日志归日志插件，它注册自己的 exporter
- **不知道自己是怎么被启动的**：经启动器加载和在本仓 `pnpm start` 做法相同，安装包的版本号拿不到
- **不知道谁读 `runtime.json`**，也不确认那里记的进程还活着
- **不提供设置、数据、说明书、MCP 入口**：这些都是 `cordis.yml` 里的插件

### 只读状态页

没有插件调用 `setShell`，或外壳启动失败（import 失败、默认导出不是函数）时，页面入口画一页纯文本、没有按钮的只读状态页：第一行说明是哪种情况，然后是 home 的路径、每个条目一行（id、包名、加载到哪一步：等待中的写还缺哪个服务，失败的写错误的第一行）、最近 20 行 error 与 warn 日志。条目状态变化、每来一行 error、loader 加载完，内核都重新推送整份状态，200 毫秒内的多次合并成一次；页面订阅时也请求一次当前值，比插件晚加载完也不会错过。

### 页面上的 react 怎么打包

构建的最后一步 `scripts/build-react.ts` 用 esbuild 把 react 与 react-dom 打成浏览器能直接 import 的 ESM，写进 `dist/react/` 的四个文件，页面入口里写死的 importmap 指向它们。react 与 react-dom 是内核包的开发依赖，升级 react 就是发一版内核。

{/* ref file="../apps/desktop/scripts/build-react.ts" lines="14-43" */}

- **为什么要打包**：react 19 的清单 `exports` 只有 `react-server` 与 `default` 两个条件，`default` 指向 CJS 的 `index.js`，浏览器不能直接 import
- **为什么用 esbuild**：rolldown 在 browser 平台对「CJS 里 require 一个外置的包」保留 `require`，浏览器里没有 `require`，产物一加载就报错；esbuild 会把它提升成顶层 `import`
- **react-dom 的两个文件把 `react` 外置**：四个包名共用同一个 react 实例
- **替换 `__require` 探针**：react-dom 在工厂函数内部调 `require('react')`，esbuild 提不到顶层，产物里留一个 `__require` 探针，在浏览器里一运行就报错。构建脚本在这两个文件头加一句 `import * as __gwb_react from "react"`，再把探针换成只认 `react` 的同步解析器，返回 CJS 的 `module.exports` 原对象（react-dom 要用 React 的内部成员）；产物里有 `__require` 却认不出它的形状时构建失败
- **入口文件逐个列出具名导出**：`src/react/` 下四个入口各自 import 对应的包，再一个一个 `export const`，因为 esbuild 从 react 的 CJS 转发链上推不出具名成员，直接打只有一个 `default`。名单对齐 `@types/react` 19 的稳定 API，react 加了新 API 就补一行；少一个的话，用到它的窗格加载时报「does not provide an export named …」、整个窗格空白，构建与类型检查都发现不了

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| electron 的 `app`、`BrowserWindow`、`ipcMain`、`dialog`、`Menu`、`shell` | 单实例锁与 userData、窗口、IPC、启动失败的错误框、把网页地址交给系统浏览器 | 安装包带的 Electron，版本要在 `engines.electron` 的范围里 | `main.test.ts` 里的假 electron |
| cordis 的 `Context` 与 logger | cordis 实例、提供 `gwbKernel`、日志流、只读状态页的错误行 | home 根上唯一的那份 `cordis`（内核包 peer 里写死的版本） | 真的 cordis（本仓开发依赖，同一个版本） |
| `@cordisjs/plugin-loader`、`@cordisjs/plugin-include` | 按条目加载插件、读写 `cordis.yml` | 内核包自己的依赖，版本写死 | 真的 loader 与 include |
| 服务 `ctx.gwbCommands` | 转交页面发来的命令 | 命令插件 `@godcreator/gwb-commands` | `main.test.ts` 里从 `cordis.yml` 加载的测试插件；不装时测「没有命令服务」 |
| 文件系统与 home 目录 | 补最小文件、解析包名、写 `gwb.log` 与 `runtime.json` | 真的文件系统 | 临时目录 |
| react、react-dom（只在构建时） | 打进 `dist/react/` 给页面用 | 开发依赖里写死的版本 | `react-bundles.test.ts` 读真实产物 |

缺了会怎样：electron、cordis、loader、include 任何一个缺了都起不来；`ctx.gwbCommands` 缺了内核照常运行，页面发来的每条命令都回「没有命令服务」；`dist/react/` 里缺文件时外壳加载不了，页面显示只读状态页；home 目录建不出来时启动失败，`runtime.json` 写不进只记一行 warn，`gwb.log` 打不开时日志只写 stderr、一分钟后再试。
