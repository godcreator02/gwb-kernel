## 内核与安装包

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| 内核 | 这个仓的 Electron 应用本体：只负责主进程插件启动所需的基础能力和页面模块加载前的解析环境，其余功能全部由插件实现 | [首页](/docs) |
| 内核应用 / 内核包 | 内核发布成的 npm 包，和插件一样装在每个 home 里；包根的运行时入口就是内核主进程，类型入口只有接口类型 | [内核应用](/docs/desktop) |
| 安装包 | 启动器加 Electron 打成的安装程序；不带内核包、插件，也不带 pnpm | [安装包](/docs/installer) |
| 启动器 | 安装包里唯一的代码：选定 home，确认 home 里的内核包能在自带的 Electron 上运行，再加载它 | [启动器](/docs/installer/launcher) |
| 准入判据 | 往内核里加东西要同时满足的两条：属于主进程插件启动所需的基础能力或页面模块加载前的解析环境，并且此刻确实需要 | [首页](/docs) |
| 接缝 | 两个模块之间交换东西的地方：交换的东西不变，换掉其中一个模块，另一个不用改 | [首页](/docs) |
| 升 x / 升 y | 内核包版本号 `0.x.y` 里升哪一位：改了接缝上已有的东西升 x，其余升 y；插件在 peer 里写的范围只包含同一个 x | [开发](/docs/develop) |

## home 与插件

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| home | 装内核包与插件、存放数据的目录，也是一个普通的 npm 项目根；每个 home 有自己的内核、插件、端口和数据，互不影响 | [home 与插件加载](/docs/desktop/home) |
| default | 日常用的那个 home；没有指定 home 时用的就是它 | [home 与插件加载](/docs/desktop/home) |
| 隔离 home | 为了开发或验证单独建的 home，和 default 分开；验证改动只在隔离 home 里做 | [开发](/docs/develop) |
| cordis | 主进程里加载插件的框架：插件的上下文、服务的提供与注入、日志流、卸载时的自动清理都来自它；一个 home 里只有一份，内核与插件共用 | [首页](/docs) |
| loader | cordis 官方的插件加载器：维护条目树，按条目把插件包加载进来；内核带着它，版本写死 | [home 与插件加载](/docs/desktop/home) |
| include | cordis 官方的一种条目：读一份条目清单文件，把里面的条目加载成自己的子条目；内核用它读 home 里的条目清单 | [home 与插件加载](/docs/desktop/home) |
| 插件 | 一个普通的 npm 包，装在 home 里、在条目清单里有一条条目，由 cordis 加载，运行在 Electron 主进程里 | [home 与插件加载](/docs/desktop/home) |
| 条目 | 条目清单里的一条：一个手写的标识、一个要加载的包名、可选的配置；同一个包可以配成几条，各自独立加载 | [home 与插件加载](/docs/desktop/home) |
| 条目树 | loader 在内存里维护的全部条目及其增删改接口；运行中改条目只经它，它同时写回文件、当场加载或卸载 | [home 与插件加载](/docs/desktop/home) |
| fiber | cordis 为每个加载的插件建的运行单元，记录它加载到哪一步：等待依赖、加载中、运行中、失败、已卸载 | [home 与插件加载](/docs/desktop/home) |
| 加载成功 | 条目对应的 fiber 进入运行中状态；有 fiber 不等于加载成功 | [home 与插件加载](/docs/desktop/home) |
| 服务 | 插件经 cordis 提供、别的插件写进依赖后从上下文取用的对象；内核自己只提供一个，而且不用写进依赖 | [包根导出的接口类型](/docs/desktop/api) |
| 包名 import | 直接写包名、不带相对路径的 import（英文叫 bare specifier）；主进程里内核按 home 解析它，页面上靠 importmap 查表 | [home 与插件加载](/docs/desktop/home) |
| 插件管理 | 唯一写 home 里的包与条目的插件：装卸、升级包，增删条目，比对插件兼不兼容当前内核；不在内核仓里 | [首页](/docs) |
| 命令插件 | 提供命令总线的插件；页面上的命令经请求通道交给它，内核不认识命令 | [页面与主进程之间的通道](/docs/desktop/ipc) |
| 基础插件仓 | 命令插件、数据、设置、说明书、日志、MCP 入口等基础插件的源码仓，不在内核仓里 | [首页](/docs) |

## 日志与运行记录

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| gwb.log | 内核写在 home 里的唯一日志文件：插件、内核、页面的日志汇成一条流，一行一条记录；读日志的插件直接读这个文件 | [日志](/docs/desktop/log) |
| 挂载日志 | 内核按条目写的日志：每个插件条目加载成功、加载失败各写一行，条目树安定之后写一行汇总，列出在等的、失败的、没导入成功的 | [日志](/docs/desktop/log) |
| runtime.json | 内核每次启动写进 home 的运行记录：进程号、启动时刻、版本、调试端口；给工作台进程之外的程序找运行中的工作台，文件在不等于进程在 | [home 与插件加载](/docs/desktop/home) |

## 页面

| 术语 | 定义 | 在哪讲 |
| --- | --- | --- |
| 页面入口 | 内核包里的那个 html 文件：窗口加载的就是它；它把根元素交给外壳，没有外壳时画只读状态页 | [页面入口](/docs/desktop/page) |
| 只读状态页 | 没有外壳、或外壳启动失败时页面显示的内容：home、各条目加载到哪一步、最近的错误与警告，纯文本、没有按钮 | [页面入口](/docs/desktop/page) |
| 外壳 | 调用了设置外壳那个方法的插件：页面的根元素交给它的页面模块渲染；后调用的替换先调用的 | [页面入口](/docs/desktop/page) |
| preload | Electron 在页面脚本之前运行的脚本；内核用它在页面上注入唯一的一个对象，并接好页面与主进程之间的通道 | [页面与主进程之间的通道](/docs/desktop/ipc) |
| 请求通道 | 页面调用主进程插件的通用通道：插件按通道名登记处理器，内核只传载荷与结果，不解释业务 | [页面与主进程之间的通道](/docs/desktop/ipc) |
| 页面边界 | 内核在页面上保证的唯一一条边界：主框架只能是页面入口，新窗口一律不开，请求只收顶层框架发来的 | [页面与主进程之间的通道](/docs/desktop/ipc) |
| 浏览器模块登记 | 插件把页面上要用的包名登记到本地模块文件的机制；页面在动态 import 之前先把登记写成 importmap | [页面入口](/docs/desktop/page) |
| importmap | 页面上的一张表：包名 → 文件地址，浏览器里的包名 import 靠它找到文件；写进页面之后不能撤销或改绑，只能整页重载 | [页面入口](/docs/desktop/page) |
| 接口类型 | 内核给插件与页面代码的全部接口的类型，从内核包的包根导出，只有类型、没有运行时代码 | [包根导出的接口类型](/docs/desktop/api) |
