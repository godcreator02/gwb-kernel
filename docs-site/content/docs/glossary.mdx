# 术语表

**本页回答**：文档里那个词在这个仓里指什么。只收这个仓自己的词、在这里有特定含义的通用词和外来框架词，通用编程术语不收。定义只写概念，具体的名字、路径在所指的那一页。

| 词 | 是什么 |
| --- | --- |
| **内核** | 这个仓的 Electron 应用本体：只做第一个插件运行之前必须完成的事，其余功能全部由插件实现。见[关键设计](/docs/design) |
| **内核包** | 内核应用发布成的 npm 包，和插件一样装在每个 home 里；它的包根只导出接口类型。见[内核应用](/docs/desktop) |
| **启动器** | 安装包里唯一的代码：选定 home，确认 home 里的内核包能在自带的 Electron 上运行，再加载它。见[安装包与启动器](/docs/installer) |
| **home** | 内核包与插件安装、存放数据的目录，一个普通的 npm 项目根；每个 home 有自己的内核、插件、端口和数据，互不影响。见[关键设计](/docs/design#每个-home-相互独立) |
| **default** | 日常使用的那个 home，环境变量没指定 home 时用的就是它 |
| **隔离 home** | 为了开发或验证单独创建的 home，和 default 分开；验证改动只在隔离 home 里做。见[开发](/docs/develop#在隔离-home-里验证) |
| **插件** | 一个普通的 npm 包，装在 home 里、在条目表里有一条条目，由 cordis 加载，运行在 Electron 主进程里。见[插件加载](/docs/seams/loading) |
| **条目** | 插件清单文件里的一条配置（cordis 的 loader 里叫 entry）：一个手写的标识、一个要加载的包名、可选的配置。见[插件加载](/docs/seams/loading) |
| **条目树** | cordis 的 loader 在内存里维护的全部条目及其增删改接口；运行中改条目只经它，它同时写回文件、当场加载或卸载。见 [home 布局与条目树](/docs/seams/home) |
| **fiber** | cordis 为每个加载的插件建的运行单元，记录它的状态（等待依赖、加载中、运行中、失败等） |
| **加载成功** | 条目对应的 fiber 进入 `ACTIVE` 状态；有 fiber 不等于加载成功。见[插件加载](/docs/seams/loading) |
| **服务** | 插件通过 cordis 提供、别的插件在 `inject` 里写上名字再从上下文取用的对象；内核只提供一个，也只找一个别人提供的 |
| **接缝** | 两个模块之间交换东西的地方：只要交换的东西不变，换掉其中一个模块，另一个不用改。内核仓有十条，每条一页。见[接缝图](/docs#接缝图) |
| **接口类型** | 内核给插件和页面代码的全部接口的类型，从内核包的包根导出，只有类型、没有运行时代码。见[包根导出的接口类型](/docs/desktop/api) |
| **外壳** | 调用了设置外壳那个方法的插件，页面的根元素交给它在页面上运行的模块来渲染；后来的替换先来的。见[外壳接管](/docs/seams/shell) |
| **页面入口** | 内核包里的那个 html 文件：窗口加载的就是它，它把根元素交给外壳，没有外壳时画只读状态页 |
| **只读状态页** | 没有外壳、或外壳启动失败时页面显示的内容：各条目的加载状态和最近的错误日志，纯文本、没有按钮。见[内核应用](/docs/desktop#只读状态页) |
| **页面边界** | 内核在页面这一侧守的唯一一条线：主框架只能是页面入口，新窗口一律不开，命令只收顶层框架发来的。见 [IPC 通道](/docs/seams/ipc#页面边界) |
| **命令插件** | 提供命令总线服务的插件：页面、MCP 入口和其他插件都经它按名字调用命令。内核只把页面发来的命令转交给它。见[命令转交](/docs/seams/commands) |
| **插件管理** | 唯一写 home 的插件：装卸、升级包，增删条目，比对插件兼不兼容当前内核；在生命周期插件仓 `gwb-lifecycle-plugins`。见 [home 布局与条目树](/docs/seams/home) |
| **包名 import** | 直接写包名、不带相对路径的 import（英文叫 bare specifier）。主进程里内核按 home 解析它，页面上靠 importmap 查表。见[关键设计](/docs/design#包名一律按-home-解析) |
| **importmap** | 页面上的一张表：包名 → 文件地址，浏览器里的包名 import 靠它找到文件。内核的页面入口里写死了一张，只有 react 的四个包名。见[页面上的 react](/docs/seams/page-react) |
| **准入判据** | 往内核里加东西要满足的条件：第一个插件运行之前必须完成，并且此刻确实需要。见[关键设计](/docs/design#准入判据) |
| **升 x、升 y** | 内核包版本号 `0.x.y` 里升哪一位：改了接缝上已有的东西升 x，其余升 y。插件在 peer 里写的范围只包含同一个 x。见[开发](/docs/develop#发版) |
| **基础插件仓** | 命令插件、数据、设置、说明书、日志、MCP 入口等基础插件的源码仓，不在内核仓里 |
