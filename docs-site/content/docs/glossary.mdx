# 术语表

**本页回答**：文档里那个词在这个仓里指什么。只收这个仓自己的词和在这里有特定含义的词，通用编程术语不收。

| 词 | 是什么 |
| --- | --- |
| **内核** | 这个仓的 Electron 应用本体：只做第一个插件运行之前必须完成的事，其余功能全部由 `cordis.yml` 里的插件实现，命令插件与插件管理也是。见[关键设计](/docs/design) |
| **内核包** | 内核应用发布成的 npm 包 `@godcreator/gwb-kernel-desktop`，和插件一样装在每个 home 的 `node_modules` 里。见[关键设计](/docs/design#内核和插件一样装在-home-里) |
| **启动器** | 安装包里唯一的代码 `apps/launcher`：选定 home，确认 home 里的内核包能在这个 Electron 上运行，再加载它。见[启动器加载内核](/docs/seams/launcher) |
| **插件** | 一个普通的 npm 包，安装在 home 里、写在 `cordis.yml` 里，由 cordis 加载，运行在 Electron 主进程里。见[插件加载](/docs/seams/loading) |
| **接缝** | 两个模块之间的连接处：只要接口不变，换掉其中一个模块，另一个不用改。内核仓有十条，每条一页，写清连接的模块、接口、各模块保证什么、谁不负责什么、由什么测试保护。见[接缝图](/docs#接缝图) |
| **home** | 内核包与插件安装、存放数据的目录，一个普通的 npm 项目根；每个 home 有自己的内核、插件、端口和数据，互不影响。见[关键设计](/docs/design#每个-home-相互独立) |
| **隔离 home** | 为了开发或验证单独创建的 home，和日常使用的 `default` 分开 |
| **条目** | `cordis.yml` 里的一条配置（loader 里叫 entry）：`id` 是它的标识，手写；`name` 是要加载的包名。见[插件加载](/docs/seams/loading) |
| **加载成功** | 条目对应的 fiber 进入 `ACTIVE` 状态；有 fiber 不等于加载成功。见[插件加载](/docs/seams/loading) |
| **fiber** | cordis 为每个加载的插件建的运行单元，记录它的状态（等待依赖、运行中、失败等） |
| **包名 import** | 直接写包名、不带相对路径的 import（英文叫 bare specifier），比如 `import { Service } from 'cordis'`。运行时要靠 Node 去 `node_modules` 里找，或靠页面的 importmap 查表。见[关键设计](/docs/design#包名一律按-home-解析) |
| **构建产物** | 包构建后发布出去的 `dist/` 里的文件，也就是运行时真正加载的代码 |
| **importmap** | 页面上的一张表：包名 → 文件地址。浏览器里的包名 import 靠它找到文件。见[页面上的包名](/docs/seams/shared) |
| **`gwb.shared`** | 内核包清单里的一个字段：页面的 importmap 里有哪些包名、各指向内核包里的哪个文件，现在是 react 的四个。只有内核包的这个字段算数，别的包写了内核不读。见[页面上的包名](/docs/seams/shared) |
| **外壳（shell）** | 调用了 `setShell` 的那个插件，页面的 `#root` 交给它的默认导出来渲染。见[外壳接管](/docs/seams/shell) |
| **只读状态页** | 没有外壳、或外壳启动失败时页面显示的内容：各条目的加载状态和最近的错误日志，纯文本、没有按钮。见[内核应用](/docs/desktop)、[外壳接管](/docs/seams/shell) |
| **命令插件（命令总线）** | 基础插件仓的 `@godcreator/gwb-commands`，提供 `gwbCommands` 服务，类型也由它导出；页面、MCP 入口和其他插件都经它按名字调用命令。内核只把页面发来的命令转交给它，见[命令转交](/docs/seams/commands) |
| **服务** | 插件通过 cordis 提供、别的插件在 `inject` 里写上名字再从 `ctx` 上读的对象。提供有两种写法：继承 cordis 的 `Service` 类，或 `ctx.provide` |
| **接口类型** | 内核给插件和页面代码的全部接口的类型，从内核包的包根导出，只有类型、没有运行时代码；插件写 `import type`。见[包根导出的接口类型](/docs/desktop/api) |
| **准入判据** | 往内核里加东西要满足的条件：第一个插件运行之前必须完成，并且此刻确实需要。见[关键设计](/docs/design#准入判据) |
| **基础插件仓** | `gwb-base-plugins`：命令插件、数据、设置、说明书、日志、MCP 入口等基础插件的源码仓，不在内核仓里；这些插件和别的插件一样装在 home 里。插件管理不在这里，在 devkit 仓 `gwb-devkit` |
