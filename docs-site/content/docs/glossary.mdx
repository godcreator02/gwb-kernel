# 术语表

**本页回答**：文档里那个词在这个仓里指什么。只收这个仓自己的词和在这里有特定含义的词，通用编程术语不收。

| 词 | 是什么 |
| --- | --- |
| **内核** | 这个仓的 Electron 应用本体：只做第一个插件运行之前必须完成的事，外加内置的命令总线与插件管理，其余功能全部由 `cordis.yml` 里的插件实现。见[关键设计](/docs/design) |
| **插件** | 一个普通的 npm 包，安装在 home 里，由 cordis 加载，运行在 Electron 主进程里。见[插件加载](/docs/seams/loading) |
| **内置插件** | 命令插件与插件管理：代码按插件的写法写，但构建进内核、由内核作为 loader 根层的条目在 `cordis.yml` 之前加载，不在 `cordis.yml` 里，随内核升级。见[关键设计](/docs/design#命令插件与插件管理内置在内核里) |
| **接缝** | 不改这里的代码就能换掉一边实现的位置。一条接缝回答四件事：两侧各是谁、交换什么、各保证什么、在哪里换。内核仓有十二条，每条一页。见[接缝图](/docs#接缝图) |
| **home** | 插件安装和存放数据的目录，一个普通的 npm 项目根；每个 home 有自己的插件、端口和数据，互不影响。见[关键设计](/docs/design#一个-home-是一个独立的世界) |
| **隔离 home** | 为了开发或验证单独创建的 home，和日常使用的 `default` 分开 |
| **条目** | `cordis.yml` 里的一条配置（loader 里叫 entry）：`id` 是它的身份，手写；`name` 是要加载的包名。见[插件加载](/docs/seams/loading) |
| **加载成功** | 条目对应的 fiber 进入 `ACTIVE` 状态；有 fiber 不等于加载成功。见[插件加载](/docs/seams/loading) |
| **fiber** | cordis 为每个加载的插件建的运行单元，记录它的状态（等待依赖、运行中、失败等） |
| **包名 import** | 直接写包名、不带相对路径的 import（英文叫 bare specifier），比如 `import { Service } from 'cordis'`。运行时要靠 Node 去 `node_modules` 里找，或靠页面的 importmap 查表。见[关键设计](/docs/design#包名一律按-home-解析) |
| **构建产物** | 插件构建后发布出去的 `dist/` 里的文件，也就是运行时真正加载的代码 |
| **importmap** | 页面上的一张表：包名 → 文件地址。浏览器里的包名 import 靠它找到文件。见[页面上的包名](/docs/seams/shared) |
| **共享声明** | 包清单里的 `gwb.shared` 字段：「把我的这几个文件放进页面的 importmap」。见[页面上的包名](/docs/seams/shared) |
| **外壳（shell）** | 调用了 `setShell` 的那个插件，页面的 `#root` 交给它的默认导出来渲染。见[外壳接管](/docs/seams/shell) |
| **只读状态页** | 没有外壳、或外壳启动失败时页面显示的内容：各条目的加载状态和最近的错误日志，没有按钮。见[只读状态页的数据](/docs/desktop/status-page)、[外壳接管](/docs/seams/shell) |
| **命令总线** | `gwbCommands` 服务，由内核内置的命令插件（commands）提供，类型在词汇表包里；页面、MCP 入口和其他插件都经它按名字调用命令。见[命令插件](/docs/commands)、[命令总线](/docs/seams/command-bus) |
| **服务** | 插件通过 cordis 提供、别的插件在 `inject` 里写上名字再从 `ctx` 上读的对象。提供有两种写法：继承 cordis 的 `Service` 类，或 `ctx.provide`（只表示存在、不需要认出调用方时） |
| **扩展点** | 让别的插件往里注册东西的服务方法，比如注册命令、注册窗格、注册工具条按钮；提供扩展点的服务一律继承 `Service`，注册随调用方卸载自动撤销 |
| **存在标记服务** | 只用来表示「某个插件已经加载」的服务，可以带一个契约版本号；依赖它的插件会随它一起重新加载。插件管理的 `gwbPluginManager` 就是一个，见[插件管理](/docs/plugin-manager/commands#服务只表示装了) |
| **接口定义包** | 提供方单独发布的一个库：只有类型、常量和纯函数，没有状态；调用方把它打包进自己的构建产物 |
| **词汇表包** | `@godcreator/gwb-plugin-api`：内核给插件和页面提供的全部接口的类型，纯类型、没有运行时代码。见[词汇表包](/docs/vocab) |
| **准入判据** | 往内核里加东西要满足的条件：第一个插件运行之前必须完成，或者是没有它工作台就无法操作、也没有替换必要的平台核心；并且此刻确实需要。见[关键设计](/docs/design#准入判据) |
| **三路日志** | 插件、内核、页面 console 三个来源的日志，汇成同一条 cordis 日志流。见[日志](/docs/seams/log) |
