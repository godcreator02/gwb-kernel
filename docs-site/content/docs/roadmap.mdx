# 路线

**「等什么」那一栏是这页的重点。** 它记着「为什么现在不做」，正好接住准入判据第二关
（真遇到需求才加）。一条东西等的前提到了，它才该动。

## 做完了

| | 断言 | 怎么证明的 |
| --- | --- | --- |
| **一刀** 载体与桥 | 两个世界通上了 | 页面调一条命令穿过 IPC → fd3 → cordis 宿主再原路回；宿主 pid 独立、`node` 版本对得上 |
| **二刀** 取址 | 能挂插件 | 三条条目「挂上 / 位里没有 / 被禁用」逐条对上 |
| **三刀** 桥的另一半 | 看得见 | `client.js` 经 `gwb://` 到页面、`mountShell` 被调、外壳自己经 bridge 调命令 |
| **四刀** 装机 | 能从零装出一套 | 删净 home 起一次建出 home；外壳调 `kernel.install` 从本机 registry 装真包；重启后被挂上 |
| **五刀** loader 与服务 | **热挂载生效**、内核给得出信息 | 运行中 `create` 一条条目那个件当场挂上，`remove` 当场卸载、yml 自动写回；`ctx.gwbKernel` 四样对上；`emit` 的事件穿过 fd3 到了外壳 |
| 日志落盘 | 脱离终端也查得到 | 三处输出汇进 `<home>/gwb-kernel.log` |
| 保底 error 出口 | 挂载失败说得出原因 | 坏件报 `ERR_MODULE_NOT_FOUND` 带完整路径 |
| 词汇表包 | 契约面只有五个名字 | 产物 729 字节，零运行时依赖 |
| 文档三层分流 | 文档撒谎会被抓 | `walls.mdx` 钉住 14 处代码，`pnpm doc` 全绿 |
| **运行时环境** | **React 件跑得起来** | 验收件的 shadcn 按钮在页面上样式正确（`oklch(0.21 …)` 精确等于令牌值）；亮暗切换当场变色、没有任何件重新构建 |
| **home 分格** | **验收有干净场子了** | `homes/<名>`，`GWB_HOME` 选、不给就是 `default`；实测开一个测试 home 之后日常那份文件数 164→164 一个字节没动。顺带把「全新 home 从零起」这条**从没被走过**的路径第一次验通（撞出一个宿主整个退出的 bug，见 walls） |
| 门禁加一道 lint | **type-aware 真在跑，不是假装绿** | 双探针都报（`no-unused-vars` + `typescript/no-floating-promises`）；反向探针去掉 type-aware 后只剩前者；探针在时 `pnpm check` `exit 1`。基线 17 文件 / 111 规则 / 零诊断 |

内核现在约 **795 行**（`apps/desktop/src` 757 + 词汇表包 38），对照母仓 5100。

## 在等前提

| 要做的 | 等什么 | 说明 |
| --- | --- | --- |
| **主进程日志环形缓冲 + `logBacklog`** | **日志件真要看历史段** | 缓冲存原始行还是结构化条目，得看窗格怎么解析 |
| **打包（出安装包）** | 真要分发的时候 | 那时才拿 electron-builder 与 Forge 各试一次，手上会有一个确定的问题：pnpm 怎么进产物 |
| **MCP / 外部访问** | 真有 agent 要连进来 | 那时装官方的 `plugin-http`/`plugin-server`，不自己写 |
| **命令行（`gwb` CLI）** | 界面点不动时真需要一条出路 | 「刻意不做 GUI 兜底页」这条的前提就是命令行在。眼下从终端起，`console` 够用 |
| **多 home 的控制面** | 真要同时跑两套 | 目录已经是 `homes/<名>`、`GWB_HOME` 能选，验收够用了。缺的是 GUI 里切换那半（**那仍然是控制面，可能根本不该在内核里**），以及「两个实例同时跑」没验过——它们共享同一份 userData |

## 件那边

件的路线在**件仓的文档站**（`26090709qzp/gwb-base-plugins`）。眼下：

- `gwb-cli` 已发 0.0.3，装进 home 验通
- 两个共享包已发 0.0.1：`gwb-shared-react`（运行时环境）与 `gwb-tokens`（设计令牌）。
  **它们不是件**，是件的依赖，跟件平级装进 home
- `gwb-hello` 0.0.1 是验收件——运行时环境这条链路的证据，将来被真外壳替掉
- 下一个是 `gwb-shell`（dockview 外壳，分量最大）
- 然后 `gwb-logger`、`gwb-settings`

## 不在路线上

这些是**决定不做**，不是排期没排到。要做得先推翻准入判据——理由见
[刻意不做什么](/docs/not-doing)：

自动升级、盘上对账与失败还原、GUI 兜底页与阶段页、件之间的 peer 准入、
配置文件的模板与自愈、`plugin-hmr`。

**数据落盘**也归到这里了：它一度挂在「在等前提」那栏（等第一个真要落盘的件），而 shell
让那条前提到期时，重新过了一遍准入判据——第一关就否掉了，于是做成
[`gwb-data` 件](/docs/decisions)。内核只出 `dataDir`，其余归件。
