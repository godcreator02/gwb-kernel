# 路线

**「等什么」那一栏是这页的重点。** 它记着「为什么现在不做」，正好接住准入判据第二关
（真遇到需求才加）。一条东西等的前提到了，它才该动。

## 做完了

| | 断言 | 怎么证明的 |
| --- | --- | --- |
| **一刀** 载体与桥 | 两个世界通上了 | 页面调一条命令穿过 IPC → fd3 → cordis 宿主再原路回；宿主 pid 独立、`node` 版本对得上 |
| **二刀** 取址 | 能挂插件 | 三条条目「挂上 / 位里没有 / 被禁用」逐条对上 |
| **三刀** 桥的另一半 | 看得见 | `client.js` 经 `gwb://` 到页面、`bootShell` 被调、外壳自己经 bridge 调命令 |
| **四刀** 装机 | 能从零装出一套 | 删净 home 起一次建出 home；外壳调 `kernel.install` 从本机 registry 装真包；重启后被挂上 |
| **五刀** loader 与服务 | **热挂载生效**、内核给得出信息 | 运行中 `create` 一条条目那个件当场挂上，`remove` 当场卸载、yml 自动写回；`ctx.gwbKernel` 四样对上；`emit` 的事件穿过 fd3 到了外壳 |
| 日志落盘 | 脱离终端也查得到 | 三处输出汇进 `<home>/gwb-kernel.log` |
| 保底 error 出口 | 挂载失败说得出原因 | 坏件报 `ERR_MODULE_NOT_FOUND` 带完整路径 |
| 词汇表包 | 契约面只有五个名字 | 产物 729 字节，零运行时依赖 |
| 文档三层分流 | 文档撒谎会被抓 | 轨迹的墙卡钉住 14 处代码，`pnpm doc` 全绿 |
| **运行时环境** | **React 件跑得起来** | 验收件的 shadcn 按钮在页面上样式正确（`oklch(0.21 …)` 精确等于令牌值）；亮暗切换当场变色、没有任何件重新构建 |
| **home 分格** | **验收有干净场子了** | `homes/<名>`，`GWB_HOME` 选、不给就是 `default`；实测开一个测试 home 之后日常那份文件数 164→164 一个字节没动。顺带把「全新 home 从零起」这条**从没被走过**的路径第一次验通（撞出一个宿主整个退出的 bug，见[那面墙](/docs/trajectory/2026-09-07-wall-fresh-home-no-yml)） |
| 门禁加一道 lint | **type-aware 真在跑，不是假装绿** | 双探针都报（`no-unused-vars` + `typescript/no-floating-promises`）；反向探针去掉 type-aware 后只剩前者；探针在时 `pnpm check` `exit 1`。基线 17 文件 / 111 规则 / 零诊断 |

内核现在 **1374 行**（`apps/desktop/src` 1330 + 词汇表包 44），对照母仓 5100。

口径是**连空行与注释一起数**（`Get-Content | .Count`），这个仓注释密度高，正文远少于这个数。
**上一版这儿写着 795，那是个早就过时的数**——中间加了外壳反查、运行时环境收集等好几笔没跟着更新。
数字漂了就订正，但别为它专门去数：它只用来提醒「离母仓那 5100 还有多远」。

## 日志四路汇总

**前提到期了**——「主进程日志环形缓冲 + `logBacklog`」原先挂在下面那栏，等的是「日志件真要看
历史段」。要做 `gwb-logger` 了，于是重新过了一遍判据，形状也一并定死（六条都在
[轨迹](/docs/trajectory)）。

四路：件与 loader 的 cordis 日志、宿主自己的话（`host`/`install`/`stdin`）、主进程自己的话、
渲染层的 console。**窗格件那半在件仓**（`gwb-logger`），内核这边出的是通道与缓冲。

| | 做什么 | 状态 |
| --- | --- | --- |
| 一 | 宿主的 exporter 从「只管 error」扩成全量，正文同一个字符串投 stderr 与 fd3；宿主那几处裸 `console.error` 改走 `ctx.logger`；`logger-console` 撤掉 | **完成** |
| 二 | 主进程收齐四路发号进环形缓冲（`{ seq, ts, source, level, name, msg }`，2000 条） | **完成** |
| 三 | preload 加 `gwb.logs.backlog()` 与 `gwb.logs.on()`，实时按批推 | **完成** |
| 四 | 落盘挪到 `<home>/logs/`，2 MB 切一段、留 20 份 | **完成** |

**实机验收**（`GWB_HOME=log-2609071850`，装了 cli / shell / hello 三个真件）：

| 断言 | 怎么证明的 |
| --- | --- |
| 四路都进得来 | `backlog()` 点名回 `plugin × 2 → gwb-cli,gwb-shell`、`host × 6`、`renderer × 3`，外加杀宿主后的 `main` 那条 |
| 级别是真的、不是猜的 | 同一份文件里 Electron 那条 CSP 警告是 `W`、`console.error` 那条是 `E`、`console.log` 是 `I` |
| **窗口就绪之前一条不丢** | 宿主说的头四句（`install` 新 home、`host up`、条目逐条）`seq` 是 1–4，稳稳在 `backlog()` 里——那时窗口还没建出来 |
| **宿主死了 backlog 还在** | 杀掉宿主 pid，再取一次，尾巴上多出 `8 main/error/gwb 宿主退出（code=…）`，前面七条一条没少。**这一条单独证明「缓冲放主进程」是对的** |
| 实时推得动 | 页面里 `logs.on` 订上再 `console.log` 一句，回调收到一批，里头就是那句 |
| 落盘换了位置 | `<home>/logs/gwb.log` 出现，旧的 `gwb-kernel.log` 不再被写 |
| 轮转 | 单测跑真文件（切段、rename 撞占用仍交回可用 fd、删旧只碰归档名） |

**内核为此涨了 294 行**（src 1036 → 1330）。**当初估的是 190，估少了三分之一**——多出来的几乎
全是注释与那两条防回环的说明。这是单次最大的一笔增量，摆在这儿是因为「蹲住这条线」说的正是
这个：能砍掉一大块的只有轮转那部分，其余是「四路进窗格」的最小集。

## 在等前提

| 要做的 | 等什么 | 说明 |
| --- | --- | --- |
| ~~**收编件的裸 `console.log`**~~ | ~~真有件在裸 console 打日志~~ | **到期了，做了**（约 8 行，宿主里 `adoptConsole()` 把 `console.debug/info/warn/error` 转 `ctx.logger('console')`，走 plugin 路）。同轮把主进程侧几处静默失败也接上了日志：`gwb://` 取件失败、命令超时、宿主没起来/已杀、`GWB_HOME` 不合规——过去这些只回给调用方或者干脆无声 |
| **日志历史段跨启动** | **真要看上次那趟运行** | 眼下重启就清空，上次的去 `<home>/logs/` 翻文件。要跨启动得再写一份结构化 JSONL，那是净新增的第二份日志文件，两份不一致时没人说得清信哪份——到期时重新过第一关 |
| **打包（出安装包）** | 真要分发的时候 | 那时才拿 electron-builder 与 Forge 各试一次，手上会有一个确定的问题：pnpm 怎么进产物 |
| ~~**MCP / 外部访问**~~ | ~~真有 agent 要连进来~~ | **前提到了，做成件了**：`@godcreator02/gwb-mcp`（件仓 `26090709qzp`）。原来这条写着「那时装官方的 `plugin-http`/`plugin-server`」——**那句是错的**，见下 |
| **命令行（`gwb` CLI）** | 界面点不动时真需要一条出路 | 「刻意不做 GUI 兜底页」这条的前提就是命令行在。眼下从终端起，`console` 够用 |
| **多 home 的控制面** | 真要同时跑两套 | 目录已经是 `homes/<名>`、`GWB_HOME` 能选，验收够用了。缺的是 GUI 里切换那半（**那仍然是控制面，可能根本不该在内核里**），以及「两个实例同时跑」没验过——它们共享同一份 userData |

**MCP 那条为什么划掉了**：前提到了，于是做了——**做成件**（`@godcreator02/gwb-mcp`），
不进内核。它过不了准入判据第一关，也不需要过。

顺带订正那条里的一处事实错误：**`@cordisjs/plugin-http` 是 HTTP 客户端**
（`ctx.http`，axios 风格），它收不了请求；收请求的是 `plugin-server`（`ctx.server`）。
原来那句把两个件当成一对写，是没查过。而 `plugin-server` 最后一次发布早于
`cordis@4.0.0-rc.9` 两个半月，属于「semver 说行、作者没验过」。

最后哪个都没装：mcp 件自己起 `node:http`——那个 server 上眼下只有它一个客户，
拆一个 HTTP 件出来正好撞在第二关上。取舍的现场在件仓那页。

## 件那边

件的路线、每个件的状态与版本号，全在**件仓的文档站**（`26090709qzp/gwb-base-plugins`）。

**这儿不再抄一份** ——两处各记一份必然漂移，而且已经漂过：这一节的版本号一度停在好几轮
之前（`gwb-cli` 还写着 0.0.3、共享包写着 0.0.1），而 roadmap 是 `livedoc: none`、没有守卫。

形势一句话：底座那几件与两个共享包都验通了，外壳已经开得出窗格；**下一个是 `gwb-logger`**，
而它等的是内核这一轮（上面「在做」那节），件那边没有别的缺口。再往后是 `gwb-settings`。

## 不在路线上

这些是**决定不做**，不是排期没排到。要做得先推翻准入判据——理由见
[刻意不做什么](/docs/not-doing)：

自动升级、盘上对账与失败还原、GUI 兜底页与阶段页、件之间的 peer 准入、
配置文件的模板与自愈、`plugin-hmr`。

**数据落盘**也归到这里了：它一度挂在「在等前提」那栏（等第一个真要落盘的件），而 shell
让那条前提到期时，重新过了一遍准入判据——第一关就否掉了，于是做成
[`gwb-data` 件](/docs/trajectory/2026-09-07-gwb-data-plugin)。内核只出 `dataDir`，其余归件。
