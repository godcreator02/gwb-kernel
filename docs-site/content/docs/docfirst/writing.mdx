# 页怎么写

读完这页你能回答：一页文档的骨架是什么；新词怎么落；决策卡与墙卡怎么写；改代码和改文档谁先谁后。

## 读者是谁

第一读者是**通过 AI agent 干活的开发者**——读文档是为了理解系统、指挥 agent、判断 agent 的产出；**agent 也会直接读这些页**。所以：

- 事实必须**精确且完整**——「大概齐」对人是废话，对 agent 是毒药
- 写完全句，不写电报体；比喻可以进标题，不进正文
- 不写「先读第三章」那种债——每页自己站得住

## 三层分流

| 层 | 只装 | 判据 |
| --- | --- | --- |
| `CLAUDE.md` | 每次会话都得知道的硬约束 | 不知道就会做错事 |
| 文档站（钉代码） | 为什么这么定、撞过什么、判据怎么来的 | 需要时查；代码一变就报黄 |
| 代码注释 | 只写现状：这个文件装什么、这行在做什么 | 离了它读不懂**这一行** |

判断一句话去哪，问自己：是「必须知道」还是「想知道」？「服务名一律 `gwb` 开头」是必须知道（不知道就写错）→ `CLAUDE.md`；「为什么全加而不是通用名才加」是想知道 → 文档站；「这个函数是保底 error 出口」是读这行代码需要的 → 注释。**默认答案是文档站**——往 `CLAUDE.md` 加东西之前，先答上「不知道这条会做错什么事」。

## 一页的骨架

1. **承诺开头**：「读完这页你能回答……」——这页存在的理由，写不出承诺的页就别开
2. **定义**：一句话说清它是什么
3. **为什么**：为什么它不能是件、为什么这么定——这是文档站对注释的分工
4. **机制**：讲清楚怎么运作。钉码**稀疏**——解释页少钉，参考页多钉
5. **代价**：这套买到了什么、放弃了什么

## 术语

新词先在出现处定义一句，再收进[术语表](/docs/glossary)。造词是负债：每个词都要有人养，没人养的词赶紧删。

## 卡片：决策与墙

定过的事与撞过的墙住[轨迹](/docs/trajectory)，一卡一文件，只追加：

- **决策卡**五段：背景 / 结论与边界 / 否掉的候选 / 依据 / 代价与遗留。「代价」最要紧
- **墙卡**四段：现状 / 为什么 / 症状 / 钉住的那段代码。「症状」最值钱——写清**当时看到的是什么**（报错原文、日志里有什么、还是一声没有），下一个人照着症状就能认出同一个坑

`born-at` 取自引入它的那次提交，**永不改**；订正写进原卡、不删旧话；一条推翻另一条的写 `supersedes::`。

## 顺序

**先改代码 → 提交 → 写文档 → confirm。** 反过来行号全变，白 confirm 一遍；被钉的代码没提交，confirm 直接拒绝（见[账本与钉码](/docs/docfirst/how-it-works)）。
