# 页面与桥

**本页回答**：窗口怎么开、页面与主进程之间有哪几条通道、外壳怎么接管页面、没有外壳时页面画什么。

## 管什么

主进程这一头：开一扇窗，挂三条 IPC——命令下行、事件上行、外壳地址（连同 importmap 与只读现状）推给页面。页面这一头：`preload.cjs` 经 `contextBridge` 注一个 `window.gwb`，`index.html` 听外壳是谁、注 importmap、import 外壳模块并把 `#root` 交给它的默认导出；没有外壳或外壳起不来时，画一份只读现状。

## 不知道什么

不认识任何命令名——命令原样派给命令总线（某个件提供的 `gwbCommands` 服务），没有总线就回一句错。不挑外壳：谁调 `setShell` 谁是，后调的顶掉先调的。不画任何界面（只读现状除外）、不认识窗格。只读现状不归因、不重试、没有按钮。

## 数据结构

- **`gwb:shell` 消息**：`{ url, imports, report }`——外壳的 `file://` 地址（没有外壳是 `null`）、[importmap](/docs/kernel/importmap)、只读现状
- **只读现状 `report`**：home 路径、每条条目的 `{ id, name, state }`、cordis 日志缓冲里最近的 warn / error 行
- **条目状态词**：照 cordis 的 FiberState 原名（`PENDING` 带缺哪个服务、`FAILED` 带错误第一行），另有 `disabled` 与「没有 fiber（import 失败）」两种

## 提供的接口

**开窗**：一扇窗，`webPreferences` 只设 `preload`，沙箱与 `contextIsolation` 用 Electron 默认（开着）。窗底色与页面底色同一个值，首帧画好再亮窗；开窗时把 Electron 兜底的默认菜单撤成 null（菜单归件，[撤默认菜单](/trajectory/2026-09-15-default-menu-null)）。页面 console 逐条转进 `ctx.logger('renderer')`。开窗先于挂载件。

**三条 IPC**（主进程这一头）：`gwb:command` 派给命令总线；`gwbKernel.emit` 经 `gwb:event` 单向推给页面、火过就灭；`setShell` 与它的撤销函数、页面的 `gwb:hello` 各推一次 `gwb:shell`。

{/* ref file="../apps/desktop/src/main.ts" lines="223-247" */}

**去抖重推**：条目换态（cordis 的 `internal/status`）与 warn / error 日志到来时，去抖成一次重推 `gwb:shell`——给只读现状用，外壳在时页面收到也不动。

{/* ref file="../apps/desktop/src/main.ts" lines="204-221" */}

**`window.gwb`**（页面这一头）：`command` / `on` / `onShell` 三个函数，再没别的；`onShell` 订上就发 `gwb:hello` 问一次当前值。沙箱里跑，所以是 CJS。形状正本在[契约面](/docs/kernel/contract)的 `GwbWindowApi`。

{/* ref file="../apps/desktop/src/preload.cjs" lines="4-19" */}

**页面根**：先注 importmap 再 import 外壳（importmap 只注一次、空表不注，注过就盖不掉已解析过的名字）；同一个 url 已挂或正在来就不重复挂；拆旧外壳出错只 `console.error`；url 为 `null` 画只读现状；默认导出不是函数、或 import 失败，也画只读现状并带上原因。

{/* ref file="../apps/desktop/src/index.html" lines="68-98" */}

**只读现状**：全是 `textContent`，没有按钮。数据全是内核已经攥着的——loader 的条目树与 cordis 的日志缓冲。

**资产**：没有自定义协议，页面直接吃 `file://`；件的浏览器半地址由件自己从 `import.meta.url` 算、自己报（[单进程](/trajectory/2026-09-09-single-process)）。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `ctx.gwbCommands.run` | 页面命令的去处 | 命令总线件（commands） | — |
| `BrowserWindow` / `ipcMain` / `contextBridge` | 窗与桥 | Electron | — |
| `collectImports` | `gwb:shell` 里的 importmap | [importmap](/docs/kernel/importmap) | — |
| loader 条目树、cordis 日志缓冲 | 只读现状的数据 | cordis | 手造的 Entry（状态分类器） |

## 怎么单独测

`entry-state.ts` 不碰 electron 与 cordis 实例：手造条目，证明 disabled、没有 fiber、各 FiberState、`PENDING` 缺哪个服务、`FAILED` 取错误第一行、认不出的状态数字各说什么（`tests/entry-state.test.ts`）。窗、IPC、页面根与外壳交接只在隔离 home 里实机验：没有外壳件时看到只读现状，装上外壳后被接管，卸掉外壳后回到只读现状。
