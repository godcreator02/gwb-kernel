# 页面与 IPC

**本页回答**：窗口怎么创建、页面与主进程之间有哪几条通道、外壳怎么接管页面、没有外壳时页面显示什么。

## 管什么

主进程这一侧：创建一个窗口，注册三条 IPC 通道——命令从页面发给插件、事件从插件推给页面、外壳地址（连同 importmap 与只读状态页的数据）推送给页面。页面这一侧：`preload.cjs` 经 `contextBridge` 注入一个 `window.gwb`；页面入口 `index.html` 接收当前外壳是谁、注入 importmap、import 外壳模块并把 `#root` 交给它的默认导出；没有外壳或外壳启动失败时，显示只读状态页。

## 不知道什么

不认识任何命令名——命令原样转交给命令总线（某个插件提供的 `gwbCommands` 服务），没有命令总线就返回一句错误。不挑选外壳：谁调用 `setShell` 谁就是外壳，后调用的替换先调用的。不渲染任何界面（只读状态页除外），不认识窗格。只读状态页不分析失败原因、不重试、没有按钮。

## 数据结构

- **`gwb:shell` 消息**：`{ url, imports, report }`——外壳的 `file://` 地址（没有外壳时是 `null`）、[importmap](/docs/kernel/importmap)、只读状态页的数据
- **只读状态页的数据 `report`**：home 路径、每个条目的 `{ id, name, state }`、cordis 日志缓冲里最近的 warn / error 行
- **条目状态名**：沿用 cordis 的 FiberState 原名（`PENDING` 附带缺哪个服务、`FAILED` 附带错误的第一行），另外还有 `disabled` 与「没有 fiber（import 失败）」两种

## 提供的接口

**创建窗口**：一个窗口，`webPreferences` 只设置 `preload`，沙箱与 `contextIsolation` 用 Electron 的默认值（开启）。窗口背景色与页面背景色用同一个值，首帧渲染完成后再显示窗口；创建窗口时把 Electron 自带的默认菜单设为 null（菜单由插件负责，[移除默认菜单](/trajectory/2026-09-15-default-menu-null)）。页面 console 的每一条输出都转发到 `ctx.logger('renderer')`。创建窗口早于加载插件。

{/* ref file="../apps/desktop/src/main.ts" lines="249-273" */}

**三条 IPC**（主进程这一侧）：`gwb:command` 转交给命令总线；`gwbKernel.emit` 经 `gwb:event` 单向推送给页面，只推送、不保留；调用 `setShell`、调用它返回的撤销函数、页面发来 `gwb:hello`，这三种情况各推送一次 `gwb:shell`。

{/* ref file="../apps/desktop/src/main.ts" lines="223-247" */}

**去抖重推**：条目状态变化（cordis 的 `internal/status`）与 warn / error 日志到来时，去抖合并成一次 `gwb:shell` 重新推送——这是给只读状态页用的，外壳在的时候页面收到了也不做任何事。

{/* ref file="../apps/desktop/src/main.ts" lines="204-221" */}

**`window.gwb`**（页面这一侧）：只有 `command` / `on` / `onShell` 三个函数，没有别的；`onShell` 一订阅就发送 `gwb:hello`，请求一次当前值。它运行在沙箱里，所以是 CJS。类型定义的正本是[内核接口](/docs/kernel/contract)里的 `GwbWindowApi`。

{/* ref file="../apps/desktop/src/preload.cjs" lines="4-19" */}

**页面入口（`index.html`）**：先注入 importmap 再 import 外壳（importmap 只注入一次、空表不注入，注入后已经解析过的名字无法再被覆盖）；同一个 url 已经加载或正在加载，就不重复加载；卸载旧外壳出错只 `console.error`；url 为 `null` 时显示只读状态页；默认导出不是函数、或 import 失败，也显示只读状态页并写明原因。

{/* ref file="../apps/desktop/src/index.html" lines="68-98" */}

**只读状态页**：全部用 `textContent` 输出，没有按钮。数据全部是内核已经持有的——loader 的条目树与 cordis 的日志缓冲。

{/* ref file="../apps/desktop/src/main.ts" lines="173-195" */}

{/* ref file="../apps/desktop/src/entry-state.ts" lines="29-40" */}

**静态资源**：没有自定义协议，页面直接加载 `file://` 地址；插件在页面里运行的代码的地址，由插件自己从 `import.meta.url` 计算并上报（[两个进程合并为一个](/trajectory/2026-09-09-single-process)）。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `ctx.gwbCommands.run` | 处理页面发来的命令 | 命令总线插件（commands） | — |
| `BrowserWindow` / `ipcMain` / `contextBridge` | 窗口与 IPC 通道 | Electron | — |
| `collectImports` | `gwb:shell` 里的 importmap | [importmap](/docs/kernel/importmap) | — |
| loader 条目树、cordis 日志缓冲 | 只读状态页的数据 | cordis | 手工构造的 Entry（测状态分类函数） |

## 怎么单独测

`entry-state.ts` 不依赖 electron 与 cordis 实例：手工构造条目，证明 disabled、没有 fiber、各种 FiberState、`PENDING` 缺哪个服务、`FAILED` 取错误第一行、无法识别的状态数字，各自显示什么（`tests/entry-state.test.ts`）。窗口、IPC、页面入口与外壳接管只能在隔离 home 里实机验证：没有外壳插件时看到只读状态页，装上外壳后页面被外壳接管，卸载外壳后回到只读状态页。
