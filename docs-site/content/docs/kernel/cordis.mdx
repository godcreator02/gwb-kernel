## cordis 是什么

[cordis](https://github.com/cordiverse/cordis) 自我描述是 **「Meta-Framework for Modern
Applications」**——一个用来构建框架的框架：服务容器、插件生命周期、事件系统，三合一。
它从聊天机器人框架 Koishi 的核心里长出来成了独立库（Koishi 文档里那篇
[可逆的插件系统](https://koishi.chat/zh-CN/cookbook/design/disposable.html)把它的设计
动机讲得最透）。

本仓的「取址」和「插件」两件事整个站在它上面：主进程里那个 `Context` 是 cordis 的，gwb 插件
就是 cordis 插件，`cordis.yml` 这个文件名也来自它的官方约定。

- 源码：[cordiverse/cordis](https://github.com/cordiverse/cordis)（MIT）
- 文档：[cordis.moe](https://cordis.moe/zh-CN/)
- 本仓钉的版本：**cordis 4.0.0-rc.9**、plugin-loader 1.0.0-rc.6、plugin-include 1.0.5——
  **全部精确版本号，不用 `^`**：rc 期间插入符会悄悄吃进破坏性变更

## 功能地图

从装出来的包看，导出面是这几块（对着 rc.9 的类型声明核对过）：

| 能力 | 是什么 | 本仓怎么用 |
| --- | --- | --- |
| `Context` | 一切入口：依赖容器、插件挂载、事件总线三合一，可 extend 出子上下文 | 主进程 `new Context()` 一个根，provide 与挂 loader 全在它身上 |
| 插件与 fiber | `apply(ctx, config)` 或 `Service` 子类；fiber 六个状态，挂载/卸载/重挂构成生命周期 | gwb 插件＝cordis 插件；「挂上了」判 fiber ACTIVE（见[取址](/docs/kernel/loading)） |
| 服务系统 | `provide` / `inject` / `Service` 基类；服务撞名当场抛；`reflect.store` 可反查提供者 | `gwbKernel`、`gwbCommands` 全是 cordis 服务（见[内核契约面](/docs/plugins/contract)） |
| effect | `ctx.effect(() => 清理函数)`：注册即记档，卸载时逆序回收 | 插件提供服务的标准包法（外壳的 `setShell` 就包在这里面）；热挂载的清理靠它白得 |
| 事件 | `ctx.on` / `emit`，事件即服务（`EventService` 也是可注入的） | 插件与插件之间照用。插件到页面不走它——走 IPC（`gwbKernel.emit` → `gwb:event`，见[桥](/docs/kernel/bridge)） |
| 配置校验 | `plugin.Config` 走 Standard Schema，同步校验，async schema 直接拒 | 条目 `config` 原样交给 `apply`，校验归 cordis 本体 |
| 日志 | `ctx.logger(name)` + exporter 机制；没有 exporter 时只缓冲不输出 | 内核挂一个全量 exporter——这是三路日志唯一的内核侧出口（见[日志](/docs/kernel/logs)） |
| 计时器 | 原生 `ctx.setTimeout` 不随插件卸载回收 | 不用原生——挂 `plugin-timer` 替换，随插件卸载自动收 |

## 官方插件生态

`@cordisjs` 这个 scope 下有一排官方插件：`plugin-loader`（条目树与加载）、
`plugin-include`（读 yml 成条目）、`plugin-timer`、`plugin-http`、`plugin-server`、
`plugin-logger-console`、`plugin-hmr`、`plugin-database`……本仓只开三个
（loader / include / timer），其余各有理由不开——那张表在
[取址](/docs/kernel/loading#官方插件开着的与不开的)。加载链之外的官方插件，照样过准入
两道关才进。

## 去哪查

- **概念与指南**：[cordis.moe](https://cordis.moe/zh-CN/)——service、event、fiber 几章是主干
- **源码**：[github.com/cordiverse/cordis](https://github.com/cordiverse/cordis)，官方插件同在 cordiverse 组织下
- **本地最准**：`node_modules/cordis/lib/*.d.ts` 就是 rc.9 的完整类型面——rc 阶段文档
  可能滞后，行为拿不准时读类型与 dist 比猜文档快

## 代价与边界

- **它是 rc**：4.0 还在 rc，semver 不可全信——本仓钉精确版本，把升级当事件对待：读
  changelog、实机跑一遍再动
- **它不是我们家的**：cordis 官方插件的服务名不带 `gwb` 前缀（`timer`、`loader`），行为
  也不归我们管——那部分永远按「外部插件」对待，坏了自己修不修另说，反正不在内核仓修
- **骨架是它的，判据是我们的**：哪些能力进内核、哪些做成插件，照旧过准入两道关——cordis
  让「挂一个官方插件」变得便宜，但「便宜」不等于「该进」
