# 载体：一个进程、一扇窗

读完这页你能回答：cordis 和所有件为什么住在 Electron 主进程里；启动那几行为什么长那样；
窗口为什么必须由内核开。

**做什么**：主进程里一个 cordis `Context`（件全挂它身上），一扇 `BrowserWindow`。

**为什么不能是插件**：模块要有运行时才跑得起来，窗口要有进程才开得出来。这两样都发生在
第一个件之前。

## 为什么是一个进程

第一版不是：cordis 和件住一个独立的 node 宿主子进程，跟 Electron 隔开。本意是隔离，
结果件真正要的恰恰是 Electron——开窗、菜单、托盘、子进程、`electron` 模块本身——隔开的
墙上于是长满了绕墙的东西（fd3 协议、`gwb://`、exports 解析、日志四路管道）。2026-09-09
墙拆掉，cordis 搬进主进程：**件跑在主进程里，意味着件拿得到 `electron`**——开窗、菜单、
对话框、协议处理、子进程，全是件的事，内核一条都不用代办。两道准入判据因此更好用了。

了断与四个探针的读数见[单进程重构](/docs/trajectory/2026-09-09-single-process)。

## 启动的形状：ready 不能顶层等

Electron 的 ESM 主进程有一堵不起眼的墙：**`app` 的 `ready` 事件要等入口模块求值完才发**。
所以 `await app.whenReady()` 写在模块顶层就是互相等死——模块等 ready、ready 等模块——
而且**静默挂住**，一个报错都没有。

这段就是那堵墙的形状：入口模块里不 `await`，把启动体挂进 `.then(main)`；`main()` 里抛
什么都在 `.catch` 里走 `say` 落 stderr 与 `<home>/gwb.log`，弹一个 `dialog.showErrorBox`
（Electron 保证 ready 之前就能弹——这时窗多半还没开，没有这个框人看到的是程序闪一下没了），
再 `app.exit(1)`——起不来也得让人看见死因。现场见[那面墙](/docs/trajectory/2026-09-09-wall-esm-await-whenready)。
**别改回顶层 await。**

模块顶层那几行（铺 home、开日志文件）不在这个 `.catch` 里——它们抛了就是 Electron 自己的
未捕获异常框。够用，不另铺。

## 窗口必须由内核开

即使将来把窗口的尺寸、标题、关窗语义都交出去，`BrowserWindow` 这个动作本身仍留在内核——
**在件挂上之前就得有一扇窗让页面加载**（页面加载后先说「没有外壳件」，见[页面那半](/docs/plugins/client)）。

{/* ref file="../apps/desktop/src/main.ts" lines="254-275" */}

窗口先于挂件：`main()` 开完窗、加载 `index.html`，然后才 `ctx.plugin(Loader)` 去挂
home 的条目树（见[取址](/docs/kernel/loading)）。窗口里画什么归件——内核不画外壳，只铺
`#root`；外壳不在时页面画的那份只读现状是唯一例外（见[页面那半](/docs/plugins/client#没有外壳时那份只读现状)）。

## 渲染层的 console 归流

`console-message` 事件把页面 console 的每一条转进 `ctx.logger('renderer')`——这是三路
日志的第三路（见[日志](/docs/kernel/logs)）。级别词对不上的只有 warning→warn 一处，
逐词映射。

## 窗的安全位

`webPreferences` 里只设了一样：`preload` 的路径。其余全用 Electron 的默认——**沙箱开着、
`contextIsolation` 开着**。所以 `preload.cjs` 是 CJS（沙箱里跑不了 ESM），它经
`contextBridge` 只注一个 `window.gwb`（三个函数，见[桥](/docs/kernel/bridge)），其余
什么都不注；件与页面之间没有任何别的通道。
