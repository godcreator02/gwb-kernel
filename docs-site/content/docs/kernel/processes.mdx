# 载体：一个进程、一扇窗

读完这页你能回答：cordis 和所有插件为什么住在 Electron 主进程里；启动那几行为什么长那样；
退出时 cordis 由谁收走；窗口为什么必须由内核开。

**做什么**：主进程里一个 cordis `Context`（插件全挂它身上），一扇 `BrowserWindow`。

**为什么不能是插件**：模块要有运行时才跑得起来，窗口要有进程才开得出来。这两样都发生在
第一个插件之前。

## 为什么是一个进程

把 cordis 跟 Electron 隔开是条死路：插件真正要的恰恰是 Electron——开窗、菜单、托盘、子进程、
`electron` 模块本身——隔开的那道墙上只会长出绕墙的机器。cordis 住主进程：**插件跑在主进程里，
意味着插件拿得到 `electron`**——开窗、菜单、对话框、协议处理、子进程，全是插件的事，内核
一条都不用代办。唯一的例外是开窗时把 Electron 兜底的默认菜单撤成 null（没人订的默认，退它
不算代办，件要菜单随时自己 `Menu.setApplicationMenu` 盖回来，见[撤默认菜单](/trajectory/2026-09-15-default-menu-null)）。
两道准入判据因此更好用了。

了断与四个探针的读数见[单进程重构](/trajectory/2026-09-09-single-process)。

## 启动的形状：ready 不能顶层等

Electron 的 ESM 主进程有一堵不起眼的墙：**`app` 的 `ready` 事件要等入口模块求值完才发**。
所以 `await app.whenReady()` 写在模块顶层就是互相等死——模块等 ready、ready 等模块——
而且**静默挂住**，一个报错都没有。

{/* ref file="../apps/desktop/src/main.ts" lines="268-277" */}

这段就是那堵墙的形状：入口模块里不 `await`，把启动体挂进 `.then(main)`；`main()` 里抛
什么都在 `.catch` 里走 `say` 落 stderr 与 `<home>/gwb.log`，弹一个 `dialog.showErrorBox`
（Electron 保证 ready 之前就能弹——这时窗多半还没开，没有这个框人看到的是程序闪一下没了），
再 `app.exit(1)`——起不来也得让人看见死因。现场见[那面墙](/trajectory/2026-09-09-wall-esm-await-whenready)。
**别改回顶层 await。**

模块顶层那几行（铺 home、开日志文件）不在这个 `.catch` 里——它们抛了就是 Electron 自己的
未捕获异常框。够用，不另铺。

## 退出的形状：will-quit 里收走 cordis

「起 cordis」有收尾的另一半：app 退出前 dispose 掉 loader 的 fiber，整棵插件树
（home → include → 每个插件）的收尾 effect 递归跑完。插件起的长命子进程（站点插件起的 node
那种）靠这条路被带走——不然主进程一退，它们就是孤儿占着端口。

{/* ref file="../apps/desktop/src/main.ts" lines="280-307" */}

判据一句话：**谁起了 Context 谁收 Context**。收运行时是「起 cordis」的收尾半，住内核；
插件各自挂 will-quit 各救各的会是第二份真相——总有插件忘了挂，而忘了的那个插件恰好就是
起进程的那个时，没人兜底。

**等到拆完是两半的合同，缺一不可**（判据见[退出收尾两半的合同](/trajectory/2026-09-12-quit-dispose-two-halves)）：cordis 的
`dispose()` 只把拆卸**启动**，嵌套的异步收尾不包在它的 promise 里——孙层 300ms 的清理
它不等，随后 `await()` 补上才等得到整棵树；插件那半也得把真收尾**返回**出来（effect 清理
回 promise），否则 cordis 沿链等的时候手里等的是个立即完成的空盒。两半只修其一，实测
现象是「退出日志一切正常、子进程原地活着」。

这段里四个要素缺一不可：`preventDefault` 拦住这一趟，收完尾再 `app.quit()`；`quitting`
标记放收尾完的二次 quit 过去；dispose 的错只记不拦——一个插件的收尾抛了不该拦住别的插件的
收尾；**5 秒超时兜底**——某个插件的收尾挂死时工作台也必须退得出去，超时就硬退，没杀干净
的认了。`main()` 还没走到挂 loader（起得慢、起来就退）时 fiber 是 undefined，放行正常退出。

## 窗口必须由内核开

即使将来把窗口的尺寸、标题、关窗语义都交出去，`BrowserWindow` 这个动作本身仍留在内核——
**在插件挂上之前就得有一扇窗让页面加载**（页面加载后先说「没有外壳件」，那句是 `index.html` 里的原话，见[内核契约面](/docs/plugins/contract)）。

{/* ref file="../apps/desktop/src/main.ts" lines="230-254" */}

窗口先于挂载插件：`main()` 开完窗、加载 `index.html`，然后才 `ctx.plugin(Loader)` 去挂
home 的条目树（见[取址](/docs/kernel/loading)）。窗口里画什么归插件——内核不画外壳，只铺
`#root`；外壳不在时页面画的那份只读现状是唯一例外（见[内核契约面](/docs/plugins/contract#没有外壳时那份只读现状)）。

## 渲染层的 console 归流

`console-message` 事件把页面 console 的每一条转进 `ctx.logger('renderer')`——这是三路
日志的第三路（见[日志](/docs/kernel/logs)）。级别词对不上的只有 warning→warn 一处，
逐词映射。

## 窗的安全位

`webPreferences` 里只设了一样：`preload` 的路径。其余全用 Electron 的默认——**沙箱开着、
`contextIsolation` 开着**。所以 `preload.cjs` 是 CJS（沙箱里跑不了 ESM），它经
`contextBridge` 只注一个 `window.gwb`（三个函数，见[桥](/docs/kernel/bridge)），其余
什么都不注；插件与页面之间没有任何别的通道。
