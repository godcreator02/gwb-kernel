# 日志：四路汇主进程

读完这页你能回答：一句 `console.log` 走哪条路进窗格；为什么历史段不过命令通道；文件里那行文本和窗格里那条结构化条目是什么关系。

**缓冲与汇总在主进程**，不在宿主、也不在任何件：够得着四路的只有它，而且**宿主崩了之后它还在**——那正是最需要翻历史的时刻（判据见[日志四路汇在主进程](/docs/trajectory/2026-09-07-logs-converge-main-process)）。

## 四个源头，在源头就结构化

| 源 | 是什么 | 怎么进来的 |
| --- | --- | --- |
| `plugin` | 件与 loader 的 cordis 日志 | 宿主的 exporter 打成结构化条目走 fd3 |
| `host` | 宿主自己的话 | 同一条 fd3；分源靠 `KERNEL_LOGGERS` 名册（`host`/`stdin`/`loader` 算宿主的话——loader 报的是引导链，不是件） |
| `main` | 主进程自己的话 | `mainLog` 直进 |
| `renderer` | 页面的 console | Electron 的 `console-message` 事件，主进程补上来源标记 |

四路各自在**源头**结构化成条目，因为界面要的是按级别与来源筛，文本行给不了这个。`level` 四路给的都是真级别：渲染层的 `warning` 归一成 `warn`，不猜——「宁可用钝的级别，也别留一个永远关不掉的筛选项」。

## exporter 必须在第一个件之前

cordis 的日志在没有 exporter 时**只缓冲不输出**。宿主的全量 exporter 在 `new Context()` 之后、挂 loader 之前注册——第一个挂不上的件可能正是会格式化日志的那个件，它的报错不能等（见[那面墙](/docs/trajectory/2026-09-07-wall-loader-error-swallowed)）。两处细节：

- `%o`/`%O` 走 `util.inspect` 而不是 JSON——循环引用会在业务代码的 `logger.info` 调用点上炸，那不是日志该干的事
- exporter 投 stderr 用 `process.stderr.write`、不用 `console.error`——主进程那边劫持了 stdout/stderr 落盘，用 `console.error` 就是自食其尾的无限循环

件的 cordis 日志正文是**同一个字符串两处投**：stderr（进文件）与 fd3（进窗格）。格式只有一种，`formatLogLine` 收在一处——一处两投之后格式混过，靠收拢修掉（见[那面墙](/docs/trajectory/2026-09-07-wall-two-format-mix)）。

## 发号、缓冲、推送

**seq 由主进程在四路汇合之后发**——全局序只在这一个地方存在。去重和排序都用它，别拿 `ts` 拼字符串：同一毫秒里两句一模一样的话是常事，字符串键会静默吃掉第二句。

进缓冲和发往窗口是两步，**先缓冲后推**：窗口还没建出来那阵（宿主起步、坏件报错）恰恰是最值钱的几条。缓冲 2000 条；攒 100ms 推一批——崩溃循环里逐条 IPC 会把渲染层钉死。

## backlog 不过命令通道

历史段从主进程内存直答（IPC `gwb:log-backlog`），**不走命令通道绕宿主**。理由：命令要从缓冲旁边路过、绕到宿主再原路背回来，而**宿主一挂命令全废——那恰恰是最需要看日志的时候**（判据全文见[日志走 preload](/docs/trajectory/2026-09-07-logs-preload-api)）。实测过：杀掉宿主，backlog 尾巴上多出 main 记的那条「宿主退出」，前面一条不少——这一条单独证明「缓冲放主进程」是对的。

页面的消费契约：**先订阅，后取历史**，两段按 seq 合并去重。顺序反了，订阅之前那一瞬的条目就漏了。

## 文件是第五条平行漏斗

结构化的四路之外，`<home>/logs/gwb.log` 收的是**字节**：主进程把 stdout/stderr 整个劫持落盘——宿主 pipe 过来的、第三方库直写的、没经过结构化路径的崩溃现场，全在。两条漏斗不是子集关系，谁也替代不了谁（判据见[按字节切](/docs/trajectory/2026-09-07-log-byte-rotation)）。

- 文件名固定——`tail -f` 和所有读者都靠它
- 2 MB 切一段、留 20 份归档，按字节不按行
- **两个闩分开**：`dead` 管写失败（一次就永远不再写文件，否则每行输出都变成一次失败的 syscall）；`rotateDead` 管轮转失败（不再切、但继续写进单文件）。共用一个的话，一次 rename 撞占用就把整个文件漏斗杀死了（见[那面墙](/docs/trajectory/2026-09-07-wall-log-latch-once)）

## 两条纪律

**一、件别自己挂 exporter。** 日志出口归内核——件挂一个就是同一句话走两条通道，日志页里两行一模一样。件要打日志就正常用 `ctx.logger`，四路汇总会收到。

**二、收日志的路径上一个 `console` 都不许打。** 渲染层 console 是四路之一：窗格打一句 → 主进程收走 → 进缓冲 → 推回窗格 → 路上如果又打了一句，就是一变二、二变四，**界面当场冻死**。取表失败那种非循环路径上的可以留。
