# 日志：stderr 加一个文件

读完这页你能回答：日志有哪些路、出口在哪儿；为什么内核不替窗格铺日志管道；件的日志件
怎么把三路收齐。

内核铺的出口**只有一处**：stderr，加 home 里一个只追加的文件。

{/* ref file="../apps/desktop/src/main.ts" lines="43-52" */}

一个件都没有、窗口没起、终端不在——只要这个进程活着，`<home>/gwb.log` 里就有人读得懂的
一行行。`say` 只给 exporter 本身与「起不来」那一句用；格式是最朴素的 `ISO 时间 级别 名字
正文`。**只追加、不轮转**——按字节切段的旧机制随日志管道一起退役了（见[轨迹](/docs/trajectory)），
真到文件要人管的那天，重新过判据。

末行那句 `process.stderr.on('error', () => {})` 不是可省的：没有终端起的时候（比如从
`run.cmd` 双击起），stderr 对端是断的，每写一次抛一次 EPIPE，不吞它进程就死在写日志上
（见[那面墙](/docs/trajectory/2026-09-08-wall-stderr-epipe)）。

## exporter 必须在第一个件之前

cordis 的日志在没有 exporter 时**只缓冲不输出**。内核的全量 exporter 在模块顶层注册——
挂 loader、开窗都在它后面，第一个挂不上的件可能正是要报错的主角，它的报错不能等
（见[那面墙](/docs/trajectory/2026-09-07-wall-loader-error-swallowed)）。

{/* ref file="../apps/desktop/src/main.ts" lines="89-121" */}

三处细节值得看：

- **渲染交给 cordis 自己的 `Logger.format`**——`%s`、`%o`、Error 它都认。类从一个实例的
  `constructor` 上取，免得 import cordis 的内部；format 失败还有一层把参数逐个 String 的
  兜底，**日志格式化自己坏了不能把业务调用点炸了**
- 级别与名字在 cordis 那边就是字符串，`export` 里照抄不加工——真级别在源头就是真的
- error / warn 到来时**捅一下页面**（`pushShell`，去抖）：没有外壳时页面画的那份只读现状
  里有「最近的错误行」，它从 cordis 自带的 `buffer` 里筛——内核不自建缓冲，用 cordis 那份
  （见[浏览器那半](/docs/plugins/client#没有外壳时那份只读现状)）。exporter 里做的仍然
  只是「通知」，不写任何会进日志的东西

## 三路怎么齐的

| 路 | 名字 | 怎么进来 |
| --- | --- | --- |
| `plugin` | 件自己的 logger 名 | 件正常用 `ctx.logger`，cordis 分发到 exporter |
| `kernel` | `kernel` | 内核自己的话也走 `ctx.logger('kernel')`，**不直接 `say`** |
| `renderer` | `renderer` | 页面 console 经 `console-message` 事件转进来（见[载体](/docs/kernel/processes#渲染层的-console-归流)） |

{/* ref file="../apps/desktop/src/main.ts" lines="123-130" */}

「内核的话也走 logger」是刻意的小绕：不绕的话内核的话只进文件，件挂 exporter 收不到它。
走了同一条流，**任何件挂一个 exporter 就把三路收齐**。件仓的 `gwb-logger` 就是那个收的
件：挂第二个 exporter、从 `ctx.logger.buffer` 补历史段、经 `gwbKernel.emit` 推给页面上的
日志窗格——内核不为窗格铺任何管道。

末尾那两个 `process.on` 是「件跑在这个进程里」的直接后果：件的错就是这个进程的错。
**只记不退**——一个坏件不该带走工作台。三种坏法（apply 同步抛、没人接的 rejection、
定时器里抛）实机验过全接得住、主进程活着，读数见
[单进程重构](/docs/trajectory/2026-09-09-single-process)。

## 两条纪律

**一、收日志的件只读不写。** 件挂 exporter 是正道（日志件就靠它），但 exporter 里不许再
碰任何会进日志的东西——再 `console` 或 `logger` 一句，那句又被自己收走，一变二、二变四。
内核那份 exporter 里 `try/catch` 兜底也是同一个理由。

**二、渲染层窗格里的 console 是日志的源，不是调试台。** 页面窗格打一句 console → 转成
`renderer` 路 → 日志件收走 → 推回窗格 → 路上谁再打一句就是回环，界面当场冻死。取数据
失败那种非循环路径上的可以留。
