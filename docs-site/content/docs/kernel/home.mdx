# home

**本页回答**：内核怎么决定用哪个 home、每次启动往里面补什么、为什么同一个 home 启动不了第二个实例、`runtime.json` 是什么。

## 管什么

在任何插件存在之前，把 home 准备成 cordis 能启动的目录：选定目录并规范化为磁盘上的真实路径，补齐两个文件，获取这个 home 的单实例锁，写下本次运行的进程信息。这些全部在 `main.ts` 的模块顶层同步完成，早于 `whenReady`。

## 不知道什么

不知道 home 里装了哪些插件、条目表里写了什么——补的两个文件只保证「能启动」，不保证「里面有插件」。不碰 pnpm，不安装任何包。不认识 `runtime.json` 里内核以外的字段（提供 MCP 入口的插件会在里面补上自己的字段）。不读取、不清理别的 home。

## 数据结构

| 磁盘上的文件 | 谁写 | 内核怎么处理 |
| --- | --- | --- |
| `<home>/package.json` | 缺了由内核补一份最小清单，之后归 pnpm 管 | 只补不改 |
| `<home>/cordis.yml` | 缺了由内核补空表 `[]`，之后归 include 管 | 只补不改；缺了它整次启动都会失败（[全新 home 没有 `cordis.yml` 时启动失败](/trajectory/2026-09-07-wall-fresh-home-no-yml)） |
| `<home>/electron/` | Chromium | 这个 home 的 userData，也是单实例锁的依据 |
| `<home>/runtime.json` | 内核 | 每次启动整份重写，退出时不删 |
| `<home>/gwb.log` | 内核 | 见[日志](/docs/kernel/logs) |

## 提供的接口

**怎么选定 home**：`GWB_HOME` 不设时是 `default`；给一个纯名字，就用 `<appData>/gwb-kernel/homes/<名>`；含路径分隔符，就直接用那个目录。选定后用 `realpath` 规范化，同一个 home 的两种写法得到同一个字符串——单实例锁靠它判断「是不是同一个 home」。

**补齐两个文件**：每次启动都执行，缺什么补什么，已有的一律不覆盖。

**单实例锁**：用 Electron 的单实例锁，锁的依据是上面那份按 home 分开的 userData。同一个 home 的第二个实例拿不到锁，就在 stderr 报一句、以退出码 1 退出、不动 `runtime.json`；正在运行的那个实例把窗口调到最前。不同的 home 可以同时运行。理由见[同一 home 只允许一个实例](/trajectory/2026-09-12-one-home-one-instance)。

**`runtime.json`**：pid、启动时间、内核版本、应用目录；开了 Chromium 调试端口时再加一个 `cdp` 字段（没开就没有这个字段，不写 0 或 null）。每次启动整份重写；退出时不删——**读它的一方负责确认进程还活着**（pid 对应的进程还在，而且确实占着那个端口）。写入失败只报一句 warn。理由见[内核启动时把运行时记录写进 home](/trajectory/2026-09-11-kernel-writes-runtime-record)。

{/* ref file="../apps/desktop/src/main.ts" lines="97-122" */}

**`dataDir` 是唯一来源**：`ctx.baseUrl`、日志路径、`gwbKernel.dataDir` 都由它得出；插件要 home 路径只从 `gwbKernel.dataDir` 取（见[内核接口](/docs/kernel/contract)）。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `GWB_HOME` 环境变量 | 选定 home | 由启动进程的一方设置 | 实机验证：每次验证用一个隔离 home 名 |
| `app.getPath('appData')` / `app.setPath('userData')` | homes 根目录、按 home 分开 userData | Electron | — |
| `app.requestSingleInstanceLock` | 单实例锁 | Electron | 实机验证：同一个 home 启动两次 |
| 命令行 `--remote-debugging-port` | `runtime.json` 的 `cdp` 字段 | 由启动进程的一方传入 | — |

## 怎么单独测

没有可以抽出来的纯函数——这部分全是 Electron 与文件系统的顶层副作用，只能在隔离 home 里实机验证：全新的 home 能启动、两个文件被补齐且已有的不被覆盖、同一个 home 第二次启动被拒绝、`runtime.json` 每次启动都重写。
