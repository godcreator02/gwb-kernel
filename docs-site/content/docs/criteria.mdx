# 关键判据

**本页回答**：在这个内核上写件、改内核时，反复出现的几类选择该怎么判。

每条都是此刻生效的规矩：新写的和改动的代码照它办；代码还没跟上的地方，在「执行」一项里标出来。编号稳定，说明书和别的仓引用时写「见关键判据 K2」，不复述正文。为什么这么定，链到轨迹卡与探针。

## K1 进内核还是做成件

**凡是第一个件存在之前必须发生的事，才进内核；真遇到需求才加。** 其余一律皆件。

- **怎么判**：先问这件事能不能由某个件提供、经服务送到用得着的地方，能就做成件。说不出「此刻干不成」的现场（谁、在做什么、卡在哪），就不加。拿不准按「不进」——加回来永远比拿掉容易
- **反例**：「将来可能要」「顺手做了」「母仓有这个」
- **为什么**：[根卡](/trajectory/2026-09-07-gwb-kernel)、[另起一条线](/trajectory/2026-09-07-fresh-line-over-subtraction)
- **执行**：靠人；改内核要人拍板。内核此刻只做什么、刻意不做什么见[边界](/docs/boundary)

## K2 依赖怎么写（peer 怎么用）

**peer 只用于运行环境提供、件不自带的东西。** 按运行时这份代码由谁提供来定：

| 运行时谁提供 | 写法 |
| --- | --- |
| 宿主提供、件按值 import（`cordis`） | 必选 peer，不打进束 |
| 运行环境自带（node 内置、`electron`） | 不声明 |
| 页面经 importmap 提供（react 四名，见 K3） | 浏览器半外置，类型写 dev |
| 另一个件 | 不 import，走服务或命令（见 K4） |
| 只出现在本件导出的类型里 | 可选 peer（`peerDependenciesMeta.optional`）＋ dev，沿类型链逐包成立 |
| 本件运行时自用的库 | dev，打进束 |

- **反例**：拿 peer 声明别的件、普通库、react 或已停发的共享包；把宿主的 `cordis` 打进束；写 `instanceof Service`——件和宿主的 cordis 可能是不同的拷贝，跨拷贝时它为 false
- **为什么**：cordis 靠 `Symbol.for` 协议键跨拷贝工作，实测见仓根 `probes/2609231600_cordis-multi-copy/`；导出类型里的外部包只写 dev 时，解析全靠 pnpm 的隐藏提升、少列一个就静默变 any，可选 peer 要沿类型链逐包成立，实测见 `probes/2609231600_types-without-peer/`；[cordis 走 peer](/trajectory/2026-09-07-wall-cordis-peer)
- **执行**：迁移中（[机制定案](/spec/ecosystem-simplify)第二、三期）。守卫计划放在 `devkit.release`：node 半产物里的裸名只能是内置、`electron` 与必选 peer；发布的 d.ts 里出现的外部包都有 peer 声明

## K3 什么能进 importmap

**importmap 只放整页必须只有一份的运行时**，今天就是 react 那四个名字。

- **怎么判**：同一个模块在页面上出现两份会出错（全局单例、hooks 这类），才进。只是体积大、或好几个件都用，不进，各自打进束——页面从本机 `file://` 加载，重复几百 KB 可以接受
- **规则**：提供方只能是挂着条目的件；一个裸名只有一个提供方，撞名全拒（见 [importmap](/docs/kernel/importmap)）；件的外置名单只从提供方的声明里读，不手抄；共享的运行时升大版本，就是提供方的破坏版
- **反例**：库自己声明 `gwb.shared`；为省体积把工具库放进 importmap；在各件的构建脚本里手抄外置名单
- **为什么**：[importmap 归内核](/trajectory/2026-09-09-importmap-in-kernel)
- **执行**：撞名全拒已有机械守卫；块笔记的解析库现在经 importmap 共享、各件构建脚本手抄 react 四名，属迁移中

## K4 件与件怎么交互

**只经 cordis 服务与命令，不 import 别的件的运行时代码。**

- **怎么判**：跨边界只传纯数据、函数与 `{ ok, data, error }` 信封，不对别件的对象做 `instanceof`（各件带的库可能是不同的拷贝）。几个件读写同一份盘上格式时，用契约版本号比对，对不上就拒绝挂载。在场与联动交给 cordis 的 inject：提供方重挂时，依赖它的件被自动拆掉再挂回
- **反例**：import 别的件的包来拿运行时函数；靠模块单例共享状态
- **执行**：大多数件已符合；块笔记一族与论文件之间的运行时 import 属迁移中

## K5 服务还是命令

**调用方是件 → provide 服务；调用方是页面或 agent → 注册命令；两边都要 → 服务为本，命令做一层薄包装。**

- **怎么判**：服务在进程内、类型化，可以传函数与对象，随 fiber 撤销。命令的参数与回执可序列化，一条只做一件事；把多步编排写进一条命令是反模式，编排归说明书——唯一例外是判定依赖同一份「这一趟之前」状态的事务。命令的 `plugin` 字段写包名
- **反例**：件之间互调命令；一条命令把抬号、查重、发布、装机串成一串
- **为什么**：[命令原子、门中立](/trajectory/2026-09-14-atomic-commands-door-neutral)
- **执行**：靠人；命令总线对 `plugin` 字段的写法只警告不拦

## K6 契约住哪

**谁提供，谁定义。** 内核提供的面（`gwbKernel`、`window.gwb`、外壳导出形状）住词汇表包，只增不减；件提供的服务类型、命令形状住那个件自己的包。

- **反例**：把件之间的契约塞进词汇表包；消费方手写提供方的类型
- **为什么**：[词汇表独立包](/trajectory/2026-09-07-vocab-package-standalone)、[它就这么大](/trajectory/2026-09-07-wall-vocab-just-size)
- **执行**：词汇表包已是纯类型（见[契约面](/docs/kernel/contract)）；「只增不减」靠发版纪律

## K7 状态与收尾

**随重挂该清掉的状态放 `apply` 里；件自己起的进程、定时器、监听、在途落盘，卸载时收走，并把 promise 交回去。**

- **怎么判**：模块顶层的状态在同版本重挂时不会重置，只放真要跨重挂留着的东西。落盘走数据件，配置走设置件；home 路径只从 `gwbKernel.dataDir` 取，不自己拼
- **为什么**：内核退出时只等交回来的 promise，[退出收尾两半](/trajectory/2026-09-12-quit-dispose-two-halves)；[数据件](/trajectory/2026-09-07-gwb-data-plugin)
- **执行**：靠人；node-cli、py-cli、windows-backup、bn-core、mcp 各有一处要补（[机制定案](/spec/ecosystem-simplify)）

## K8 版本抬哪一位

**0.x 里只在破坏契约面时抬 x，其余一律抬 y。** 契约面清单、peer 范围怎么写、发破坏版多做的两步，正本在 devkit 的说明书 `gwb-release`，这里不复述。

- **执行**：`devkit.release` 的发版检票机械执行其中一部分
