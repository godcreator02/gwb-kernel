# K5 服务还是命令

## 规则

**扩展点用服务，数据读写和动作用命令；同一能力只提供一种调用方式（服务或命令二选一）。**

## 怎么判

- **服务**：用于命令表达不了的东西——注册（让别的插件往这里注册窗格、命令、工具）、回调、需要跟着提供方一起重新加载的生命周期。服务上不放读写数据和执行动作的方法
- **命令**：可序列化的读写和动作。页面、agent、插件都用同一套命令，这是插件对外提供能力的唯一方式；插件内部想要类型安全，就通过提供方发布的类型化客户端来调（放在接口定义包里，见 [K4](/docs/criteria/k4)）
- **存在标记服务**：依赖方需要跟着提供方一起重新加载、但又只用命令时，inject 提供方的一个存在标记服务（可以只带契约版本号）
- 一条命令只做一件事；多步流程写在说明书（skill）里。唯一的例外是判定依赖同一份「这次执行之前」状态的事务
- 命令的 `plugin` 字段写包名

## 标准例子

- 只有扩展点的服务：[E1 commands](/docs/criteria/examples/e1-commands#对外接口)、[E5 node-cli](/docs/criteria/examples/e5-node-cli#对外接口)
- 服务只留扩展点、数据和动作全部通过命令：[E2 shell](/docs/criteria/examples/e2-shell#对外接口)、[E3 unit-folder](/docs/criteria/examples/e3-unit-folder#对外接口)
- 以命令为主，加一个存在标记服务：[E4 块笔记](/docs/criteria/examples/e4-block-note#对外接口)

## 反例

同一能力既有服务方法又有命令（两种调用方式会悄悄变得不一致）；为了读别的插件的配置或数据，去调它的设置分区；一条命令带一个 `action` 参数做四件事；一条命令把升版本号、查重、发布、安装串成一串。

## 为什么

命令表是页面、agent、插件共用的同一份事实来源；再提供一套服务方法，就有了两份并行的来源。服务留给命令表达不了的扩展点和生命周期。[命令保持原子、多步流程写进 skill；内核不关心 MCP 入口用什么协议](/trajectory/2026-09-14-atomic-commands-door-neutral)。

## 执行

迁移中：shell、unit-folder、node-cli 等服务上的读写方法与同名命令重复；plugin-manager、docs-site 通过设置命令读别的插件的设置分区。命令总线对 `plugin` 字段的写法只警告、不拦截。
