# 关键判据

**本页回答**：有哪几条关键判据、每条一句话说什么、执行到了哪一步；怎么读、怎么引用。

每条判据都是当前生效的规矩：新写的代码和改动的代码都按它来，代码还没改过来的地方，在各页「执行」一段里标出来。编号就是网址（`/docs/criteria/k2`），说明书（skill）和别的仓引用时写「见关键判据 K2」，不复述正文。每页六段：规则、怎么判、标准例子、反例、为什么、执行。判据落到一个具体的插件上是什么样子，看[标准例子](/docs/criteria/examples)。

| 编号 | 规则 | 执行 |
| --- | --- | --- |
| [K1](/docs/criteria/k1) | 第一个插件运行之前必须完成的事才进内核；确实遇到需求才加 | 靠人工把关 |
| [K2](/docs/criteria/k2) | peer 只写由宿主（内核）提供、插件按值 import（import 的是运行时的值，不只是类型）的 `cordis`；其余一律写 dev；构建产物里剩下的包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）只能是 node 内置模块、`electron`、`cordis` 与 importmap 里的名字 | 迁移中 |
| [K3](/docs/criteria/k3) | importmap 只放整个页面必须只有一份的运行时代码，提供方只能是插件 | 部分有自动检查 |
| [K4](/docs/criteria/k4) | 插件之间只通过服务和命令交互；共享代码用无状态的接口定义包；磁盘上的数据格式按区间比对契约版本 | 迁移中 |
| [K5](/docs/criteria/k5) | 扩展点用服务（继承 cordis 的 `Service` 类，注册随调用方卸载自动撤销），数据读写和动作用命令；同一能力只提供一种调用方式（服务或命令二选一） | 迁移中 |
| [K6](/docs/criteria/k6) | 谁提供接口，谁定义契约；调用方不手写、不强制转换成提供方的类型 | 迁移中 |
| [K7](/docs/criteria/k7) | 插件自己启动或创建的一切，卸载时都要清理掉，并返回 promise | 迁移中 |
| [K8](/docs/criteria/k8) | 0.x 版本里只在破坏契约（对外承诺的接口）时升 x，其余升 y | 部分有自动检查 |

读的顺序：写插件先读 K2、K4、K5、K7，再对照[标准例子](/docs/criteria/examples)；改内核先读 K1。
