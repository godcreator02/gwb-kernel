# 关键判据

**本页回答**：有哪几条关键判据、每条一句话说什么、执行到哪一步；怎么读、怎么引用。

每条判据是此刻生效的规矩：新写的与改动的代码照它办，代码还没跟上的地方在各页「执行」一段标出来。编号就是网址（`/docs/criteria/k2`），说明书与别的仓引用时写「见关键判据 K2」，不复述正文。每页六段：规则、怎么判、标准例子、反例、为什么、执行。判据落到一个具体的件上长什么样，看[标准例子](/docs/criteria/examples)。

| 编号 | 规则 | 执行 |
| --- | --- | --- |
| [K1](/docs/criteria/k1) | 第一个件存在之前必须发生的事才进内核；真遇到需求才加 | 靠人 |
| [K2](/docs/criteria/k2) | peer 只写宿主提供、件按值 import 的 `cordis`；其余一律 dev；产物里只剩内置、`electron`、`cordis` 与 importmap 名 | 迁移中 |
| [K3](/docs/criteria/k3) | importmap 只放整页必须只有一份的运行时，提供方只能是件 | 部分守卫 |
| [K4](/docs/criteria/k4) | 件与件只经服务与命令交互，共享代码走无状态的契约包，盘上格式按区间比对契约版本 | 迁移中 |
| [K5](/docs/criteria/k5) | 扩展点用服务，数据与动作用命令，同一能力只开一个面 | 迁移中 |
| [K6](/docs/criteria/k6) | 谁提供谁定义契约；调用方不手写、不强转提供方的形状 | 迁移中 |
| [K7](/docs/criteria/k7) | 件自己起的一切在卸载时收走，并把 promise 交回去 | 迁移中 |
| [K8](/docs/criteria/k8) | 0.x 里只在破坏契约面时抬 x，其余抬 y | 部分守卫 |

读的顺序：写件先读 K2、K4、K5、K7，再对照[标准例子](/docs/criteria/examples)；改内核先读 K1。
