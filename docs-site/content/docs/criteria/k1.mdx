# K1 进内核还是做成件

## 规则

**凡是第一个件存在之前必须发生的事，才进内核；真遇到需求才加。** 其余一律皆件。

## 怎么判

先问这件事能不能由某个件提供、经服务送到用得着的地方——能，就做成件。再问现场：说不出「此刻干不成」的谁、在做什么、卡在哪，就不加。拿不准按「不进」，加回来永远比拿掉容易。件跑在主进程里、拿得到 `electron`，开窗、菜单、托盘、对话框、子进程都是件的事。

## 标准例子

内核此刻只做的那几件事，与刻意不做的那些，见[边界](/docs/boundary)。命令总线、外壳、数据、设置、装卸、给 agent 开的门全是件，例子见 [E1 commands](/docs/criteria/examples/e1-commands)、[E2 shell](/docs/criteria/examples/e2-shell)。

## 反例

「将来可能要」「顺手做了」「母仓有这个」；为了让某个件方便，往内核里塞它专用的逻辑。
