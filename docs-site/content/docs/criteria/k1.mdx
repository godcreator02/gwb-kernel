# K1 进内核还是做成插件

## 规则

**只有第一个插件运行之前必须完成的事，才进内核；而且确实遇到需求才加。** 其余一律做成插件。

## 怎么判

先问这件事能不能由某个插件提供、通过服务交给需要它的地方——能，就做成插件。再问具体场景：说不出此刻是谁、在做什么、因为缺了它卡在哪一步，就不加。判断不了就按「不进内核」处理：以后再加进来，永远比加进来之后再拿掉容易。插件运行在主进程里、能拿到 `electron`，开窗口、菜单、托盘、对话框、子进程都由插件来做。

## 标准例子

内核此刻只做的那几件事、以及刻意不做的事，见[边界](/docs/boundary)。命令总线、外壳、数据、设置、插件的安装与卸载、给 agent 用的 MCP 入口，全都是插件，例子见 [E1 commands](/docs/criteria/examples/e1-commands)、[E2 shell](/docs/criteria/examples/e2-shell)。

## 反例

「将来可能要」「顺手做了」「旧版工作台仓 god-workbench 里有这个」；为了方便某个插件，往内核里加只有它用的逻辑。

## 为什么

[这个内核的起点轨迹卡](/trajectory/2026-09-07-gwb-kernel)、[另起一个新仓，而不是在旧仓上删减](/trajectory/2026-09-07-fresh-line-over-subtraction)。

## 执行

靠人工把关；改内核要人来决定。
