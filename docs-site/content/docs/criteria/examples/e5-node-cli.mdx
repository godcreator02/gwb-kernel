# E5 node-cli（`@godcreator/gwb-node-cli`）

## 角色

让插件注册随包附带的 node 命令行工具；每个工具自动生成一条对应的命令，调用时启动子进程、收集输出，超过时限就结束它。

## 清单

```json
{
  "keywords": ["gwb", "gwb-plugin"],
  "gwb": { "provides": { "gwbNodeCli": { "summary": "…", "usage": "…" } } },
  "peerDependencies": { "cordis": "…" },
  "devDependencies": { "cordis": "…", "@godcreator/gwb-plugin-api": "…", "@godcreator/gwb-commands": "…" }
}
```

peer 只有 `cordis`（`extends Service`），commands 只取类型（[K2](/docs/criteria/k2)）。

## 构建产物里的包名 import

构建产物里剩下的包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）：`cordis` 与 node 内置模块（`node:child_process` 这类）。

## 对外接口

- **服务** `gwbNodeCli.register` 是扩展点：别的插件用它注册自己的工具（[K5](/docs/criteria/k5)）
- **命令**是「运行工具」的唯一方式：每个注册的工具自动生成一条对应的命令；服务上没有 `run`

## 契约

导出注册参数的类型与运行结果的类型（stdout、stderr、退出码、超时、溢出文件路径）（[K6](/docs/criteria/k6)）。

## 卸载清理

这是 [K7](/docs/criteria/k7) 的标准写法：
- 每个启动的子进程都记进一张「运行中的子进程」表，进程退出时从表里删掉
- 卸载时对表里的每一个子进程杀掉整棵进程树，从清理函数返回一个等它们全部真正退出才 resolve 的 promise
- 超时仍然按注册时给的时限杀掉
- 输出过长时写到自己数据目录下的文件里，文件路径放进运行结果

## 现状偏差

待改：卸载时不清理运行中的子进程，只靠超时；服务上的 `run` 与自动生成的命令重复；词汇表包写成了 peer。
