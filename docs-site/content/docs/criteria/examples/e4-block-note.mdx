# E4 块笔记（`block-note` + `bn-core` + `bn-comment`）

## 角色

三种角色各有一个：
- **`@godcreator/block-note`**：接口定义包（是库，不是插件）。包含命令的参数与返回值定义、类型化客户端、类型与纯函数、界面组件
- **`@godcreator/gwb-bn-core`**：提供方。持有笔记库，实现全部 `block-note.*` 命令
- **`@godcreator/gwb-bn-comment`**：使用方之一（props、query、members、journal 的写法相同）。给块添加评论，通过命令读写 bn-core 的数据

## 清单

```jsonc
// @godcreator/block-note —— 库
{
  "keywords": ["gwb"],
  "exports": { ".": "…", "./ui": "…", "./ui/style.css": "…", "./testing": "…" },
  "devDependencies": { "react": "…", "react-dom": "…", "mdast-util-from-markdown": "…" }
}
```

```jsonc
// @godcreator/gwb-bn-core —— 提供方
{
  "keywords": ["gwb", "gwb-plugin"],
  "gwb": { "provides": { "blockNote": { "…": "…" }, "blockNoteLibraries": { "…": "…" }, "blockNoteExtensions": { "…": "…" } } },
  "devDependencies": {
    "cordis": "…", "@godcreator/block-note": "…", "@godcreator/block-notebook-core": "…",
    "@godcreator/gwb-plugin-api": "…", "@godcreator/gwb-commands": "…",
    "@godcreator/gwb-data": "…", "@godcreator/gwb-shell": "…"
  }
}
```

```jsonc
// @godcreator/gwb-bn-comment —— 使用方
{
  "keywords": ["gwb", "gwb-plugin"],
  "devDependencies": {
    "cordis": "…", "@godcreator/block-note": "…", "@godcreator/gwb-bn-core": "…",
    "@godcreator/gwb-plugin-api": "…", "@godcreator/gwb-commands": "…"
  }
}
```

三个包都**没有 peer**：bn-core 与 bn-comment 用 `ctx.provide` 和函数式写法，不按值 import cordis；block-note 与 block-notebook-core 是自己用的库，打包进各自的构建产物；bn-comment 对 bn-core 只取类型（[K2](/docs/criteria/k2)）。bn-comment 需要 bn-core 已经安装，这一点不写进清单——没装时它停在「等待 blockNote 服务」的状态。

## 构建产物里的包名 import

构建产物里剩下的包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）：node 端代码里只有 node 内置模块；浏览器端代码里只有 react 的四个包名。block-note 用的解析库（mdast 这一系列包）体积大，但不需要整个页面只有一份，所以不进 importmap，各插件自带；block-note 不声明 `gwb.shared`（[K3](/docs/criteria/k3)）。插件之间共享 React context 不通过 block-note 的 `./ui`，通过 props。

## 对外接口

- **以命令为主**（[K5](/docs/criteria/k5)）：`block-note.*` 是读写笔记的唯一方式，页面、agent、各插件共用；bn-comment 注册自己的 `bn-comment.*` 命令
- **存在标记服务**：bn-core 提供服务 `blockNote`，只带 `{ contract, minCompatible }`；bn-comment 写 `inject: ['gwbCommands', 'blockNote', 'blockNoteExtensions']`，bn-core 重新加载时，它会跟着被卸载、再重新加载
- **扩展点**：`blockNoteLibraries`（注册笔记库）、`blockNoteExtensions`（注册属性提供者之类）做成服务，因为要传回调、注册要随提供方卸载一起撤销
- **契约版本区间**（[K4](/docs/criteria/k4)）：bn-comment 把自己期望的版本写死在代码里，加载时和 `blockNote` 的 `[minCompatible, contract]` 比对，落在区间外就拒绝加载

## 契约

命令的参数、返回值与类型化客户端放在 block-note 接口定义包里，由 bn-core 这一方维护并发版；使用方通过客户端调命令，拿到的是有类型的结果（[K6](/docs/criteria/k6)）。改命令的参数或返回值结构要改 `contract`，破坏了旧结构还要升 `minCompatible`；接口定义包的导出也算契约（[K8](/docs/criteria/k8)）。

## 卸载清理

bn-core 卸载时关闭笔记库，把待写数据写入磁盘的 promise 从清理函数里返回；bn-comment 的注册在卸载时自动注销；各插件只读写自己的数据目录，bn-core 的笔记库数据，别的插件通过命令拿，不自己拼路径（[K7](/docs/criteria/k7)、[K4](/docs/criteria/k4)）。

## 现状偏差

待改：block-note 库声明了 `gwb.shared`；这组插件把 block-note、bn-core、commands 等写成了 peer；契约版本比对要求完全相等而且只警告，bn-papers 期望的版本已经落后；bn-core 关闭笔记库时写盘的 promise 没有返回；bn-single 自己拼路径读 bn-core 的数据目录；bn-papers 在运行时 import 论文插件的子路径。
