# E1 commands（`@godcreator/gwb-commands`）

## 角色

命令总线：别的插件往这里注册命令，页面、agent、别的插件通过它按名字调用。它只提供扩展点，别的不做。

## 清单

```json
{
  "keywords": ["gwb", "gwb-plugin"],
  "gwb": { "provides": { "gwbCommands": { "summary": "…", "usage": "…" } } },
  "peerDependencies": { "cordis": "…" },
  "devDependencies": { "cordis": "…", "@godcreator/gwb-plugin-api": "…" }
}
```

**为什么 peer 只有 cordis**——看代码。`register` 是扩展点，按 [K5](/docs/criteria/k5#提供服务用哪种写法) 继承 cordis 的 `Service` 类。命令表本身（`createRegistry`，一张按名字存命令的表）不碰 cordis，服务类只在它外面包一层：

```ts
import { Service } from 'cordis'
import type { GwbContext } from '@godcreator/gwb-plugin-api'
import { createRegistry, type GwbCommands, type GwbCommandDef } from './registry.js'

declare module 'cordis' {
  interface Context {
    gwbCommands?: GwbCommands
  }
}

export default class GwbCommandsService extends Service implements GwbCommands {
  private readonly table: GwbCommands

  constructor(ctx: GwbContext) {
    super(ctx, 'gwbCommands')
    this.table = createRegistry(ctx.logger(name))
  }

  register(def: GwbCommandDef, handler: (args?: unknown) => unknown): () => void {
    const unregister = this.table.register(def, handler)
    // this.ctx 是调用方插件的上下文：调用方卸载时，这条命令自动从命令表里删掉
    this.ctx.effect(() => unregister)
    return unregister
  }

  list() {
    return this.table.list()
  }

  run(name: string, args?: unknown) {
    return this.table.run(name, args)
  }
}
```

构建产物 `dist/index.js` 开头的 import：

```js
import { Service } from 'cordis';
import { createRegistry } from './registry.js';
```

`import type` 和 `declare module 'cordis'` 都只是类型，编译后不留下代码；留下来的是 `import { Service } from 'cordis'`——`Service` 是一个类，运行时要用到它，所以运行时要从 home 里找到 cordis，写 peer（[K2](/docs/criteria/k2)）。`cordis` 同时写在 dev 里，给本地构建和类型检查用。

调用方注册命令只写一句，不用自己包 `ctx.effect`（完整的调用方写法见 [E6 最小插件](/docs/criteria/examples/e6-minimal)）：

```ts
ctx.gwbCommands!.register(
  { name: 'demo.ping', description: '…', plugin: '@godcreator/gwb-demo' },
  async () => ({ ok: true }),
)
```

## 构建产物里的包名 import

包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）：`cordis` 与 node 内置模块。

## 对外接口

一个服务 `gwbCommands`：`register` 是扩展点（别的插件往里注册命令），`list` 列出已注册的命令，`run` 按名字转发调用。它自己不注册命令（[K5](/docs/criteria/k5)）。

## 契约

自己的包导出命令定义的类型、服务接口和命令返回值的外层结构 `{ ok, data, error }`，以及 `declare module 'cordis'` 的类型增强（[K6](/docs/criteria/k6)）。

## 卸载清理

`register` 把注销函数登记到调用方的上下文里，调用方卸载时自动注销；返回值是注销函数，调用方想提前注销时可以调它。commands 自己不启动进程、不开定时器（[K7](/docs/criteria/k7)）。

## 现状偏差

待改：
- 服务用 `ctx.provide` 提供一个普通对象，没有继承 `Service`，认不出调用方，只能要求调用方自己把注册包进 `ctx.effect`（忘了包，调用方卸载后命令名还留在命令表里）。现在的写法（`gwb-base-plugins/plugins/commands/src/index.ts`，节选）：

  ```ts
  export function apply(ctx: GwbContext): void {
    const api = createRegistry(ctx.logger(name))
    ctx.effect(() => {
      const unprovide = ctx.provide('gwbCommands', api)
      return unprovide
    })
  }
  ```

  改成继承 `Service` 后清单要加 peer `cordis`。已经自己包了 `ctx.effect` 的调用方不受影响：注销函数只删自己注册的那一条，执行两次，第二次什么也不做——可以逐个删掉那层包装
- 词汇表包写成了 peer；命令返回值的外层结构放在词汇表包里；说明书（skill）服务的类型是用 `as` 强制转换出来的
