# E1 commands（`@godcreator/gwb-commands`）

## 角色

命令总线：别的插件往这里注册命令，页面、agent、别的插件通过它按名字调用。它只提供扩展点，别的不做。

## 清单

```json
{
  "keywords": ["gwb", "gwb-plugin"],
  "gwb": { "provides": { "gwbCommands": { "summary": "…", "usage": "…" } } },
  "devDependencies": { "cordis": "…", "@godcreator/gwb-plugin-api": "…" }
}
```

**为什么没有 peer**——看代码。源码 `gwb-base-plugins/plugins/commands/src/index.ts`（节选）：

```ts
import type { GwbContext } from '@godcreator/gwb-plugin-api'
import { createRegistry, type GwbCommands } from './registry.js'

declare module 'cordis' {
  interface Context {
    gwbCommands?: GwbCommands
  }
}

export function apply(ctx: GwbContext): void {
  const api = createRegistry(ctx.logger(name))
  ctx.effect(() => {
    const unprovide = ctx.provide('gwbCommands', api)
    return unprovide
  })
}
```

构建产物 `dist/index.js` 开头的 import 只剩这一句：

```js
import { createRegistry } from './registry.js';
```

`import type` 和 `declare module 'cordis'` 都只是类型，编译后不留下任何代码；`ctx.provide`、`ctx.effect`、`ctx.logger` 都是 cordis 通过 `apply(ctx)` 的参数交给插件的，插件不用自己去 import cordis。所以构建产物里没有 `from 'cordis'`，运行时不需要在 home 里找到 cordis 这个包——不写 peer（[K2](/docs/criteria/k2)）。`cordis` 留在 dev 里，只给 `declare module 'cordis'` 这段做类型检查。

它照样依赖 cordis 的行为（`ctx.provide` 怎么工作），这份兼容性由「宿主（内核）换 cordis 大版本就是内核的破坏性版本、所有插件同一次全部重新验证」来保证（[K8](/docs/criteria/k8)）。

## 构建产物里的包名 import

包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）只有 node 内置模块。

## 对外接口

一个服务 `gwbCommands`：`register` 是扩展点（别的插件往里注册命令），`run` 按名字转发调用。它自己不注册命令（[K5](/docs/criteria/k5)）。

## 契约

自己的包导出命令定义的类型、服务接口和命令返回值的外层结构 `{ ok, data, error }`，以及 `declare module 'cordis'` 的类型增强（[K6](/docs/criteria/k6)）。

## 卸载清理

`register` 返回注销函数，调用方把它包进 `ctx.effect`，卸载时自动注销；自己不启动进程、不开定时器（[K7](/docs/criteria/k7)）。
