# 标准例子

**本页回答**：关键判据落到具体的插件上是什么样子；看哪个例子学哪几条判据。

每个例子是这个插件**按判据应该写成的样子**，不是它今天的样子；今天对不上的地方，在各页末尾「现状偏差」里留一行，迁移清单在[全生态机制定案](/spec/ecosystem-simplify)。每页七段：角色、清单、构建产物里的包名 import、对外接口、契约、卸载清理、现状偏差。其中「包名 import」指 bare specifier：直接写包名、不带相对路径的 import，比如 `from 'cordis'`。

| 例子 | 为什么挑它 | 主要示范 |
| --- | --- | --- |
| [E1 commands](/docs/criteria/examples/e1-commands) | 最底层的服务提供方 | 扩展点用服务；不按值 import cordis 就不写 peer；契约放在自己的包里（K2、K5、K6） |
| [E2 shell](/docs/criteria/examples/e2-shell) | importmap 的唯一提供方 | K3 对提供方的全部规矩；服务只留扩展点（K2、K3、K5） |
| [E3 unit-folder](/docs/criteria/examples/e3-unit-folder) | 普通的带窗格插件 | 数据读写和动作通过命令；浏览器端代码怎么外置；导出返回值类型（K2、K3、K5、K6） |
| [E4 块笔记](/docs/criteria/examples/e4-block-note) | 插件之间的关系最复杂 | 接口定义包、以命令为主、存在标记服务、契约版本区间（K3、K4、K5、K6、K7） |
| [E5 node-cli](/docs/criteria/examples/e5-node-cli) | 会启动子进程 | 卸载清理的完整做法（K5、K7） |
