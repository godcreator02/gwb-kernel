# E3 unit-folder（`@godcreator/gwb-unit-folder`）

## 角色

单元文件夹：扫描单元容器根目录（存放各个单元目录的那个目录）、读取每个单元的 `unit.json`，给用户一个单元树窗格，给 agent 和别的插件一组读写单元的命令。

## 清单

```json
{
  "keywords": ["gwb", "gwb-plugin"],
  "gwb": { "provides": { "gwbUnitFolder": { "summary": "…", "usage": "…" } } },
  "exports": { ".": "…", "./client": "…", "./style.css": "…" },
  "peerDependencies": { "cordis": "…" },
  "devDependencies": {
    "cordis": "…", "react": "…", "react-dom": "…",
    "@godcreator/gwb-plugin-api": "…", "@godcreator/gwb-shell": "…",
    "@godcreator/gwb-commands": "…", "@godcreator/gwb-data": "…", "@godcreator/gwb-settings": "…"
  }
}
```

**为什么 peer 只有 cordis**——和 [E2 shell](/docs/criteria/examples/e2-shell#清单) 同一个道理。源码 `gwb-unit-folder/src/index.ts`（节选）：

```ts
import { Service } from 'cordis'

export default class GwbUnitFolder extends Service implements GwbUnitFolderApi {
  constructor(ctx: GwbContext) {
    super(ctx, 'gwbUnitFolder')
    // …
  }
}
```

构建产物 `dist/index.js` 里留着 `import { Service } from 'cordis';`，运行时要从 home 里找到 cordis，所以写 peer。

shell 写 dev：三个用途都只发生在构建时或类型检查时——取类型、构建脚本调用 `@godcreator/gwb-shell/externals` 拿外置名单、样式文件引用 `theme.reference.css`。构建产物里不会出现 `from '@godcreator/gwb-shell'`（[K2](/docs/criteria/k2)）。

## 构建产物里的包名 import

构建产物里剩下的包名 import（bare specifier，直接写包名、不带相对路径的 import，比如 `from 'cordis'`）：node 端代码里是 `cordis` 与 node 内置模块；浏览器端代码里只有 react 的四个包名，这份外置名单（构建时不打包、留给 importmap 提供的包名清单）从 shell 的 `./externals` 取，不手抄（[K3](/docs/criteria/k3)）。

## 对外接口

- **命令**提供全部的数据读写和动作：`unit-folder.list`、`create`、`listDir`、`readFile`、`open`、`code`、`select`、`current`、`pin`、`unpin`、`toolbarButtons`——页面、agent、别的插件都用这一套
- **服务** `gwbUnitFolder` 只留扩展点：`registerToolbarButton`（往单元树的工具条上加按钮），外加选中项变化的事件 `unit-folder/selection`
- 读当前选中项、读置顶列表，只通过 `unit-folder.current` 与 `unit-folder.list` 两条命令，服务上没有作用相同的方法（[K5](/docs/criteria/k5)）

## 契约

导出每条命令的参数与返回值类型（比如单元清单的结构）、工具条按钮的类型；调用方用 `import type` 取（[K6](/docs/criteria/k6)）。

## 卸载清理

置顶清单存在数据插件里，容器根目录的配置存在设置插件里；工具条按钮的注册在调用方卸载时自动注销；启动外部编辑器的进程是有意比宿主（内核）活得久的，要 detached，并在代码里写明（[K7](/docs/criteria/k7)）。

## 现状偏差

待改：构建脚本手抄外置名单；命令的返回值类型没有导出；commands、shell、skills、词汇表包写成了 peer；服务上的 `current()` / `pinned()` 与命令重复。
