# K4 插件之间怎么交互

## 规则

**插件之间只通过 cordis 服务和命令交互，不 import 别的插件。** 要共享代码，提供方另外发布一个无状态的接口定义包；要共享磁盘上的数据格式，按区间比对契约版本。

## 怎么判

- **「import 别的插件」**指 import 带 `apply` 或有模块状态的插件包入口和子路径。import 一个库或接口定义包不算——接口定义包只有类型、常量和纯函数，没有模块状态，使用方写 dev、打包进自己的构建产物
- **跨插件边界只传**纯数据、函数和 `{ ok, data, error }` 格式的命令返回值；不对别的插件所带库里的类做 `instanceof`（各插件带的是不同的拷贝）。`Error`、`URL` 这类平台全局对象不受限
- **依赖是否存在、要不要跟着提供方重新加载**，交给 cordis 的 inject：提供方重新加载时，依赖它的插件会被自动卸载、再重新加载
- **契约版本**：几个插件读写同一份磁盘上的数据格式、或者依赖同一组命令的参数与返回值结构时，提供方给出 `contract` 与 `minCompatible` 两个数，使用方把自己期望的版本**写死在自己代码里**，落在区间外就拒绝加载，不只是警告
- **数据目录归主人**：插件的数据目录只由它自己读写；别的插件要那份数据，通过它的命令拿。各插件共同约定的文件（比如单元的 `unit.json`）归定义它的那个插件，读的一方按它发布的契约来读

## 反例

`import` 别的插件的包或子路径来拿运行时函数；靠模块单例在插件之间共享状态；契约版本要求完全相等（加一个可选字段就判为不兼容）、或者只警告；使用方从共享库里取期望版本（比对的两边永远相等，等于没比）；自己拼路径去读别的插件的数据目录。

## 为什么

各插件带的库是各自的一份拷贝，模块单例和 `instanceof` 在插件之间不成立；块笔记两个仓里所有 `instanceof CommandError` 接住的都是本插件自己创建的对象，命令总线只传 `{ ok, data, error }` 格式的返回值，所以各插件各自带一份不会出错；真正的风险是各方版本不一致，导致磁盘上的数据格式对不上。
