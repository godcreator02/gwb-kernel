# K8 版本抬哪一位

## 规则

**0.x 里只在破坏契约面时抬 x，其余一律抬 y。**

## 怎么判

契约面清单、依赖范围怎么写、发破坏版多做的两步，正本在 devkit 的说明书 `gwb-release`，这里不复述。本页只补两条：
- 共享库的导出子路径、契约包的导出，也在契约面里
- **宿主换 cordis 大版本是内核的破坏版**：cordis 的协议是每个件都依赖的，不管它产物里 import 没 import cordis。先装新内核，所有件在隔离 home 里同一趟重验，不靠 peer 报信（[K2](/docs/criteria/k2) 只让按值 import 的件写 peer）

## 标准例子

- react 升大版本是 shell 的破坏版：[E2 shell](/docs/criteria/examples/e2-shell#面)
- 契约包改命令形状要动 `contract` 与 `minCompatible`：[E4 块笔记](/docs/criteria/examples/e4-block-note)

## 反例

删了运行时导出只抬 y；加功能、加可选参数顺手抬 x。

## 为什么

依赖范围管不到运行时实际解析到哪一版：词汇表包从 0.1 到 0.2 撤掉了运行时导出，下游的范围还写着 `^0.1.2`，home 里照样解析到 0.2.7，三个件挂不上。真正的保证是发版检票加 [K4](/docs/criteria/k4) 的契约版本比对。

## 执行

`devkit.release` 的发版检票机械执行其中一部分。
