# 写第一个件

读完这页你能回答：一个件最少要哪几个文件；怎么让它挂上；怎么在窗口里占一格。

每步做完就重启验一次——**实机是这仓的验收方式**，宿主日志会把条目逐条报出来。

## 1. 建包

一个件就是一个普通的 npm 包：

```json
{
  "name": "@you/thing",
  "version": "0.0.1",
  "type": "module",
  "exports": { ".": "./index.js" }
}
```

`exports` 是内核唯一的取址依据，写什么才能取到什么。

## 2. 写 apply

```js
export const name = 'thing'

export function apply(ctx, config) {
  ctx.logger.info('thing 起来了')
}
```

`apply` 的签名与语义全归 cordis，不归内核——内核只负责把模块 import 进来交给 cordis。`config` 就是条目里写的那份。

## 3. 挂上它

装进 home（`pnpm add`，本地包用 `file:` 协议或发到 Verdaccio），然后在 `cordis.yml` 里写条目：

```yaml
- id: thing
  name: '@you/thing'
```

`id` **必须手写**：不写的话 loader 当场发一个 8 位随机十六进制，而且首次加载不写回 yml——它会一直漂，按条目身份存的东西每次都对不上。重启，宿主日志里这条条目报「挂上」。

## 4. 验收：条目表说 ok

页面 console 或终端调 `kernel.info`，看 `entries` 里那条的 `ok`。**`ok` 判的是 fiber 真的 ACTIVE 了**，不是「fiber 建出来了」——`inject` 永远等不到的件也有 fiber，但 `ok: false`。

## 5. 提供一个服务

```js
export function apply(ctx) {
  const api = { hello: () => 'world' }
  ctx.effect(() => ctx.provide('gwbThing', api))
}
```

服务名一律 `gwb` 开头；`ctx.effect` 包一层，件卸载时自动撤销。消费方写 `inject: ['gwbThing']`——那是硬等待：服务不在，件不挂。

**想被页面调到**：注册进命令总线（`ctx.gwbCommands.register(...)`，如果装了 `gwb-commands`）。总线的收据形状是 `GwbResult`，未知命令不 throw——契约见[服务与命令](/docs/plugins/services)。

## 6. 用内核的服务

```js
import { requireKernel } from '@godcreator02/gwb-plugin-api'

export function apply(ctx) {
  const kernel = requireKernel(ctx)
  kernel.emit({ type: 'thing.ready' })   // 页面 window.gwb.onEvent 收到
}
```

`dataDir`、`appVersion` 这些运行时值只走 cordis 服务；类型才走词汇表包。`requireKernel` **别写进 `inject`**——那个服务永不撤销，写进去只多一处挂不上的可能。

## 7. （选）浏览器那半

多导出一个 `./client`，页面就能经 `gwb://` 取到它：

```json
{ "exports": { ".": "./index.js", "./client": "./client.js" } }
```

打包时**只把 importmap 里有的裸名外置**（要用 `react`，得先有个共享包声明 `gwb.shared`），其余打进自己这份束。窗格件导出 `mountPane`，由外壳调：

```js
export function mountPane({ host, shell, pane }, container) {
  container.textContent = 'thing 的第一格'
  return { dispose() {} }
}
```

`mountPane` 的完整契约正本住件仓的 `gwb-shell` 那页；`window.gwb` 的面、样式与组件的规矩见[浏览器那半](/docs/plugins/client)。
